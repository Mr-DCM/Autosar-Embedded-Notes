# 02-失效响应

> 一句话定位：监督违规不是"直接复位"一步走——WdgM 用本地/全局两级状态机收口失效（OK→FAILED→EXPIRED），失效反应按配置分级（本地恢复回调/全局上报/复位），参数算错和 checkpoint 漏埋是两类最高发的坑。
> 等级：L2 ｜ 前置：[01-监督实体与checkpoint](01-监督实体与checkpoint.md)

## 原理

### 本地状态机：单个 SE 的病程发展

```plantuml
@startuml
title SE 本地状态机：OK → FAILED → EXPIRED
skinparam defaultFontName "Microsoft YaHei"
[*] --> DEACTIVATED : 初始化\n（当前模式未启用该 SE）
DEACTIVATED --> OK : 模式启用该 SE
OK --> FAILED : 单次违规\n（本轮 Alive/Deadline/Logical 不过）
FAILED --> OK : 下轮恢复\n（继续按时打卡）
FAILED --> EXPIRED : 连续违规\n（过期监督被判"没救了"）
OK --> EXPIATED [hidden]
OK --> DEACTIVATED : 模式切换停用
EXPIRED --> DEACTIVATED : 模式切换重置
note right of FAILED
  FAILED 是"黄牌"：
  单次抖动也能触发，
  恢复即回 OK——别拿它直接当复位依据
end note
note right of EXPIRED
  EXPIRED 是"红牌"：
  持续失效才进入，
  是触发全局反应的正式信号
end note
@enduml
```

**两级收口**：每个 SE 有 Local Status（OK/FAILED/EXPIRED/DEACTIVATED）；WdgM 汇总出 Global Status——任一 SE EXPIRED → 全局 EXPIRED，才是"动真格"的时刻。设计意图：**黄牌容忍抖动、红牌确认失效**，避免一次调度毛刺就让 ECU 复位。

### 失效反应的三个层级

| 层级 | 机制 | 配置形态 | 适用 |
|---|---|---|---|
| 本地恢复 | FAILED/EXPIRED 回调通知应用（`WdgM_Trigger`/通知接口），应用自救 | E_ExpiredSupervisionNotification 等回调 | 可自愈故障：数据重同步、降级重试 |
| 全局上报 | 全局 EXPIRED 通知 EcuM（进入失效处理状态），由 BswM/EcuM 决策 | WdgM→EcuM 失效接口联动 | 需要系统级协调：进安全态、记录故障 |
| 复位兜底 | 停止喂狗 → 硬件 WDT 到期复位 | 喂狗策略随全局状态自动停 | 安全完整性要求：直接复位重启 |

典型组合：通知回调记日志+置 Dem 事件 → 上报 EcuM 走安全停机 → 最终停喂让硬件狗复位兜底（三层全上）。

## 详解

### Alive 监督参数计算实例

设：任务周期 10ms，WdgM 监督周期（MainFunction 周期×监督窗口）= 1s，打卡点在循环末。

1. **期望到达次数（expected alive）**：1s / 10ms = **100 次**；
2. **容差（margin）**：考虑调度抖动与高优抢占，取 ±20%；
3. **min = 100×(1−20%) = 80**，**max = 100×(1+20%) = 120**；
4. 收紧策略：量产数据回灌后先收 margin（±20%→±10%），**不要一上来就紧**；
5. 反向校验：任务若被错误地双倍激活（配置错成 5ms），max=120 会命中"狂转"违规——max 同时是"过速探测器"。

**边界容差的坑**：监督周期与任务周期不整除（如 1s 监督窗 vs 13ms 任务）时期望值非整数，取整方向要保守（min 向下取整、max 向上取整），并用实测分布复核。

### 监督失败的排障路径

按"从打卡到判定"链路逆推：

1. **checkpoint 漏埋**：违规 SE 的打卡计数一直为 0 → 查代码里 WdgM_CheckpointReached 调用与配置 CP ID 是否对得上（最高发）；
2. **周期漂移**：计数在期望值附近但偶发越界 → 用 OS trace/GPIO 打点量任务实际周期，常见根因：调度表改了没同步 WdgM 参数、高优任务新增抢走 CPU；
3. **引擎心跳错**：WdgM_MainFunction 任务没起/周期不符 → 全部 SE 集体违规，看引擎任务是否被激活；
4. **模式切换不同步**：只在特定阶段（下电/诊断会话）违规 → WdgM_SetMode 与 EcuM/BswM 的切换点没对齐，慢阶段仍在用 NORMAL 参数；
5. **回调自检**：在失效回调里只置标志+轻量记录，用调试器/DLT 拉出违规 SE 与计数，再定位上述 1~4。

## 配置层

| 配置项 | 含义 | 典型值 | 易错点 |
|---|---|---|---|
| WdgMExpiredSupervisionToLocalState | SE 从 FAILED 转 EXPIRED 的连续违规门槛 | 2~3 轮 | 门槛=1：黄牌机制失效，抖动即红牌 |
| WdgMEcuM 通知联动 | 全局 EXPIRED 报 EcuM | 启用 | 只复位不通知：失效原因无从追溯 |
| WdgMFailedAliveSupervisionRef / 参数 | [min,max] 与监督周期绑定 | 按实例计算 ±20% | 监督周期改了参数没跟 |
| WdgMExpiredNotification | EXPIRED 用户回调 | 记 Dem/DLT+置标志 | 回调里做重活：在判定上下文里拖时 |
| WdgMMode（含喂狗策略） | 各模式喂狗开/停 | NORMAL 喂 / OFF 停 | 停喂模式配置后无人负责最终复位 |
| WdgM_SetMode 调用点 | EcuM 生命周期切换 | 启动 SLOW→RUN NORMAL→下电 SLOW | 下电忘切：NvM 慢流程被误咬（见 [EcuM/02](../EcuM/02-上下电时序.md)） |
| WdgMMainFunction 周期 | 引擎心跳 | 10~20ms | 与监督参数假定的周期不一致 |

## 易错点与陷阱

1. **拿 FAILED 当复位依据**：单次违规即复位/下电，正常抖动被放大成系统故障；复位动作只应挂在全局 EXPIRED（经连续违规门槛确认）。
2. **EXPIRED 门槛配 1**：黄牌红牌机制作废，调度毛刺直接进全局失效；默认 2~3 轮起步。
3. **失效回调里做重活**：在 WdgM 判定上下文里刷 NvM/长循环，拖垮引擎心跳；回调只置标志，善后交给任务。
4. **全局 EXPIRED 后忘了"现在谁负责复位"**：停喂配置下硬件狗会复位，但若该模式喂狗仍开——失效了还继续喂，监督形同虚设；失效路径要和喂狗策略一起评审。
5. **参数与实际周期脱钩**：调度表/任务周期调整后 Alive 参数没重算，投产后集中爆"越界"；把"改周期必查 WdgM 参数"写进变更检查单。
6. **复位风暴当崩溃查**：EXPIRED→复位→启动期又违规（初始化时序型故障）→再复位，现象是周期性重启；先在回调里留证据（复位原因寄存器+DLT）再谈修复。

## 面试高频题

- **Q：WdgM 本地状态机有哪几个状态？FAILED 和 EXPIRED 的区别？**
  A：OK/FAILED/EXPIRED/DEACTIVATED；FAILED=单次违规的黄牌（下轮恢复可回 OK），EXPIRED=连续违规的红牌（正式失效信号，推动全局反应）；两级设计用来容忍抖动、确认真失效。
- **Q：监督失效后系统可以怎么响应？**
  A：三级——本地恢复回调（应用自救/降级）、全局上报 EcuM（系统级安全停机协调）、复位兜底（停止喂狗由硬件 WDT 复位）；典型全上，形成"可追溯→可协调→可复位"。
- **Q：10ms 任务、1s 监督周期，Alive 参数怎么算？**
  A：期望次数=100；按抖动裕量取 margin（如 ±20%）得 min=80/max=120；监督窗与任务周期不整除时取整要保守；量产前用实测分布收紧。
- **Q：上线后偶发 WdgM 复位，怎么定位？**
  A：先取失效证据（回调记录的违规 SE+计数/复位原因寄存器）；按链路逆推：checkpoint 漏埋（计数为 0）→周期漂移（trace 实测）→引擎心跳（集体违规）→模式切换不同步（只在特定阶段）。
