# 01-ASIL与安全机制

> 一句话定位：ISO 26262 的"打分表"与"流水线"——ASIL 如何由严重度 S × 暴露率 E × 可控性 C 查表得出，安全目标如何沿 V 模型一路拆到软硬件安全要求，WdgM/E2E/Lockstep/MPU 这些机制名各在哪一层接活。

## 核心概念

### 标准全景：12 个 Part + 一个 V 模型

ISO 26262 是 IEC 61508 在汽车领域的改编，现行 2018 版共 12 个 Part。不用背，记住每个 Part 回答哪一类问题即可：

| Part | 主题 | 与软件工程师的关系 |
|---|---|---|
| 1 | 词汇 | 查术语：安全状态、安全目标、失效等的规范定义都在这 |
| 2 | 功能安全管理 | 开发接口协议 DIA、确认措施的独立性要求 |
| 3 | 概念阶段 | **HARA、ASIL 定级、安全目标、功能安全概念**——概念链的起点 |
| 4 | 系统层 | 技术安全概念、系统架构、失效分配 |
| 5 | 硬件层 | FIT 失效率、诊断覆盖率、SPFM/LFM/PMHF 度量 |
| 6 | 软件层 | 软件安全需求、软件架构与单元设计、测试覆盖率要求 |
| 7 | 生产/运行/服务 | 量产交付后的安全维护 |
| 8 | 支持过程 | 需求/配置/变更管理、工具置信度（TCL） |
| 9 | ASIL 导向分析 | FMEA/FTA/DFA 等分析方法 |
| 10 | 指南 | 各 Part 的解释性示例（入门读这个最友好） |
| 11 | 半导体应用指南 | MCU 供应商"考纲"——TC377/S32K 安全手册的源头 |
| 12 | 摩托车改编 | 两轮车场景（点到即止） |

### ASIL 定级：S×E×C 直觉表

三个维度各回答一个问题：

| 维度 | 问什么 | 取值直觉（从轻到重） |
|---|---|---|
| **S** 严重度 | 失效演变成伤害时有多重 | S0 不伤 / S1 轻中度伤 / S2 重伤可能致命 / S3 致命（危及生存） |
| **E** 暴露率 | 该运行场景多久遇到一次 | E0 极罕见 / E1 每年少于一次 … E4 每次驾驶都可能（行驶本身、加速） |
| **C** 可控性 | 司机或旁人救得回来吗 | C0 完全能控 / C1 ≥99% 能控 / C2 通常能控 / C3 来不及或根本无法控 |

S3 行完整查表（刹车/转向类安全机制最常落在这行）：

| S3 | C1 简单可控 | C2 一般可控 | C3 难控/不可控 |
|---|---|---|---|
| **E1** 很少发生 | QM | QM | ASIL A |
| **E2** 偶尔发生 | QM | ASIL B | ASIL C |
| **E3** 经常发生 | ASIL A | ASIL C | ASIL D |
| **E4** 每次驾驶 | ASIL B | ASIL D | ASIL D |

S1/S2 行整体"下移一档"。方向记忆法：**伤得越重、遇得越频、越救不回来，等级越向 D 逼近；三者只要有一头拉不狠，等级立刻掉**。导读里的刹车助力：行驶中（E4）+ 司机来不及用力（C3）+ 可能致命（S3）→ ASIL D，就是这么查出来的。

### 概念链走通示例（接着导读的刹车助力讲）

| 链条环节 | 刹车助力例子 | 产物落点 |
|---|---|---|
| 危害事件 | "高速中助力突然消失，踏板死硬" | HARA 分析对象 |
| 安全目标 SG | "助力失效时，X ms 内司机以 ≤Y N 踏板力获得 ≥Z% 减速度" | 带 ASIL D 的顶层安全需求 |
| 功能安全要求 FSR | "助力失效须被检测并在 FTTI 内切换到冗余助力路径" | 系统功能安全概念 |
| 技术安全要求 TSR | "电机堵转检测 ≤10ms；控制报文 E2E 保护；程序流监控；失效→安全状态" | **安全机制在这里成形** |
| 软/硬件安全要求 | 软件：WdgM 监督电机控制任务、E2E Profile 保护报文；硬件：双通道驱动、欠压监控 | 分别流进 Part 6 / Part 5 |

一句话：**SG 说"要什么"，FSR 说"靠什么功能兜底"，TSR 说"用什么机制实现兜底"，SSR/HSR 说"机制在软硬件上的具体要求"**。每往下一层，ASIL 继承（或经论证分解），验证要求随之加深。

## 详解

### ASIL 等级决定的是"开发纪律"，不是"产品好坏"

QM 到 ASIL D 的差别不是"质量高低"，而是**多大程度不信任单一手段**。落到软件侧的典型纪律差：

| 纪律项 | QM | ASIL B | ASIL D |
|---|---|---|---|
| 结构覆盖率 | 按项目惯例 | 语句+分支覆盖 | 分支+**MC/DC** |
| 评审独立性 | 同行评审 | 增加独立评审 | 高度独立的确认评审（I3 级别） |
| 安全分析 | 可选 | FMEA 常规做 | FMEA+FTA+DFA，含相关性分析 |
| 工具置信度 | 一般不评估 | 按 TCL 评估 | 按 TCL 评估+可能要求鉴定 |
| 架构约束 | 无 | 惯例 | 分区/免于干涉论证 |

### ASIL 分解：冗余的"官方姿势"

ASIL D 的需求太重时，可分解到冗余通道：**ASIL D → ASIL B(D) + ASIL B(D)**（或 C(D)+A(D)）。两个充分独立的通道各按较低等级开发，组合达成 D。关键约束：**分解必须伴随独立性论证（免于干涉 FFI）**——两条通道若共享同一个任务、同一段 RAM、同一个时钟，共因失效会击穿分解。MPU 分区、独立供电/时钟、多样性设计就是干这个的。分解是"把 D 的负担摊到两条 B 上"，不是"降级成 B 就完事"。

### 双平台硬件根：Part 11 的落地长相

- **TC377（AURIX）**：Lockstep 锁步核、开机 LBIST 自检、时钟/电压监控（EMA/SMU 集中响应）——这些就是芯片厂按 Part 11 交付的"安全手册"内容，软件要按手册配 SMU 响应与自检节奏；
- **S32K（S32K3 侧）**：FCCU 集中收集故障并按配置响应、CMU 时钟监控、SWT 窗口看门狗、MPU 分区——同样是一套"硬件已做的检测 + 软件要做的响应"分工。

读芯片安全手册时的正确姿势：**先找"已实现的安全机制清单+诊断覆盖率数字"，它们直接支撑你 ECU 级的 PMHF/SPFM 计算**（Part 5 的账）。

## 易错点与陷阱

1. **把 ASIL 当可靠性等级**：现象——"ASIL D 的芯片不容易坏"；原因——ASIL 定的是失效后的容忍度与开发纪律，与失效率（FIT）是两个轴；对策——记住"等级高 = 坏了必须能发现+兜底，且过程更严"，选型时同时看 FIT 与安全手册。
2. **S/E/C 各评各的，场景没对齐**：现象——同一功能，A 团队评出 ASIL B、B 团队评出 D；原因——运行场景清单（高速/泊车/洗车）不统一，E 和 C 就没有共同基准；对策——先冻结运行场景清单，逐场景打分，功能 ASIL 取各场景最高。
3. **概念链断链**：现象——TSR 里写了"WdgM 监督 XX 任务"，向上追溯不到任何 SG；原因——安全分析与需求管理脱节，机制是"拍脑袋加的"；对策——每条 TSR 维持到 FSR→SG 的追溯矩阵，评审时抽链检查。
4. **ASIL 分解忘了独立性**：现象——分解成 B(D)+B(D) 后两条通道跑在同一 OS 分区/共享 RAM；原因——只抄了分解公式没做 FFI 论证；对策——分解伴随独立性分析（MPU 分区、独立资源），并把共因失效写进 DFA。
5. **QM 误区**：现象——"QM 就是不用管"；原因——把"无 26262 附加要求"理解成"无要求"；对策——QM 仍按质量管理体系（如 ASPICE/IATF）正常开发，只是免除安全专用纪律。
6. **把复位当安全状态**：现象——失效反应一律"系统复位"；原因——没论证复位后的行为（行驶中转向助力 ECU 直接断电复位本身可能就是危害）；对策——安全状态要逐 SG 论证（降级模式、保持最后有效值等），复位只是选项之一。

## 面试高频题

**Q：ASIL 是怎么定出来的？**
答：对每个危害事件做 HARA，按严重度 S（伤多重）、暴露率 E（场景多久遇到一次）、可控性 C（司机能否救回）三个维度打分，查 ISO 26262-3 的定级表得出 QM 或 ASIL A~D；一个功能跨多个场景时取各场景最高等级，并作为安全目标与后续全部需求的继承等级。

**Q：ASIL D 比 QM 在软件开发上具体多做什么？**
答：纪律加深而非"写更好的代码"：结构覆盖率要到 MC/DC、评审与确认措施要求独立性（I3）、必须做 FMEA/FTA/DFA 安全分析、开发工具按置信度评估（TCL）、架构上要求分区与免于干涉论证——本质是降低"系统性失误漏网"的概率。

**Q：请从安全目标讲到软件安全要求，用刹车助力举例。**
答：HARA 得出"助力失效且司机无法及时补偿"为 ASIL D → 安全目标"失效时 X ms 内仍提供 Z% 减速度" → FSR"检测助力失效并在 FTTI 内切换冗余路径" → TSR 细化为安全机制（电机堵转检测、控制报文 E2E 保护、程序流监控） → SSR 落到软件（WdgM 监督实体配置、E2E Profile 选择、失效反应函数），每一层可追溯、等级继承。

**Q：ASIL 分解是什么？什么时候能用？**
答：把一个高等级需求分给足够独立的冗余元素，如 D → B(D)+B(D)，括号标注原始等级防丢失；前提是元素间证明免于干涉（独立供电/时钟/分区/多样性），否则共因失效使分解无效；常用于双通道传感器、监控+被监控的架构。
