# 概览

> 一句话定位：ISO 21434 是信息安全版的"驯化流水线"——把"有人要攻击这辆车"的担忧，变成 TARA、网络安全目标和一整套可落地的工程要求，本篇建立全景坐标。

## 核心概念

[区导读](../../00-入门导读/01-从一个刹车失灵的故事说起-功能安全全景.md)里说过：功能安全假设**系统自己会坏**，信息安全假设**有人要弄坏你**。ISO 21434（道路车辆网络安全工程）就是后者的方法论总纲。它与 ISO 26262 共用同一条"分析→定级→目标→机制→验证"的流水线，只是每一步换了问的问题：

```plantuml
@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontSize 13
rectangle "V 模型左翼：分析与定级" as V
package "ISO 26262（防失效）" {
  [HARA：危害分析与风险评估] as HARA
  [S×E×C → ASIL A~D] as ASIL
  [安全目标 → 安全机制] as FSM
}
package "ISO 21434（防攻击）" {
  [TARA：威胁分析与风险评估] as TARA
  [严重度×可能性 → CAL 1~4] as CAL
  [网络安全声明 → 安全机制] as CSM
}
V <-down- HARA
V <-down- TARA
HARA --> ASIL --> FSM
TARA --> CAL --> CSM
note bottom of V
  同构不同问：
  26262 问"坏了伤多重、多常见"
  21434 问"被攻破了伤多重、攻进来多容易"
end note
@enduml
```

一句话记住 ISO 21434 的结构：**概念阶段（TARA）→ 产品开发 → 验证 → 生产 → 运维（漏洞管理与监控）**，覆盖车辆全生命周期，不是一次性交付物。

## 详解

### 1. 为什么需要它：CAN 总线是"不设防的城市"

经典 CAN 是广播总线：任何节点发出的帧，所有节点都收，且帧里**没有任何发送者身份证明**。OBD 口就插在车里，几十块钱的开源工具（candump/cansend、SocketCAN）就能做到：监听全部报文→解析出"哪个 ID 控制转向/制动"→原样重发或伪造。2015 年 Jeep Cherokee 被远程攻破、召回 140 万辆，就是这条链路：蜂窝网入口→信息娱乐 ECU→CAN 网关→车控报文。功能安全的 HARA 完全管不了这种"有人故意发的假报文"——失效概率再低，攻击者可以百分百复现。信息安全由此成为独立支柱，而它落到车载通信上的第一件武器就是 [SecOC](../SecOC/01-CMAC与新鲜度.md)，密钥的保险箱就是 [HSM与SHE](../../3-L3高级/HSM与SHE/README.md)。

### 2. 与 ISO 26262 的关系与差异

| 维度 | ISO 26262（功能安全） | ISO 21434（网络安全） |
|---|---|---|
| 防什么 | 随机硬件失效、软件 bug（无意） | 恶意攻击（有意） |
| 分析方法 | HARA：S×E×C 查表 | TARA：威胁场景+攻击可行性打分 |
| 定级输出 | ASIL A/B/C/D + QM | CAL 1~4（ assurance 等级，方法学厂商自定） |
| 对手模型 | 物理规律（失效率可算） | 聪明的攻击者（持续演化，无法"算概率"） |
| 时间维度 | 发布时风险可接受即达成 | 全生命周期军备竞赛，需持续运维 |
| 法规地位 | 行业标准（非强制） | 配合 UNECE R155 成为准入法规 |

两条线不是平行铁轨而是麻绳：SecOC 防住"假报文让助力电机乱转"，本身就在保护刹车那条 ASIL D 安全目标；反过来加密引入的计算延迟若导致车控报文超时，Security 机制就反过来伤害了 Safety——需求矩阵里必须双维度对齐。

### 3. TARA 的工程直觉

TARA（Threat Analysis and Risk Assessment）四步，每步都有个"人话"版本：

1. **资产识别**：这台 ECU 上什么值钱？——密钥、标定数据、车控指令、诊断服务、固件本身。
2. **威胁场景**：对每个资产问"攻击者想对它干什么？"——伪造指令（刹车报文）、重放（旧的开锁命令）、窃取（导出密钥）、篡改（刷改固件）、拒绝服务（刷爆总线）。
3. **攻击路径分析**：从攻击面（OBD、无线入口、ECU 调试口、供应链）到威胁场景有没有走得通的路？对每条路按攻击可行性打分（耗费时间、专业度、目标知识、机会窗口、所需装备）。
4. **风险定级**：风险值 = 严重度 × 可能性 → 输出 CAL 等级 → 决定这个威胁"必须处理 / 处理到什么强度"（例如 CAL 4 的车控指令就要求 SecOC + HSM 硬件级密钥保护）。

与 HARA 最大的差别在第 4 步：HARA 查的是固定表（S/E/C 组合唯一确定 ASIL），TARA 的定级方法学标准不做规定，OEM 各家有各自的打分矩阵——所以看 TARA 报告先看它用的哪套方法。

### 4. 从概念到运维：生命周期全覆盖

- **概念阶段**：整车级 TARA → 网络安全目标（"车控指令不可被伪造"）→ 分解到 ECU 的网络安全需求。
- **产品开发**：需求下探到 BSW 配置——SecOC I-PDU 布局、Csm 密钥管理、HSM 固件（这些配置实操都在 [07 区加密栈](../../../07-AUTOSAR架构/3-L3高级/加密栈/README.md)，本区只管"为什么"）。
- **验证**：渗透测试、模糊测试（fuzzing 诊断服务）、漏洞扫描。
- **运维阶段**：PSIRT 漏洞响应流程、现场监控（异常报文率、认证失败计数）、R156 管的软件升级（OTA 本身也是攻击面，升级包必须签名验签）。

## 易错点与陷阱

1. **现象：网络安全需求被标上 ASIL 等级。** 原因：把两套定级混用，以为 Security 也是"失效概率×伤害"。对策：Security 用 CAL（或 OEM 自定等级）表达"要多强的保障强度"，ASIL 只属于功能安全侧；一条机制可以同时服务于两个目标，但属性各标各的。
2. **现象：TARA 在项目 kickoff 做完就归档，量产车漏洞无人管。** 原因：把 21434 当成一次性交付物。对策：TARA 是 living document，新攻击技术、新诊断后门、漏洞通告都要求回溯更新；运维监控（如 SecOC 认证失败计数上报）要写进量产需求。
3. **现象：渗透测试发现诊断会话绕过了安全访问。** 原因：开发期图方便开的 0x22/0x2E 免密服务、遗留调试 CAN 通道进了量产。对策：概念阶段就盘点攻击面清单，量产配置与开发配置用 CI 比对，安全访问（0x27/0x29）全覆盖写服务。
4. **现象：加了 SecOC 后刹车报文周期抖动超时，E2E 报 Counter 异常。** 原因：加密计算挤占发送任务时间片，Security 伤害了 Safety。对策：CMAC 计算走硬件（HSM/CSEc），链路时序预算里给认证开销留位，SecOC 与 E2E 的叠加时序要在集成测试验证。
5. **现象：CAL 定级两家供应商对不上，集成时吵架。** 原因：21434 不规定定级矩阵，各 OEM/供应商方法学不同。对策：项目启动时以 OEM 的网络安全接口协议（CSMS 接口）为准，供应商 TARA 复用 OEM 方法学。

## 面试高频题

**Q：ISO 21434 和 ISO 26262 是什么关系？**
答：两者都是覆盖全生命周期的工程标准，方法论同构（风险分析→定级→目标→机制→验证），ISO 21434 甚至大量复用了 26262 的流程框架。核心差异在防御对象：26262 防随机失效，输出 ASIL；21434 防恶意攻击，输出 CAL。两者交叉点很多——SecOC 报文认证保护的车控信号往往就是 ASIL D 信号，工程上需求要双维度对齐。

**Q：TARA 和 HARA 有什么异同？**
答：同：都是"找危害→评风险→定等级→导出需求"的分析流水线，都服务于概念阶段决策。异：HARA 针对无意的随机失效，S×E×C 查标准表得 ASIL；TARA 针对有意的攻击者，需要建对手模型、分析攻击路径和可行性，定级方法（CAL）标准不规定、由各厂商自定义。另外 TARA 结果随威胁演化持续更新，HARA 结论相对稳定。

**Q：R155 是什么？和 21434 什么关系？**
答：R155 是 UNECE 法规，强制要求车企建立网络安全管理体系（CSMS）并通过认证，新车型型式认证（欧洲、日本等市场准入）必须有 CSMS 证书——一句话：21434 是"怎么做"的方法学标准，R155 是"不做不行"的法规强检，21434 实质上是 R155 认证的落地路径。配套的 R156 管软件升级管理体系（OTA 升级必须受控）。

**Q：Security 和 Safety 需求冲突时怎么办？**
答：典型冲突是加密认证引入延迟导致安全报文超时。原则是"安全状态不可被安全机制本身破坏"：优先保证 Safety 的时间约束，Security 机制退而求其次（CMAC 走硬件加速、只认证不加密降开销、必要时对最关键报文做降级策略），并在集成层验证两种需求同时满足，而不是各自验收。
