# Lockstep 安全机制

> 一句话定位：把同一份程序在两个物理核上错拍运行、持续比对，让核内随机硬件故障在微秒级暴露——ASIL-D 等级下 CPU 自身诊断覆盖的核心硬件护栏。
> 等级：L3 ｜ 前置：[01-TC1.6P内核概览](01-TC1.6P内核概览.md)

## 太长不看

- **人话直觉**：锁步 = 同一份程序在两个核上错开一拍跑、持续比对——一个核算错立刻被另一个"揭发"，专补 ECC/看门狗/MPU 都看不见的"核自己算错"。
- **本篇解决**：为什么 ASIL-D 必须有锁步？延迟一拍和物理隔离各防什么？对写应用的你意味着什么？
- **赶时间记住 3 条**：
  1. ECC 查存储位翻转、锁步查核内计算逻辑，互补不替代；
  2. 软件视角锁步对就是"一个核"，不能往冗余核塞任务，性能负载去独立核（CPU2）；
  3. 失配走 SMU 报警处置——只复位不留故障记录，售后就是查不出的"无理由重启"。

## 原理

### 为什么需要 lockstep：功能安全的账

ISO 26262 对 ASIL-D 的随机硬件故障有量化要求（SPFM/LFM 与诊断覆盖率指标，概念见 [功能安全与信息安全](../../../11-功能安全与信息安全/README.md)）。逐项看常规手段的盲区：

| 故障位置 | 常规手段 | 盲区 |
|---|---|---|
| 存储器位翻转 | ECC（Error Correction Code，错误校验纠正） | 覆盖好 |
| 程序跑飞 | 看门狗/窗口看门狗、MPU | 覆盖尚可 |
| **核内逻辑**（ALU 算错、控制逻辑失效、寄存器堆位坏） | 上面这些**全都看不见** | 诊断覆盖率的最大缺口 |

核内逻辑故障的出路只有**计算冗余**：同一输入、同一程序、两份独立硬件各算一遍、比对结果——lockstep（锁步）就是这个思路的硬件化。代价是一倍的核资源，换来的是"算错必被抓"的高诊断覆盖，这正是动力/底盘等 ASIL-D 域愿意付的账。

### 延迟锁步原理：错开一拍再比对

TC3xx 采用**延迟锁步（delayed lockstep）**：锁步对里两个核执行同一指令流，其中一个核的输入/状态被刻意**延迟固定拍数**（典型说法"延迟一拍"，具体实现查 UM），比对器持续核对两个核的架构状态/总线输出：

```plantuml
@startuml
title 延迟锁步：错拍运行 + 持续比对（概念图）
skinparam defaultFontName "Microsoft YaHei"
[主核\n（提前执行）] as M
[冗余核\n（延迟数拍执行同一流）] as R
[延迟单元] as D
[比对器] as CMP
[SMU\n安全管理单元] as SMU
[安全状态\n(如: 关激励输出/复位,\n行为查 UM)] as SAFE

M -> D : 状态/输出经延迟线
D -> R : 冗余核"追着"主核执行
M --> CMP : 主核输出
R --> CMP : 冗余核输出
CMP -> SMU : 失配(某拍之后被逮住)
SMU -> SAFE : 报警处置
note over M,R
  为什么延迟而不是同步？
  两核处于不同指令阶段:
  同一瞬间的共模扰动(电源毛刺/粒子)
  打不中"两核的同一拍"——抗共模失效
end note
@enduml
```

两个设计点吃透：

1. **为什么延迟一拍**：若两核完全同步，一次瞬时共模扰动（电源毛刺、粒子翻转）可能同时打中两核同一阶段，两核一起错、比对结果"一致地错"——冗余失效。错开拍数后，同一扰动落在两核的不同指令阶段，很难制造同时同错的镜像，共模免疫显著提高。
2. **比的是什么**：不是"每条指令都比一遍程序员的答案"，而是持续核对架构状态与对外输出（总线访问等），失配在数个周期内被逮住——故障传播时间极短，满足安全机制的诊断时间要求。

### 物理隔离：防共模失效的第二道墙

除了时间上错拍，物理上也要隔离（芯片实现层面，概念理解）：锁步双核在版图上分开布置、关键资源冗余独立——目的同样是让"一次物理事件同时废掉两个核"的概率降到可忽略。共模失效是计算冗余的天敌，**时间错拍 + 物理隔离**双管齐下才成立 ASIL-D 论证。

### 比对失败之后：SMU 与安全状态

失配不是"复位了事"，而是一条可配置的处置链（具体行为以 UM/SMU 章节为准）：

```text
比对器失配 → SMU（Safety Management Unit，安全管理单元）报警
  → 按配置处置：
     · 记录故障（哪个核、什么类别）
     · 进入安全状态：切断激励输出（FSP 安全引脚类机制）、
       受控复位、或通知上级控制器
  → 目标：在故障潜伏期内把系统带到安全侧（fail-safe）
```

SMU 是 TC3xx 的安全枢纽：不只接 lockstep 失配，还接时钟/电压/ECC/看门狗等报警源，统一仲裁处置（见 [03-Trap与中断机制](03-Trap与中断机制.md)中 NMI 一节）。对应用软件来说，通常感知为一次 NMI/复位，真正要做的响应逻辑在安全监控软件（如英飞凌 SafeTlib 类）与 EcuM 层。

### 对软件的透明性：写代码无感，调试有感

- **运行时透明**：锁步对在软件视角是"一个核"——一份程序、一套地址空间、一套中断/trap/CSA，应用代码零修改。这正是硬件方案优于软件双份运行（双核跑同样应用互相校验）的地方：不占应用算力、不需同步框架。
- **调试受影响**：暂停/单步/观测会天然破坏"两核同步执行"的前提——调试介入时锁步行为如何降级（暂停哪侧、比对是否挂起、观测以哪个视角为准），各实现不同，以 UM 与调试器手册为准；工程实践上，取证以主视角核的寄存器/内存为准（01 区 trap 篇中"lockstep 视角"注意事项同源，见 [trap 入口代码与崩溃定位](../../../01-编程语言/2-L2进阶/汇编基础/TriCore汇编/04-trap入口代码.md)）。
- **安全配置是启动期的事**：锁步使能与相关安全配置在启动早期由 SSW/启动固件+安全库完成，应用工程一般"生在锁步里"而不自知——但要知道自己在哪对核上跑（TC377 典型为 CPU0+CPU1 锁步对 + CPU2 独立，以 DS 为准）。

### 与 ECC 的分工：一张安全拼图

| 机制 | 看护对象 | 故障模型 |
|---|---|---|
| lockstep | 核内逻辑/计算通路 | ALU/控制逻辑/核内寄存器随机失效 |
| ECC | 存储/总线（PFlash/DSPR/LMU 等） | 位翻转（单/双位错） |
| 看门狗/窗口 | 程序流 | 跑飞/卡死 |
| MPU/Trap | 地址与访问 | 越权/越界访问 |

四种机制互补拼出整机诊断覆盖率——lockstep 补的正是其他机制都够不着的"核自己算错"。指标如何折算进 ISO 26262 的 FMEDA/SPFM 论证，见 [功能安全与信息安全](../../../11-功能安全与信息安全/README.md)。

## 寄存器与位表

lockstep 是"寄存器级几乎无感"的机制：比对器、延迟单元、失配状态都在安全/测试基础设施层面，应用不可直接编程。涉及的对象（SMU 报警配置、锁步相关测试/状态寄存器、FSP 引脚控制）全部以 UM 的 SMU/安全章节为准——本篇不列位表，防止过时型号细节误导。

## 双平台对照

| 维度 | TriCore TC3xx（TC377） | Cortex-M 生态 |
|---|---|---|
| 核自诊断 | 原生硬件延迟锁步（CPU0+CPU1 对） | 无原生锁步；S32K3 部分核可选锁步 CM7 对，S32K1/M4 无 |
| 配套枢纽 | SMU 统一报警仲裁 + 安全状态输出 | 厂商方案：ECC + 看门狗 + 软件自检库（STL）拼装 |
| 软件代价 | 应用透明，几乎零侵入 | STL 需要调度时间片跑自检（占算力、要规划诊断时隙） |
| 覆盖等级 | 直接支撑 ASIL-D 的核诊断覆盖论证 | 无锁步时核内覆盖有限，多用于 ASIL-B 及以下或补硬件比较器 |
| 典型分工 | 锁步对跑安全软件 + 独立核跑性能负载 | 单核/异构双核，安全靠分区与外检 |

一句话：**AURIX 把"算得对"做进了硬件，M 生态更多靠"外围查"**——这也是底盘域长期是 AURIX 主场的原因之一。

## 代码/实操

工程师在真实工程里跟 lockstep 打交道的三件事：

1. **确认自己跑在哪**：查工程 OS/编译目标配置——应用分区在锁步对（TC377 典型 CPU0/CPU1 视角）还是独立核 CPU2；跨核通信/共享数据布局与 [04-DSPR-PSPR与寻址](04-DSPR-PSPR与寻址.md)联动。
2. **别跟调试器较劲**：锁步核上调试（暂停/单步）行为与普通核有差异，闪烁断点、非侵入式观测优先；遇到"调试时行为变化"先想锁步降级，再怀疑代码。
3. **处理安全事件**：SMU 报警/失配在上层软件的落点是 NMI/复位与故障记录——按项目安全概念接好 Dem/EcuM/安全状态路径，验证"报警→记录→安全状态"全链可观测（配置细节查 UM 与安全库手册）。

## 易错点与陷阱

1. **以为锁步"跑两份程序"**：不是软件双份运行，是同一指令流的硬件镜像；应用只有一份代码、一份地址空间，无需写同步逻辑。
2. **把冗余核当第二个核用**：锁步对在软件视角是"一个核"，不能往"另一个"上塞任务；性能负载去独立核（TC377 的 CPU2）。
3. **忽略共模失效的论证**：时间错拍+物理隔离是 lockstep 有效性的前提，做安全概念时别只答"有 lockstep 就够"，要能说清它防什么、不防什么（共模是其天敌）。
4. **调试行为异常先怀疑代码**：锁步核上暂停/观测会改变比对行为，"一挂调试器就好/就坏"的现象先查锁步调试语义，再查并发问题。
5. **拿 lockstep 当 ECC 的替代**：两者故障模型不同——锁步看不见存储介质的位翻转（两核读同一份坏数据会"一致地错"），ECC 也不管核内逻辑；拼图缺一不可。
6. **安全事件只写复位不留证据**：失配报警若只触发复位不做故障记录，量产件上就是"无理由重启"，售后无从定位——SMU 报警记录链路要随安全概念一起落地。

## 面试高频题

1. **为什么 ASIL-D 需要 lockstep？**
   答：ASIL-D 对随机硬件故障诊断覆盖有量化要求，而核内逻辑故障（ALU/控制/核内寄存器失效）用 ECC/看门狗/MPU 都覆盖不到，只能靠计算冗余；lockstep 用双核错拍执行+持续比对，把这块最大缺口补上，故障在数周期内暴露。

2. **延迟锁步为什么要把一个核延迟一拍？**
   答：若两核完全同步，瞬时共模扰动（电源毛刺/粒子）可能同时打中两核同一指令阶段，产生"一致地错"、比对失效；错拍后两核处于不同阶段，共模难以同时同错，共模免疫显著提升。物理隔离（版图分离/资源冗余）是同一目标的第二道墙。

3. **lockstep 比对失败后系统会怎样？**
   答：失配上报 SMU 安全管理单元，按配置处置：记录故障、进入安全状态（切断激励输出/受控复位等），在故障潜伏期内把系统带到安全侧；对应用常表现为 NMI/复位，响应逻辑在安全监控库与 EcuM 层（具体行为查 UM）。

4. **lockstep 和 ECC 什么关系？**
   答：互补而非替代——ECC 查存储/总线位翻转，lockstep 查核内计算逻辑；锁步读同一份坏存储会"一致地错"，ECC 修不了核内逻辑。两者加看门狗/MPU 拼成整机诊断覆盖，进 FMEDA/SPFM 论证。

5. **对应用软件开发者，lockstep 意味着什么？**
   答：运行时透明：一份代码、一套地址空间、零侵入；但要知道分区在锁步对还是独立核（影响性能/共享布局），调试时暂停/观测行为有差异（以 UM/调试器手册为准），安全事件（NMI/复位）要接故障记录与安全状态链路。

6. **和 Cortex-M 平台的安全方案比，AURIX 的思路差异？**
   答：AURIX 把核诊断做进硬件（原生延迟锁步+SMU 枢纽），应用几乎零代价；M 生态（如 S32K1）无原生锁步，靠 ECC+看门狗+软件自检库（STL）拼装，占算力且覆盖有限（S32K3 部分核可选锁步）。一句话：硬件算得对 vs 外围查得勤。
