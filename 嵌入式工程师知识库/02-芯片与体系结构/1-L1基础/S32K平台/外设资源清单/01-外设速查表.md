# 外设速查表：K1/K3 命名对照与 MCAL 映射

> 一句话定位：一张表看懂 S32K 两代外设的命名、量级与 AUTOSAR MCAL 归属——通道数与频率一律"查 DS"，本表只给"查之前就该知道的事"。
> 等级：L1→L2 ｜ 前置：[01-内核与资源对比](../S32K1与S32K3对比/01-内核与资源对比.md)

## 使用说明

- 列"量级/通道"刻意写概念（如"多实例多通道"），**具体通道数、实例数、频率上限以具体料号 DS 为准**；
- "对应 MCAL/AUTOSAR 模块"指标准分层中的位置：MCAL 有标准模块的标注模块名；通信类（Can/Lin）属通信栈驱动层（非 MCAL）；无标准模块的常以 CDD（Complex Device Driver，复杂设备驱动）实现；
- 命名代差背景见 [01-内核与资源对比](../S32K1与S32K3对比/01-内核与资源对比.md)。

## 主表：外设 × 两代命名 × MCAL 映射

| 功能 | K1 命名 | K3 命名 | 量级/通道 | 一句话特性 | 对应 MCAL/AUTOSAR 模块 |
|---|---|---|---|---|---|
| 串口 | LPUART | LPUART | 多实例（查 DS） | 低功耗 UART，功能时钟源经 PCC 选择 | 无标准 MCAL（常作 CDD） |
| SPI | LPSPI | LPSPI | 多实例多 CS（查 DS） | 低功耗 SPI，支持 DMA | Spi |
| I2C | LPI2C | LPI2C | 多实例（查 DS） | 低功耗 I2C，从机地址屏蔽等 | 无标准 MCAL（常作 CDD） |
| CAN | FlexCAN | FlexCAN | 多实例多 MB（查 DS） | 经典帧+CAN FD（支持能力查 DS），报文缓冲区架构 | 通信栈 CanDrv（CanIf 之下） |
| 定时器/PWM | FTM | eMIOS | 多通道（查 DS） | K1 用 FTM；K3 换 eMIOS（Enhanced Modular IO Subsystem），通道更丰富 | Pwm / Gpt / Icu |
| ADC | LPADC | LPADC | 多实例多通道（查 DS） | 低功耗 ADC，12bit 量级（查 DS）；触发方式两代差异大 | Adc |
| ADC 触发/延时 | PDB | BCTU | 多通道（查 DS） | K1 用 PDB 定时触发 ADC；K3 用 BCTU 做后端队列化交叉触发 | 配置于 Adc/Mcu 层（无独立 MCAL 模块） |
| 触发路由 | （SIM+FTM 链） | TRGMUX | 多路多选择器（查 RM） | K3 的全片触发交换网；K1 靠 SIM 选择+固定链 | 无（底层路由配置） |
| DMA | eDMA | eDMA | 多通道多 TCD（查 DS） | 通道数与传输控制描述符量级两代不同 | 无标准模块（被 Spi/Adc 等内部使用，或 CDD） |
| 低功耗定时器 | LPTMR | LPTMR | 单/少量实例（查 DS） | 时钟源选择在自身 PSR（坑见 [02-SIM复用配置](../时钟系统/02-SIM复用配置.md)） | Gpt（或内部时基） |
| 周期定时器 | LPIT | LPIT | 多通道（查 DS） | 周期中断定时器，功能时钟经 PCC（查 RM） | Gpt |
| 引脚复用/GPIO | PORT | SIUL2 | 全引脚（查 DS） | K1 的 PORT 管引脚级 MUX；K3 的 SIUL2 兼管更多系统路由 | Port / Dio |
| 看门狗 | WDOG（+EWM 外部监控） | WDOG（+安全监控机制，查 RM） | 1~2 个（查 DS） | 独立时钟源看门狗；K3 与安全监控体系联动（查 RM） | Wdg |
| RTC | RTC | RTC（低功耗域，查 DS） | 1 个（查 DS） | VBAT/低功耗域保持（支持能力查 DS） | 无标准 MCAL（CDD/EcuM 时基） |
| Flash | FTFC（含 FlexNVM/EEE） | Flash 控制器（查 RM，无 EEE） | 容量查 DS | 机制详见 [01-FTFC机制](../存储器与Flash/01-FTFC机制.md) | Fls / Fee |
| 加密/安全 | CSEc | HSE | 密钥槽数查手册 | CSEc=SHE 级引擎；HSE=独立安全核（详见 03 篇） | 加密栈/安全服务（见 [HSM与SHE](../../../../11-功能安全与信息安全/3-L3高级/HSM与SHE/README.md)） |

## 双平台引脚复用差异（一句话）

K1 的引脚复用在 PORT 模块的每引脚 PCR（MUX 位+上下拉+滤波），K3 收敛到 SIUL2 且路由能力更强——**同一个"这根脚干什么"的问题，两代查的寄存器章节不同**；选型后期做引脚分配表时必须用对应平台的复用表（DS Pinout/复用表），不能拿 K1 的脚位映射推 K3。

## 触发链路两代速查（定时 → ADC 采样）

ADC 触发是两代架构差异最大的一条链，选型/排障先认准自己平台的路径：

| 平台 | 链路 | 一句话 |
|---|---|---|
| K1 | FTM/固定链 → SIM 选择 → **PDB**（可编程延时块）→ LPADC | PDB 提供"触发到采样"的延时与序列编排 |
| K3 | 各触发源 → **TRGMUX**（全片触发交换网）→ **BCTU**（队列化交叉触发）→ LPADC | 触发源任意组合、后端队列化，K1 思路在 K3 上落空 |

排障口诀：**采样不出来先画触发链全图，再逐节点量"触发有没有到"**——K1 查 PDB 状态与 SIM 选择，K3 查 TRGMUX 路由表与 BCTU 队列（详见 [01-SCG与PCC](../时钟系统/01-SCG与PCC.md)）。

## 外设时钟依赖速查（只列"坑过人"的）

| 外设 | 时钟/路由依赖 | 坑位提示 |
|---|---|---|
| LPUART | 功能时钟源经 **PCC** 选择 | 波特率全错先查 PCC 时钟源与分频，别先怀疑寄存器 |
| LPTMR | 时钟源选择在**自身 PSR**，不走 PCC | 与 LPUART 的直觉相反，见 [02-SIM复用配置](../时钟系统/02-SIM复用配置.md) |
| LPIT | 功能时钟经 **PCC** | 计数周期与预期不符先核 PCC 分频 |
| FlexCAN | PE 时钟源选择 + 采样点配置 | 与位时序参数联动核对（见 05 区 CAN 协议原理篇） |

## 选型与配置核对清单（立项时逐项过）

- [ ] 目标料号的实例数/通道数/频率上限逐项从 DS 摘录进资源需求表，禁止沿用"上一颗的经验值"；
- [ ] 定时器体系先定型：K1=FTM+PDB、K3=eMIOS+TRGMUX+BCTU，PWM 与采样触发链路按平台展开成图；
- [ ] 无 MCAL 标准模块的外设（LPUART/LPI2C/RTC/eDMA 直用）在立项时明确 CDD 归属与维护 owner；
- [ ] eDMA 通道预算表：列出全部 DMA 用户（Spi/Adc/CDD）的通道分配与仲裁优先级，两代 TCD 模型分别核对；
- [ ] 看门狗按代际评审：K3 与安全监控机制联动项在功能安全概念阶段过一遍（查 RM）；
- [ ] 引脚分配表用对应平台的复用表（DS Pinout）制作，K1 脚位映射不能推 K3（PORT vs SIUL2）。

## 易错点与陷阱

1. **FTM 与 eMIOS 当同一个东西**：功能定位类似（PWM/定时），寄存器模型与配置思路完全不同，驱动不可平移；
2. **PDB 在 K3 上找不到**：ADC 触发体系整体换成 TRGMUX+BCTU，按 K1 思路找"延时块"会落空（见 [01-SCG与PCC](../时钟系统/01-SCG与PCC.md) 的触发链路）；
3. **把 LPUART/LPI2C 当 MCAL 标准模块配置**：MCAL 无 Uart/I2c 标准模块，工程里一般是 CDD——分层评审时要明确归属（方法论见 [CDD设计方法论](../../../../04-MCAL与外设驱动/2-L2进阶/CDD设计方法论/README.md)）；
4. **通道数凭印象写死在代码里**：同家族不同料号实例/通道不同，用编译期配置或 DS 核对，别用"上一颗的经验值"；
5. **eDMA 通道数两代不同**：TCD（Transfer Control Descriptor，传输控制描述符）数量与通道仲裁模型按平台 DS 核对，调度假设不能跨代沿用；
6. **看门狗当普通 WDOG 配**：K3 的看门狗与安全监控机制联动（查 RM），配置项与失效行为比 K1 丰富，功能安全项目要逐项评审（见 [Wdg](../../../../04-MCAL与外设驱动/2-L2进阶/Wdg/README.md)）。

## 面试高频题

1. **S32K1 和 K3 的定时器体系有什么差异？**
   答：K1 用 FTM（FlexTimer， PWM/输入捕获/定时），K3 换成 eMIOS（通道资源更丰富）；同时 ADC 触发从"PDB 延时块"演进为"TRGMUX+BCTU 队列化触发"，定时→采样的整条链路两代架构不同。

2. **LPUART/LPI2C 在 AUTOSAR 里怎么归类？**
   答：MCAL 没有标准 Uart/I2c 模块——LPUART/LPI2C 通常以 CDD 形态实现（或移植现有 CDD 库）；对比 LPSPI 有标准 Spi 模块、CAN 走通信栈 CanDrv。

3. **K3 的 SIUL2 和 K1 的 PORT 是什么关系？**
   答：职责对应的换代关系：都管引脚级复用（MUX/上下拉），SIUL2 是 K3 的系统输入输出与加载单元，路由能力更强；配置工具层面都由 Pins 配置收口。

4. **为什么这张表里很多格子写"查 DS"？**
   答：S32K 家族料号众多，实例数/通道数/频率上限是料号相关参数，跨料号不通用；正确姿势是"概念看表、数值查 DS"，避免经验值固化到代码。

5. **eDMA 在 MCAL 分层里算什么？**
   答：eDMA 不是 MCAL 标准模块，它是被 Spi/Adc 等 MCAL 驱动内部使用的硬件资源（DMA 通道分配与优先级在对应 MCAL 配置里做）；纯软件搬运场景下 eDMA 常以 CDD 封装（另见 [DMA专题](../../../../04-MCAL与外设驱动/3-L3高级/DMA专题/README.md)）。
