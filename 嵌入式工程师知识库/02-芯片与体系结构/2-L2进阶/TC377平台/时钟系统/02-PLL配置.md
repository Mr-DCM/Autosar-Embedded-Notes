# PLL 配置：从晶振到内核主频的算术题

> 一句话定位：PLL（锁相环）用"分频 N/P × 倍频 K"把低成本晶振倍到内核主频，锁定检测、VCO 约束与频率规划是性能与安全的交界线。
> 等级：L2 ｜ 前置：[01-CCU与时钟树](01-CCU与时钟树.md)

## 原理

### 倍频原理与频率算式

PLL（Phase Locked Loop，锁相环）通过鉴相-滤波-压控振荡的闭环，把输出频率锁定在输入频率的固定倍数上。概念算式（符号仅作示意，真实系数名/合法范围/寄存器字段一律查 UM PLL 章节）：

```text
f_VCO = f_osc × (K1 × K2) / N
f_PLL = f_VCO / P
其中：N、P 为分频系数，K1、K2 为倍频系数
约束：f_VCO 必须落在手册允许区间；f_PLL 不得超过内核/各域上限（查 DS）
```

算例（纯示意，系数随便取的合法形状）：f_osc = 20 MHz，K1×K2 = 80，N = 2，则 f_VCO = 800 MHz；P = 4，则 f_PLL = 200 MHz。同一个 f_PLL 可能有多组 (N, K, P) 组合，选型时要同时满足 VCO 区间、各分频档位步进和功耗。

### 频率规划四步法

1. 定目标：内核主频、fSPB、fGTM、外设粒度各自要多少；
2. 选晶振：板级约束（常见 20 MHz 量级，以原理图为准）；
3. 解方程：枚举满足 VCO 约束的 (N, K1, K2, P) 组合，优先取"能整除出全部下游时钟"的组合；
4. 验边界：对照 DS 逐项核对各时钟域上限与外设粒度需求（如 CAN 位时序、PWM 分辨率）。

### 切换流程与时序（概念）

上电或改频的标准节奏：

1. 在内部 RC/当前稳定源上运行，先完成最小初始化；
2. 配置 PLL 参数（分频 N/P + 倍频 K，字段查 UM）；
3. 等待锁定状态位置位，必须带超时保护（锁定时间量级查 UM）；
4. 切换系统时钟到 f_PLL；
5. 重新校验各时钟域使能与外设粒度（PWM、波特率、tick）。

反模式：跳过第 3 步不等锁定；或切源前已有外设带病运行，切换瞬间半新半旧的频率让外设状态机进死角。

### 频率规划表模板（概念）

| 时钟域 | 目标频率 | 来源 | 系数组合 | 用途/约束 |
|---|---|---|---|---|
| f_PLL | （填） | 晶振 × PLL | (N, K1, K2, P) = （填） | 全局主频，VCO 约束见算式 |
| fCPU0/1/2 | （填） | f_PLL 分频 | （填） | 三核同频或按域规划 |
| fSPB | （填） | f_PLL 分频 | （填） | 不超 DS 上限 |
| fGTM | （填） | 独立选择 | （填） | 定时粒度满足 PWM 分辨率 |

这张表随设计文档归档，评审时按行验算；投产后任何改频都要回到这张表重算下游影响；有条件时用实测值回填"目标频率"列，避免长期停留在设计值。

### 锁定时间与锁定检测

- 上电/改参后 PLL 需要锁定时间（Lock Time，与环路带宽、频差相关，量级与计算查 UM）才输出稳定频率；
- 硬件提供锁定状态位与失锁告警：配置流程必须"等待锁定"再切换系统时钟到 f_PLL；运行期失锁会触发告警并走 CCU 失效兜底链路（见 [01-CCU与时钟树](01-CCU与时钟树.md)）；
- 切换时机是安全点：先把外设时钟依赖降到最低（早期初始化阶段切源），别在系统满负荷跑外设时切。

### 外设对时钟的特殊要求

| 外设 | 对时钟的敏感性 | 后果 |
|---|---|---|
| GTM（通用定时器模块） | 定时粒度直接由输入时钟决定，通道周期/占空比分辨率都从它推导 | 时钟选错档，PWM/计数全体偏移（详见 [GTM](../GTM/README.md)） |
| CAN/CAN FD | 位时序从模块时钟分频推导 | 频率错 → 波特率错 → 总线错误被动/离线 |
| ADC | 采样转换节拍与时钟域相关 | 转换时间/序列时序偏移 |
| OS tick | 由定时器时钟推导 | 所有超时/调度整体漂移 |

### 时钟配错的典型现象与排查

- **波特率全错**：CAN 采样点漂移、UART 乱码——先算"实际 f_PLL 是否等于假设值"，再查分频链；
- **外设无响应**：十有八九是模块时钟没开（见 03 篇），其次才是寄存器/引脚问题；
- **周期性抖动/偶发复位**：怀疑切源时未等锁定，或时钟域上限被超；
- 排查顺序：TRACE32 读 PLL/CCU 寄存器实际值 → 按算式反推真实频率 → 用时钟输出引脚+示波器实测（支持与否查 DS）。

## 寄存器与位表

> 位号/复位值/合法范围查 UM PLL 章节，此处只列字段族谱。

| 寄存器（概念） | 内容 | 要点 |
|---|---|---|
| PLLCON0（示意） | 分频 N/P、工作模式、锁定状态位 | 锁定位是流程闸门：等它再切源 |
| PLLCON1（示意） | 倍频系数 K1/K2 | 合法值离散，不是任意整数 |
| PLLCON2（示意） | 细分/微调类参数 | 高级用法，默认不动 |
| 告警/状态寄存器 | 失锁/失振告警 | 告警路由到 SMU 并使能处理 |

### 改频回归测试清单

任何一次 PLL/分频参数变更，至少回归以下项（都按"实际输出"而非"设计值"验收）：

1. 时钟链路实测：TRACE32 读寄存器反推 + 示波器测时钟输出（如可用）；
2. 通信类：CAN 波特率与采样点、UART 回环、LIN 调度表；
3. 定时类：PWM 周期/占空比、OS tick 周期、看门狗窗口时间；
4. 存储类：PFlash 等待状态与当前频率匹配（见存储器映射 03 篇）；
5. 低功耗：进出睡眠/待机后时钟状态与初始化一致；
6. 功能安全：失锁/失振告警路径仍然有效（告警→SMU→处理）。

改频不是"数字游戏"：它同时改变了通信、定时、存储三界的物理基准，回归范围必须按此展开。

## 双平台对照（AURIX vs S32K）

| 维度 | TC377（AURIX TC3xx） | S32K1xx |
|---|---|---|
| PLL 结构 | 多级分频+倍频（N/K/P 组合），VCO 约束显式 | SPLL 以"倍频÷分频"直接配置（查 S32K SCG 章节） |
| 锁定判断 | 状态位+告警→SMU | 锁定标志位轮询 |
| 配置入口 | MCAL Mcu 时钟配置/iLLD 封装 | MCAL Mcu / SDK Clock Manager |
| 失锁兜底 | 告警→SMU→安全状态链路 | 时钟监视/锁定丢失告警（处理策略查 RM） |
| 频率规划 | 组合多、需解方程 | 相对直接，档位少 |

## 代码/实操

- MCAL 侧：Mcu 模块把"PLL 参数、锁定等待、时钟分发"封装成配置驱动的初始化序列（配置类参数与 API 名以所用 MCAL 版本为准，专题见 [Mcu模块](../../../../04-MCAL与外设驱动/2-L2进阶/Mcu模块/README.md)）；
- iLLD 侧：提供 PLL 启动/等锁定的底层封装（`IfxScu_*` 前缀概念，接口以版本为准）；
- 评审抓手：把"晶振频率 × (K1×K2) / N / P = 目标频率"的算式写进设计文档，与 Tresos/EB 配置截图一起归档，评审时手动验算一遍。

## 易错点与陷阱

1. 不等锁定就切源：短窗内全芯片跑在错误频率，外部表现千奇百怪且难复现；
2. 频率规划只顾内核：下游 fSPB/fGTM 粒度不满足外设需求（PWM 分辨率不够、CAN 采样点难看），返工改整条链；
3. VCO 区间约束被忽略：配置工具报错还硬绕，实际输出频率与理论不符；
4. 两套代码各自假设不同 f_PLL：驱动按 200 MHz 算延时、实际 160 MHz，超时逻辑全体失真——频率作为全局宏统一管理；
5. 失锁告警只挂不复位：告警来了没人处理，等于没有；
6. 低功耗恢复后忘记重新校验时钟状态：唤醒路径与上电路径不对称，恢复成内部 RC 也有可能；
7. 直接抄评估板/demo 的 PLL 参数到本项目：晶振不同、下游需求不同，参数不可移植，必须重走规划四步法；
8. 频率规划表长期不更新：表停留在设计期版本，改频后没回填，后人按旧表排查被带偏。

## 面试高频题

1. **写出 PLL 输出频率与晶振的关系式并解释各系数。**
   答：f_VCO = f_osc × (K1×K2)/N，f_PLL = f_VCO/P（符号示意）。N/P 是分频，K 是倍频；组合选择受 VCO 允许区间和各时钟域上限约束（档位查 UM）。

2. **PLL 锁定时间与什么有关？为什么要等它？**
   答：与环路带宽和频差有关（量级见 UM）。锁定前输出频率不稳，此时切源会让全芯片短暂运行在错误频率，引发不可预期的外设行为。

3. **怎么给一个新项目做频率规划？**
   答：先定内核/外设需求（含 PWM 分辨率、CAN 位时序、OS tick），选晶振，枚举满足 VCO 约束的系数组合，对照 DS 上限验边界，最后把算式归档供评审。

4. **CAN 波特率全错，时钟侧怎么查？**
   答：先验证真实 f_PLL：TRACE32 读 PLL 寄存器反推，必要时示波器实测时钟输出；再核对模块时钟是否开启、分频是否按真实频率计算。九成问题在"假设频率≠实际频率"。

5. **GTM 为什么对输入时钟特别敏感？**
   答：GTM 的定时粒度、通道周期、占空比分辨率全部由输入时钟推导，时钟档位选错会让所有 PWM/计数输出成比例偏移，且配置工具里看起来"完全正常"。

6. **VCO 为什么有允许区间约束？**
   答：压控振荡器只在特定频率范围内具备稳定的振荡与锁定特性，超出后环路难以可靠锁定。所以频率规划必须先满足 VCO 区间，再谈目标频率（区间数值查 UM）。
