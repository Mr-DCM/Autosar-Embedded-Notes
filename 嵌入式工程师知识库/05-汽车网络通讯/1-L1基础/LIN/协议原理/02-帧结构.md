# 02-帧结构

> 一句话定位：LIN 帧 = 帧头（Break+Sync+PID）+ 响应（数据+校验和），每字节套一层 UART 外衣（起始+8 数据+停止=10 位）——把这张位级账单算清，调度表、超时、校验问题全都有了度量衡。
> 等级：L1 ｜ 前置：[01-主从与调度表](01-主从与调度表.md)

## 原理

一帧 LIN 在总线上的字节流形态（显性=低电平 0V，隐性≈电源电压）：

```wavedrom
{ signal: [
  { name: 'LIN 总线', wave: '0.3.3.3.3.3.3.1.', data: ['Break≥13显性','Sync 0x55','PID','D0','D1','D2','CK'] },
  { name: '谁在发',   wave: 'x.5.5.x.x.x.x.x.', data: ['主','主','主','从','从','从','从'] }
], head: { text: '帧头(主发) + 响应(发布者发)', tick: 1 } }
```

逐域解剖（全部按 LIN 2.x 口径）：

| 域 | 内容 | 位数 | 发出者 | 要点 |
|---|---|---|---|---|
| Break | ≥13 位连续显性 + ≥1 位隐性分隔符 | ≥14 | 主 | 总线上唯一不可能由普通数据"冒充"的序列，从机借此锁定帧头起点 |
| Sync | 0x55 | 10 | 主 | 01010101 规律边沿，从机测频校准波特率 |
| PID | 帧ID(6位)+保护位P0/P1 | 10 | 主 | ID≠PID，保护位防帧头位错被误认 |
| Data | 1~8 字节（典型 2/4/8；LIN1.3 仅 2/4/8） | 10×N | 发布者 | 主或被点名的从机 |
| Checksum | 1 字节校验和 | 10 | 发布者 | 经典/增强两型，详见 [排障/02-checksum类型](../排障/02-checksum类型.md) |

每个字节都是标准 UART 帧：**1 起始位（显性）+ 8 数据位（LSB first）+ 1 停止位（隐性）= 10 位**。所以一帧的位账单：帧头 34 位（Break 13+分隔 1+Sync 10+PID 10），响应 10×(N+1) 位，合计 **44+10N 位**（不含间隔）。

**PID 的生成**：帧 ID 只有 6 位（0x00~0x3F），两位奇偶保护位按下式叠加——

```
P0 = ID0 ^ ID1 ^ ID2 ^ ID4
P1 = ~(ID1 ^ ID3 ^ ID4 ^ ID5)
PID = ID | (P0<<6) | (P1<<7)
```

验算：ID=0x10 → P0=1，P1=0 → PID=0x50；ID=0x3C（诊断请求）→ P0=P1=0 → PID=0x3C。工程含义：**总线上传的永远是 PID，从机配置里也认 PID**；把 0x50 当 ID 用是新人最常见的配错。

## 详解

帧里还有三处"看不见的空隙"，它们不传数据却吃时间：

- **响应空间（Response Space）**：PID 停止位到响应首字节起始位之间的隐性空闲。规范允许 0 起，但从机需要启动发送（中断进 ISR+装配数据），典型留 2~4 位；上限受响应超时约束（超了主节点判超时）。它是"从机跟得上吗"的第一指标。
- **字节间隔（Inter-byte Space）**：响应中相邻字节之间的额外隐性位。发布者软件逐字节填寄存器慢了就会插进来——所以**最坏帧长永远比理论值长**，调度表槽长必须留余量。
- **帧间间隔（Inter-frame Space）**：相邻槽之间的总线空闲。主任务换槽、查表都需要时间。

帧长直接换算工程参数（19.2 kbps、8 字节帧）：(44+80)÷19200 ≈ 6.5ms 理论值；计入响应空间与字节间隔的余量后，槽长典型配 8~10ms。**先算账再配表**，是 LIN 配置区别于"抄模板"的基本功。

常用帧长的速查账单（19.2 kbps 口径）：

| 数据字节 N | 总位数 44+10N | 理论帧时长 | 建议槽长（×1.4 取整） |
|---|---|---|---|
| 1 | 54 | 2.8 ms | 4 ms |
| 2 | 64 | 3.3 ms | 5 ms |
| 4 | 84 | 4.4 ms | 6 ms |
| 8 | 124 | 6.5 ms | 9 ms |

换波特率（如 9600）只需按时长×2 换算；排障时把示波器实测帧时长对回这张表，偏差异常即指向波特率或间隔异常。

帧的分类速记（按 LDF 里的 frame 类型）：

| 类型 | 谁发响应 | 触发方式 |
|---|---|---|
| 无条件帧 | 固定发布者 | 每轮到槽必发 |
| 事件触发帧 | 多从机可能抢答 | 仅数据变化的从机发缩短响应 |
| 偶发帧 | 主节点 | 有数据才发，占位优先 |
| 诊断帧 0x3C/0x3D | 主请求/从响应 | 诊断表专用 |

## 配置层/工程关联

- **LinIf**：每帧落地为一个 `LinIfFrame` 配置：PID、帧类型（LinIfFrameType：UNCONDITION/EVENT_TRIGGERED/…）、数据长度、校验类型（LinIfChecksumType：CLASSIC/ENHANCED）、超时参数。LDF 的 Frames 节与它一一对应（见 [LDF结构](../LDF与配置/01-LDF结构.md)）。
- **LinDrv**：只负责把字节按 UART 打出/收回，帧头 Break 生成与测量回溯在驱动层实现，见 [LinDrv接口契约](../../../../04-MCAL与外设驱动/2-L2进阶/CanDrv与LinDrv/02-LinDrv接口契约.md)。
- **Com/PduR**：数据场的位排布由 Com 按 Signal 起始位/长度装取（见 [信号映射](../LDF与配置/02-信号映射.md)）。
- **CANoe 抓包列**：Trace 里 Header/Error 列直接给出 Break 宽度、PID、校验结果——本文每一域都能在 Trace 中对号入座。

## 易错点与陷阱

1. **现象**：从机永远不响应某帧。**原因**：主机配置用 PID，从机按帧 ID（或反之）过滤。**对策**：统一按 PID 0x55 式公式换算，LDF 导入的工具链里核对。
2. **现象**：槽内偶发帧超时，低负载正常。**原因**：槽长按理论帧长配死，从机响应空间/字节间隔吃掉余量。**对策**：槽长=理论帧长×1.3~1.4。
3. **现象**：帧长计算对不上示波器实测。**原因**：忘了每字节 10 位（UART 起停位）或忘算 Break。**对策**：按"帧头 34+响应 10×(N+1)"口径重算。
4. **现象**：从机偶尔丢首字节。**原因**：响应空间不足，从机 ISR 未及时启动发送。**对策**：硬件 UART+DMA/提前预装配数据；或主节点允许更大响应空间。
5. **现象**：CANoe 显示 Break 过短报警。**原因**：主节点 Break 生成用软件延时，被抢占后不足 13 位。**对策**：用硬件 Break 发送机制（见 [排障/03-排障实录](../排障/03-排障实录.md) 案例一）。

## 面试高频题

1. **问：LIN 帧头由什么构成？为什么需要 Break？**
   答：Break（≥13 位显性+分隔符）+Sync 0x55+PID。普通数据字节最多连续 9 位显性（起始终止位夹 0x00），13 位显性不可能被数据冒充，从机据此无误判地锁定帧头起点。
2. **问：PID 与帧 ID 的关系？保护位怎么算？**
   答：PID = 6 位 ID 加两位奇偶保护位，P0=ID0⊕ID1⊕ID2⊕ID4，P1=ID1⊕ID3⊕ID4⊕ID5 取反；用于在无 CRC 的帧头上把位错拦下，防止一帧错认成另一帧。
3. **问：19.2kbps 下 8 字节帧的最坏传输时间怎么估？**
   答：位账单 44+10×8=124 位 ÷19200 ≈6.5ms，再乘 1.3~1.4 余量（响应空间+字节间隔）≈8~9ms，即槽长下限。
4. **问：什么是响应空间？它反映什么问题？**
   答：PID 结束到响应首字节的隐性空闲，反映从机软件响应能力（中断延迟+数据装配），过大则触发主节点响应超时，过小则从机跟不上。
