# 项目复盘模板：把项目经历变成可复用资产

> 一句话定位：给出一份项目复盘的六段式模板（概况/关键决策/踩坑/资产/度量/改进）与资产化清单——做完项目不是终点，把配置基线、CDD、脚本、问题单库沉淀成"下次直接用"的个人资产，这才是从做项目到长能力的分水岭。
> 等级：L3 ｜ 前置：[一个ECU项目的一生-实战全景](../../00-入门导读/01-一个ECU项目的一生-实战全景.md)

## 太长不看

- 复盘不是写总结交差，是**资产盘点**：每个项目结束时你应带走 3~5 件可复用物（配置基线、CDD、脚本、检查清单、问题档案），下一项目直接站在它们上面；
- 六段式模板固定骨架：概况→关键决策（为什么这么选）→踩坑（问题单精选转档案）→资产（入库清单）→度量（数据说话）→改进（下次的 TODO）；
- 工程深入场景：接手同类新项目第一周、面试"讲一个你做过的项目"、团队知识库建设——复盘档案三处直接变现。

## 1. 核心概念：经历 ≠ 经验

同样做两年项目，有人成长飞速有人原地踏步，差别在"经历是否被加工成经验"。问题单闭环了、样件交付了，信息还散落在 Jira、邮件、聊天记录和你的记忆里——三个月后衰减一半，换个工作归零。复盘就是**赶在遗忘前做一次结构化萃取**：把项目时间线（导读那三段八站）上的产出，按"决策—证据—资产"三条线归档。

```plantuml
@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontSize 13
top to bottom direction
:项目收尾（SOP 或阶段结束）;
partition "六段式复盘" {
  :① 项目概况\n规模/周期/角色/交付物;
  :② 关键决策\n选型与取舍+为什么;
  :③ 踩坑档案\n问题单精选→一坑一档;
  :④ 资产清单\n配置/CDD/脚本/清单;
  :⑤ 度量数据\n周期/缺陷率/返工率;
  :⑥ 改进 TODO\n下次项目的第一页;
}
:入库：个人知识库\n+团队 wiki;
note right
  萃取标准：
  换个项目还能用的才叫资产，
  只对本项目有意义的是记录
end note
@enduml
```

## 2. 详解：六段怎么填

**① 概况**：一句话项目定位（车型/ECU/芯片/ASIL）、周期与你的角色、交付物清单（软件包数、文档数）。作用是给未来的你一个索引头。

**② 关键决策**：挑 3~5 个影响最大的决策，每个记"选项—取舍依据—结果验证"。例如：诊断 DID 规划为何用分段编码（对照 [DID 命名与字节序规范](../../../06-诊断与标定/2-L2进阶/DID与RID设计/01-命名与字节序规范.md)）、分核方案为何通讯独占一核（对照 [TC377 模板](../../2-L2进阶/TC377工程模板/01-模板说明.md)）、NvM 为何选显式同步（对照 [写队列与显隐同步](../../../07-AUTOSAR架构/2-L2进阶/内存栈/02-写队列与显隐同步.md)）。**决策的可迁移性比结论值钱**——换项目时依据仍成立。

**③ 踩坑档案**：从几十张问题单里挑 5~10 张"有故事的"（定位过程曲折的、根因反直觉的、跨模块联动的），按 [一坑一档模板](../../../09-调试与测试/2-L2进阶/踩坑案例库/00-一坑一档模板.md) 转写：现象→环境→时间线→根因（5Why）→修复→预防。这一段与 09 区踩坑库同源，写完直接投稿。

**④ 资产清单**：见下表逐项打勾，这是复盘的硬产出：

| 资产 | 形式 | 复用方式 |
|---|---|---|
| 配置基线 | tresos/DaVinci 工程快照+参数说明 | 新项目起点，先 [diff-review](../../../07-AUTOSAR架构/2-L2进阶/方法论与ARXML/04-diff-review技巧.md) 再增量 |
| 自研 CDD | 源码+接口文档+单元测试 | 平移后换 MemMap 段与中断挂接（[CDD 模板与评审清单](../../../04-MCAL与外设驱动/2-L2进阶/CDD设计方法论/04-模板与评审清单.md)） |
| 脚本 | 出包/diff/回归脚本 | 进 [脚本索引](../../../10-工具链与工程化/2-L2进阶/辅助脚本沉淀/01-脚本索引.md) |
| 检查清单 | 集成检查/交付检查/评审清单 | 下次当 checklist 用，防重复踩坑 |
| 问题单库 | 导出的 Jira 全量+精选档案 | 风险预判与估算依据 |

**⑤ 度量数据**：用数字校准直觉——问题单总数/按模块分布/根因分类占比、返工率（reopen 比例）、集成测试通过率趋势、每版软件包 bug 收敛曲线。没有度量的复盘容易变成印象流。

**⑥ 改进 TODO**：收敛成 3~5 条可执行项（"下个项目第一周就把出包脚本就位"），并写进下个项目计划——**复盘的闭环不在文档里，在下一个项目的动作里**。

复盘节奏建议双轨并行：里程碑复盘（A/B/C 样各一次，30 分钟轻量版，只填②③⑥三段）+ 结项复盘（完整六段，半天）。前者防遗忘，后者出资产——只有结项才做的复盘，等于把最鲜活的证据等成了化石。

## 3. 易错点与陷阱

- **现象：复盘写成流水账"我们做了 A 做了 B"。原因：** 只记做了什么，不萃取为什么与换什么。**对策：** 模板强制三问：这个决策换项目还成立吗？这个问题下次怎么提前发现？这件东西能直接复用吗？三问答不上的段落删掉。
- **现象：复盘开完，资产清单上全是"下次再说"。原因：** 没有当场入库的机制，清单变成愿望单。**对策：** 复盘会的产出物当场进库（Git 提交/wiki 建页），"散会即入库"。
- **现象：踩坑档案越写越多但没人再看。原因：** 只存档不索引，检索成本高于重踩一次的代价。**对策：** 每档打标签（模块/现象关键词/根因类别），并同步到踩坑库让 [CANoe](../../../09-调试与测试/2-L2进阶/总线工具/01-CANoe.md) 类工具的排查 SOP 引用。
- **现象：度量数据齐全但结论互相矛盾。原因：** 指标口径不一（缺陷按单还是按需求算）、样本期不同（A 样期 vs C 样期混算）。**对策：** 复盘前先统一定义与切分窗口，数据才有可比性。
- **现象：复盘只在项目结束做一次，信息已大量失真。原因：** 遗忘曲线+人员流动。**对策：** 双节奏——里程碑复盘（A/B/C 样各一次，轻量半小时）+结项复盘（完整六段），关键决策当时就记草稿。

## 4. 面试高频题

**Q：讲一个你做过的项目。（复盘视角的答法）**

答：用复盘档案的骨架反着讲：一句话定位→我负责的范围与关键决策（1~2 个，含取舍依据）→一个印象最深的坑（现象→根因→修复）→量化结果（缺陷收敛/交付准时率）→沉淀（带走什么资产）。五步三分钟，比流水账强十倍——这也是复盘最大的变现场景。

**Q：你怎么保证问题单里的经验不随人员流失？**

答：三层：问题单本身的根因字段强制结构化（根因类别枚举）；定期把"高价值单"萃取成一坑一档进知识库（标签索引）；里程碑复盘把模式性问题升级为检查清单——从"记录"到"检索"到"预防"。

**Q：复盘出的"可复用配置基线"，直接拷到新项目有什么风险？**

答：三重风险：残留旧项目专有参数（DID、报文路由）造成隐性错误；芯片/BSW 版本不匹配（参数模型变了）；安全配置（E2E/WdgM）与新项目 ASIL 不符。正确姿势是先 diff-review 全量差异、再按新项目需求逐类确认——模板是起点不是答案。

**Q：项目复盘和 5Why、一坑一档是什么关系？**

答：一坑一档是单问题的深挖格式，5Why 是其中的根因分析工具，项目复盘是项目级的批量萃取容器——单点工具装在容器里按 ③ 段落归档，三者是"问题—工具—流程"的层级关系。
