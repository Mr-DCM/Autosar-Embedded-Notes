# SID29-认证

> 一句话定位：ISO 14229-1:2020 引入的证书级身份认证——用非对称密码学替代 27 的静态 seed-key，支撑 OTA 与远程诊断的安全底座；现阶段先懂概念与流程，量产件仍以 27 为主。
> 等级：L2 ｜ 前置：[SID27-安全访问](SID27-安全访问.md)

## 原理

### 背景：27 的密码学天花板

seed-key 的三个软肋：**算法静态可逆向**（逆向固件即破防）、**可重放**（无时间因子，同一对 seed/key 可重用）、**密钥全车型共享**（一把钥匙开全城）。2020 版为 OTA 云端刷写、远程诊断场景引入 29 Authentication：基于 **X.509 证书 + 非对称签名**，ECU 只存证书公钥不存秘密，诊断仪用私钥证明身份。

### 两种验证模式

```plantuml
@startuml
autonumber on
participant "诊断仪\n(持私钥+证书)" as TESTER
participant "ECU\n(存信任根证书)" as ECU

== 模式 A：证书验证（verifyCertificate）==
TESTER -> ECU : 29 01（verifyCertificateUnconditional）
ECU --> TESTER : 69 01 <challenge（随机挑战值）>
TESTER -> TESTER : 用私钥对 challenge 签名
TESTER -> ECU : 29 06 <证书+签名>（proveIdentity）
note right of ECU : 验证书链（对信任根）→\n验签名（对 challenge）
ECU --> TESTER : 69 06 <verificationResult>（通过即认证成功）

== 模式 B：挑战验证（ECU 持证书，双向）==
TESTER -> ECU : 29 07（getChallenge）
ECU --> TESTER : 69 07 <challenge>
TESTER -> ECU : 29 05 <诊断仪的 challenge>（sendChallenge）
ECU --> TESTER : 69 05 <ECU 证书+签名>（ECU 自证身份）
note over TESTER : 验证 ECU 证书——防假 ECU
TESTER -> ECU : 29 06 <签名>（proveIdentity，双向闭合）
ECU --> TESTER : 69 06（认证完成）
@enduml
```

核心都是**挑战-应答**：一方出随机数（challenge），另一方用私钥签名作答——随机数保证不可重放，证书链保证身份可溯。

### 子功能一览（14229-1:2020 口径）

| 子功能 | 名称 | 干什么 |
|---|---|---|
| 0x00 | deAuthenticate | 主动退出认证（类似重新上锁） |
| 0x01 | verifyCertificateUnconditional | 无条件证书验证：总要走一遍完整验证 |
| 0x02 | verifyCertificateConditional | 条件证书验证：证书已在有效期/未变更时可走捷径 |
| 0x03 | authenticationConfiguration | 读取认证配置（支持哪些角色/算法） |
| 0x04 | sendCertificate | 发送证书（含证据，如 PKI 时间证据） |
| 0x05 | sendChallenge | 诊断仪向 ECU 发挑战（ECU 持证书场景） |
| 0x06 | proveIdentity | 提交身份证明（证书+对挑战的签名） |
| 0x07 | getChallenge | 获取 ECU 挑战值 |
| 0x08 / 0x0D | sendTime / sendCertPartial | 发送时间证据 / 部分证书（离线场景补件） |

认证结果按**角色（Role）**授予权限：证书里带角色标识（如"诊断工程师/产线工位/云端服务"），ECU 按角色映射到对应解锁等级——比 27 的"N 级解锁"表达力强得多。

### 29 vs 27 对比

| 维度 | 27 SecurityAccess | 29 Authentication |
|---|---|---|
| 密码学 | 对称/自制算法（seed→key） | 非对称：证书链+签名（如 ECC/RSA） |
| 密钥分发 | ECU 与工具预共享同一算法/密钥 | ECU 只存信任根公钥，工具持私钥证书 |
| 抗重放 | 弱（纯映射可重放） | 强（随机挑战，一次性） |
| 密钥泄露后果 | 全车型沦陷，换密钥=刷全量 | 吊销单个证书即可，PKI 管理生命周期 |
| 有效期 | 会话期（切会话/复位/超时即失效） | 证书有效期+会话期双重（可跨会话短存续） |
| 实现成本 | 极低（几行代码） | 高：证书存储、验签算力、时间管理 |
| 现状 | 量产绝对主流 | 新平台/OTA 车型逐步落地 |

**何时用哪个**：传统产线/售后用 27 足够（物理接触、攻击面小）；支持 OTA/远程诊断、有 PKI 体系的新架构用 29——两者可并存：29 认证成功后映射解锁等级，替代 27 的角色。

## 详解

### 报文格式逐字节

**请求（以 getChallenge 为例）：** `29 07`

| 字节 | 值 | 含义 |
|---|---|---|
| 1 | 0x29 | SID：Authentication |
| 2 | 0x07 | 子功能（+0x80 可抑制，但认证链不建议抑制） |
| 3~n | — | 该子功能的参数（challenge/证书为变长数据） |

**正响应：** `69 07 + challenge`

| 字节 | 值 | 含义 |
|---|---|---|
| 1 | 0x69 | SID+0x40 |
| 2 | 0x07 | 回显 |
| 3~n | challenge | 随机挑战值（算法相关长度） |

**proveIdentity 正响应末尾的 verificationResult**：按 2020 版口径含认证状态与剩余尝试等信息——**与 27 一样有尝试计数与延时机制**，超限报 NRC 0x36/0x37。

**负响应 `7F 29 NRC`：**

| NRC | 场景 |
|---|---|
| 0x12/0x13 | 子功能不支持/长度错 |
| 0x22 | 前置条件不满足（如需先满足会话/时间条件） |
| 0x31 | 证书格式/角色不被支持 |
| 0x35/0x36/0x37 | 验签失败（invalidKey）/尝试超限/延时未到（复用 27 家族的码） |
| 0x7E/0x7F | 会话不支持 |

## 配置层

- 29 的落地是 Dcm 与 **Crypto Stack（CSM/CryIf/Crypto）** 协作：证书解析、ECC 验签走 Crypto 驱动——TC377 的 SHE/HSS 硬件加速器在此发挥作用，接线见 [Dcm配置](../../2-L2进阶/Dcm配置/README.md)；
- 信任根证书的存放（安全 Flash 区/OTP）、证书更新流程属安全启动与密钥管理范畴，与 [Bootloader](../../3-L3高级/Bootloader/README.md) 的安全启动篇强关联；
- 29 与 27 的等级映射（认证角色→解锁等级）是 OEM 诊断安全规范的核心条目，CDD 中两套机制都要登记。

## 易错点与陷阱

1. **现象：以为 29 全面替代 27，老件上发 29 报 0x11。原因：14229-1:2020 之前的服务实现没有 29。对策：先读 CDD 确认支持性，量产排障默认从 27 开始**；
2. **现象：验证总在 proveIdentity 失败（0x35）。原因：证书过期、不在有效期（ECU 时间错乱）、证书链不完整。对策：先 sendTime 对时，核对证书链与 ECU 时钟源**；
3. **现象：认证成功但 2E 仍 0x33。原因：角色映射没配置或角色权限不含该操作。对策：查 29 角色→安全等级映射表，确认证书角色串**；
4. **现象：挑战值复用第二次认证被拒。原因：挑战必须一次性使用，重放即拒——正是设计目标。对策：每次认证完整走 getChallenge→proveIdentity**；
5. **现象：验签耗时长，诊断仪超时。原因：软实现 ECC 验签上百毫秒级。对策：启用硬件加密单元，诊断仪按 P2\*/0x78 处理长响应**。

## 面试高频题

**Q1：为什么 2020 版要加 29？**
答：27 的 seed-key 静态、可重放、密钥全车型共享，无法支撑 OTA/远程诊断的安全要求；29 用证书+非对称签名+随机挑战补齐身份认证强度。

**Q2：29 的核心流程是什么？**
答：挑战-应答：ECU 出随机 challenge，诊断仪用私钥签名（proveIdentity），ECU 用证书公钥验签+校验证书链，按证书角色授予权限。

**Q3：29 和 27 怎么选？**
答：传统物理接触的产线/售后：27 足够且成本低；OTA/远程诊断/有 PKI 的新平台：29（可并存，29 认证后映射 27 的解锁等级）。

**Q4：29 有尝试限制吗？**
答：有：与 27 同族——验签失败 0x35、超次 0x36、延时 0x37，防暴力尝试。
