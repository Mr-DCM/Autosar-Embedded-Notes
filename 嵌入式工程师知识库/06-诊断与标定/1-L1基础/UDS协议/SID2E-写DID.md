# SID2E-写DID

> 一句话定位：22 的镜像但门槛翻倍——一次只许写一个 DID，且要过"会话→安全→前置例程→运行条件"四级检查链，写完何时生效（立即/复位后）取决于 NvM 与 DID 策略。
> 等级：L2 ｜ 前置：[SID22-读DID](SID22-读DID.md)

## 原理

### 为什么写比读难：写条件链

写 DID 会改变 ECU 行为，所以请求在 Dcm 里要过一条裁决链，任何一级不过即拒：

```plantuml
@startuml
autonumber on
participant "诊断仪" as TESTER
participant "Dcm (ECU)" as ECU

TESTER -> ECU : 2E F1 87 + 数据
note right of ECU : ① 会话检查：扩展/编程？\n不过 → 7F 2E 7F/7E
note right of ECU : ② 安全检查：已解锁到要求等级？\n不过 → 7F 2E 33
note right of ECU : ③ 前置例程：\n（如要求先跑过 31 自检）不过 → 7F 2E 22
note right of ECU : ④ 长度/范围/校验和：\n数据非法 → 7F 2E 31/13
ECU -> ECU : ⑤ NvM 写入 + 回调通知应用
alt 全链通过
  ECU --> TESTER : 6E F1 87（正响应）
else NvM 写失败
  ECU --> TESTER : 7F 2E 72（generalProgrammingFailure）
end
@enduml
```

读侧只有 ①②；写侧多出 ③④⑤。**NRC 0x72（generalProgrammingFailure）是写侧专属高频码**：NvM 写爆、EEPROM 忙、范围校验失败都可能归到它。

### 写后生效时机：立即 vs 复位后

| 策略 | 含义 | 典型 DID | 工程注意 |
|---|---|---|---|
| 立即生效 | 写入即更新 RAM 运行值（NvM 异步落盘） | 部分控制参数、标定短值 | 回读 22 立刻看到新值 |
| 复位后生效 | 只写 NvM，运行值不变，等 11 复位重载 | 配置字、编码（coding）、VIN 锁定 | 诊断脚本要跟一条 11 01，否则"写了没反应" |

CDD 里每个 DID 标注生效策略。**产线最经典的误解："2E 回了 6E 但行为没变"——不是没写进去，是策略为复位后生效**。

### 与 NvM 的一句话关联

写路径的落点是 **NvM_WriteBlock（写 DID 对应的 NvM 块）**，立即写 RAM+异步落盘，或仅排队由应用择机提交；6E 正响应在"NvM 接受写入"后发出——**掉电窗口**（写过程断电）靠 NvM 的 CRC/冗余机制兜底，诊断层不重复保护。

## 详解

### 报文格式逐字节

**请求（单 DID）：**

| 字节 | 值 | 含义 |
|---|---|---|
| 1 | 0x2E | SID：WriteDataByIdentifier |
| 2~3 | 0xF187 | 目标 DID（一条请求仅一个） |
| 4~n | 数据 | 长度/格式按 CDD，通常附校验（如 XOR） |

**正响应：** `6E F1 87`——只有 3 字节，回显 SID+0x40 与 DID，不带数据。

**负响应 `7F 2E NRC` 高频表：**

| NRC | 场景 | 排障方向 |
|---|---|---|
| 0x13 | 长度与 CDD 定义不符 | 数据多打/少打一个字节 |
| 0x22 | 运行条件不满足 | 车速≠0、档位不在 P、温度超限等写保护条件 |
| 0x31 | DID 不存在/数据超范围 | DID 未配置或数值越界（范围校验失败） |
| 0x33 | 未解锁 | 先 10 03 → 27 解锁 |
| 0x72 | 写入失败 | NvM/EEPROM 故障、写回调内部错误 |
| 0x7E/0x7F | 会话不支持 | 写操作几乎都要求扩展/编程会话 |

### 写大 DID：2E 也会用上多帧

写 VIN（17 字节）等长数据时请求超过 8 字节，由 CanTp 多帧承载——2E 本身不限制长度，限制来自 Dcm 缓冲与 NvM 块大小。相关时序见 05 区传输层笔记。

### 写编码（coding）的标准动作

改 ECU 配置编码的完整产线动作：`10 03 → 27 01/02 → 2E <codingDID> → 22 <codingDID>（回读校验）→ 11 01（如为复位生效）`——把这条链背下来，半数"写不进去"的现场都能对号入座。

## 配置层

- Dcm 中 DID 行的写侧属性：**Write 支持标志、写回调（`DspDataWriteFunction`）、所属会话/安全、生效策略**——与读回调同一行配置，见 [Dcm配置](../../2-L2进阶/Dcm配置/README.md)；
- DID 与 NvM 块的映射在 RTE/应用层声明：一个 NvM 块可承载多个 DID（打包），也要防"一次 2E 只更新块的一半字段"导致旧数据回写覆盖——详见 [DID与RID设计](../../2-L2进阶/DID与RID设计/README.md)；
- 量产件的写保护（一次性 VIN 锁定、变体编码次数限制）是 OEM 需求，落在写回调的条件检查里，CDD 同步标注。

## 易错点与陷阱

1. **现象：6E 成功但 ECU 行为没变。原因：DID 策略是复位后生效。对策：跟 11 01 复位，或查 CDD 生效标注**；
2. **现象：一条 2E 想写两个 DID 报 0x13。原因：2E 标准不支持多 DID，多余字节被判长度错。对策：拆成多条 2E，各写各的**；
3. **现象：写 VIN 报 0x72 且偶发。原因：NvM 写在排队时被掉电/复位打断，或 EEPROM 磨损。对策：写后立即 22 回读校验；产线对写失败有重试与坏块统计**；
4. **现象：回读 22 与写入值不一致。原因：写回调做了范围钳制（clamp）或编码转换。对策：读回调与写回调的转换规则必须互逆，CDD 标注缩放**；
5. **现象：多 ECU 产线写同一配置字，有的成功有的 0x22。原因：各 ECU 写条件（车速/温度）阈值不同。对策：产线脚本按 ECU 清单分别核对写前置条件**；
6. **现象：解锁后写仍 0x33。原因：该 DID 要求更高安全等级。对策：CDD 里查 Security Row，逐级 27**。

## 面试高频题

**Q1：2E 和 22 在报文层的最大差别？**
答：2E 一次只能写一个 DID，正响应仅回显 `6E+DID` 不带数据；22 可多 DID 串联，正响应带全部数据。

**Q2：写条件链有哪几级？对应哪些 NRC？**
答：会话（0x7E/0x7F）→ 安全（0x33）→ 前置例程/条件（0x22）→ 长度与范围（0x13/0x31）→ NvM 写入失败（0x72）。

**Q3：写后生效的两种策略？**
答：立即生效（写 RAM 运行值）与复位后生效（只落 NvM，11 重启加载）——由 CDD 按 DID 标注。

**Q4：0x72 通常意味着什么？**
答：generalProgrammingFailure：NvM/存储器写入失败或写回调内部错误，写侧最需要与应用/存储团队联合排查的 NRC。
