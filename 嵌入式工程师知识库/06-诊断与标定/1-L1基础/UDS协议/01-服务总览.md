# 01-服务总览

> 一句话定位：把 ISO 14229 定义的 26 个服务按"分组职责"铺成一张地图——会话/数据/存储/传输/例程各司其职，请求与正负响应三种报文格式一眼可辨，之后读任何单服务笔记都只需"回图查位"。
> 等级：L1 ｜ 前置：[01-从诊断仪的一次连接说起-诊断全景](../../00-入门导读/01-从诊断仪的一次连接说起-诊断全景.md)

## 原理

### 三种报文格式：UDS 的"普通话"

诊断仪发什么、ECU 怎么答，14229 只规定了三种腔调：

| 类型 | 格式 | 示例（以 0x22 读 DID 为例） |
|---|---|---|
| 请求 | `SID + 参数` | `22 F1 90` |
| 正响应 | `SID+0x40 + 参数` | `62 F1 90 + 数据` |
| 负响应 | `7F + SID + NRC` | `7F 22 31`（请求超出范围） |

记住两个换算：**正响应 = SID + 0x40**（10→50、22→62、2E→6E、27→67），**负响应永远以 7F 开头**，第三字节 NRC 是 ECU 给你的"拒绝理由条"。有 7F 回来恰恰说明 Dcm 活着，真正的异常是超时无响应。

### SID 分组一览表

按"这组服务管什么"分成七组，比背 26 个数字快得多：

| 分组 | SID（十进制/十六进制） | 职责直觉 | 本区笔记 |
|---|---|---|---|
| 会话控制 | 10 DiagnosticSessionControl | 换权限档位：默认/扩展/编程 | [SID10](SID10-会话控制.md) |
| 会话控制 | 11 ECUReset | 让 ECU 重启，复位后回默认会话 | [SID11](SID11-ECU复位.md) |
| 安全控制 | 27 SecurityAccess | seed-key 验身份，解锁写权限 | [SID27](SID27-安全访问.md) |
| 安全控制 | 29 Authentication | 2020 版新增：证书级认证 | [SID29](SID29-认证.md) |
| 数据传输 | 22 ReadDataByIdentifier | 按 DID 号读数据（版本号、标定值） | [SID22](SID22-读DID.md) |
| 数据传输 | 2E WriteDataByIdentifier | 按 DID 号写数据（写 VIN、配置字） | [SID2E](SID2E-写DID.md) |
| 存储管理 | 14 ClearDiagnosticInformation | 清 DTC（按组/单个/全清） | [SID14](SID14-清DTC.md) |
| 存储管理 | 19 ReadDTCInformation | 读 DTC（数量/状态/快照/扩展） | [SID19](SID19-读DTC.md) |
| 例程控制 | 31 RoutineControl | 有输入有输出的"动作"（自检/擦除） | [SID31](SID31-例程控制.md) |
| 通讯控制 | 28 CommunicationControl | 开关报文发送（刷写前静默总线） | 见 SID34-37 篇 |
| 通讯控制 | 3E TesterPresent | 保活：阻止 S3 超时跌会话 | 见 SID10 篇 |
| 传输下载 | 34/35/36/37 | 请求下载/上传/传数据/传出口 | [SID34-37](SID34-37-刷写下载.md) |
| 输入输出 | 2F InputOutputControlByIdentifier | 直接控 IO（点灯、风扇占空比） | 了解即可，工程常用 31 替代 |
| 通讯控制 | 85 ControlDTCSetting | 冻结/恢复 DTC 记账 | 见 SID34-37 篇 |
| 链路控制 | 83/84/85 等 | 按 DID 控制链路、周期响应 | 按需查阅 14229-1 表 C.1 |

使用频率天差地别：产线与售后八成流量落在 **10/27/22/2E/19/14/31** 七个服务上——这也是本区"每服务一档"优先覆盖的七篇。

### 子功能与抑制位 0x80

带子功能的服务（10/11/27/19/28/29/3E/85 等）请求第二字节是"子功能字节"：

- 低 7 位（bit0~bit6）：子功能号，如 `10 03` 的 03 = 扩展会话；
- 最高位 bit7（0x80）：**抑制正响应位（SPRM）**。置 1 时 ECU 执行动作但不回正响应——`3E 80` 是"静默保活"的经典用法：既撑住 S3 计时器，又不占用总线应答。

工程直觉：需要确认结果的操作（27 解锁、10 切会话）不要抑制；高频心跳类（3E）一律带 0x80。

### 会话-安全矩阵

每个服务/DID/RID 在 ECU 里都登记了两张权限表：

| 维度 | 取值 | 决定什么 |
|---|---|---|
| 会话支持 | default / extended / programming | 该服务/数据在哪些会话**可用** |
| 安全等级 | level 0（锁）/ level 1..N（已解锁） | 该服务/数据需要**解锁到几级** |

一个 2E 写 DID 能否成功，按"会话是否支持 → 安全等级是否达到 → 条件是否满足"逐级裁决，失败分别吐 NRC 0x7E/0x7F、0x33、0x22。这张矩阵在 CDD/ODX 与 Dcm 配置里是同一份信息的两份拷贝，两边不一致是产线排障高发点（详见 [Dcm配置](../../2-L2进阶/Dcm配置/README.md)）。

## 详解

### 一次典型交互的全景

```plantuml
@startuml
autonumber on
participant "诊断仪" as TESTER
participant "ECU\n(Dcm)" as ECU

TESTER -> ECU : 10 03（切扩展会话）
ECU --> TESTER : 50 03 00 32 01 F4（正响应，含 P2/P2*server 时间参数）
TESTER -> ECU : 27 01（请求种子）
ECU --> TESTER : 67 01 <seed>
TESTER -> ECU : 27 02 <key>
ECU --> TESTER : 67 02（解锁成功）
TESTER -> ECU : 22 F1 90（读版本号 DID）
ECU --> TESTER : 62 F1 90 "V1.2.3"（正响应）
TESTER -> ECU : 2E F1 87 <配置值>（写 DID，条件不满足）
ECU --> TESTER : 7F 2E 22（负响应：conditionsNotCorrect）
@enduml
```

### 高频 NRC 速查

| NRC | 名称 | 一句话场景 |
|---|---|---|
| 0x11/0x12 | 服务/子功能不支持 | 该 ECU 没实现这个 SID，或 CDD 与 Dcm 配置不一致 |
| 0x13 | 长度或格式错误 | 多打/少打一个字节，诊断仪模板用错 |
| 0x14 | 响应超长 | 多 DID 一次读，拼出来的响应超了缓冲区 |
| 0x22 | 条件不满足 | 车速不为 0、会话不对、前置例程没跑 |
| 0x24 | 请求序列错误 | 27 的偶数子功能没跟在奇数后面直接发 key |
| 0x31 | 请求超出范围 | DID/RID 不存在——十有八九路由表漏配 |
| 0x33 | 安全拒绝 | 忘了先走 27，或 key 算法两边不一致 |
| 0x72 | 一般编程失败 | 2E 写 NvM 失败、31 例程执行失败 |
| 0x7E/0x7F | 当前会话不支持该子功能/服务 | 在默认会话里发了只有扩展会话支持的东西 |

## 易错点与陷阱

1. **现象：正响应第一字节认不出来。原因：忘了 SID+0x40 换算。对策：22→62、2E→6E、31→71、34→74，把换算表贴在抓包工具旁边**；
2. **现象：`3E 00` 每秒一条把总线刷满。原因：没加抑制位。对策：保活用 `3E 80`，只有首次握手或排障时才用 `3E 00` 要确认**；
3. **现象：同一请求在 A 车型有响应、B 车型 0x7F。原因：服务支持矩阵是每 ECU 每项目独立配置的。对策：查目标 ECU 的 CDD，别拿别的车型经验套**；
4. **现象：诊断仪显示解锁成功但 2E 仍报 0x33。原因：该 DID 要求更高安全等级（level 2），27 只解了 level 1。对策：CDD 里核对该 DID 的 Security Row**；
5. **现象：把 0x11（服务不支持）当成了 ECU 复位 SID 11。原因：NRC 与 SID 编号空间撞号。对策：看到 7F 开头先按"NRC 三段式"读，7F 后第二字节才是被拒的 SID**。

## 面试高频题

**Q1：正响应和负响应的格式分别是什么？**
答：正响应 `SID+0x40` 起头带参数；负响应固定三段式 `7F + 被拒 SID + NRC`。

**Q2：子功能字节的 bit7 是干什么的？**
答：抑制正响应位（0x80）。置 1 时 ECU 执行但不回正响应，典型用法是 `3E 80` 静默保活，避免心跳报文占带宽。

**Q3：UDS 服务怎么按职责分组记忆？**
答：会话与安全（10/11/27/29）管权限；数据传输（22/2E）管数据读写；存储（14/19）管故障账本；例程（31）管动作；通讯控制（28/3E/85）管总线行为；上传下载（34~37）管刷写。

**Q4：会话-安全矩阵是什么？**
答：每个服务/DID/RID 在 ECU 内登记"支持哪些会话 + 需要哪级安全解锁"的两维权限表，Dcm 按它逐级裁决请求，对应 0x7E/0x7F 与 0x33 两类拒绝。
