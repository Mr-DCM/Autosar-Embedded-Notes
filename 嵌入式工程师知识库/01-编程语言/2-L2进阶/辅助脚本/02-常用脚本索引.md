# 常用提效脚本索引

> 一句话定位：值得沉淀成个人工具箱的 8 个脚本方向——每条给"用途 + 输入输出 + 核心片段"，用到时回来抄骨架，配合 [01-Python处理ARXML](01-Python处理ARXML.md) 的工具函数食用。
> 等级：L2 ｜ 前置：[01-Python处理ARXML](01-Python处理ARXML.md)

## 原理

共同套路：**输入是工程产物（arxml/dbc/map/日志/二进制），输出是一眼能看懂的表格或报告**。核心库全部 pip 可装或标准库自带，单个脚本控制在 100 行内，参数用 `argparse` 暴露。

## 代码示例/解读

### 1. ARXML 版本 diff（两版配置对比）

- 用途：改完配置后"工具里到底动了哪些参数"一图流，交接/回归评审利器。输入 `old.arxml new.arxml`，输出新增/删除/修改三类条目表。
- 核心片段（复用 [01 篇](01-Python处理ARXML.md) 工具函数，先拍平成字典再比对）：

```python
def flatten(root):                      # 拍平为 {(容器全路径, 参数名): 值}
    out = {}
    def walk(c, path):
        p = path + "/" + short_name(c)  # 全路径：各级 SHORT-NAME 拼接
        for e in c.iter():
            if local(e.tag) in PARAM_TAGS:
                out[(p, def_name(e))] = get_value(e)
        for s in c:                     # 递归子容器
            if s.tag.endswith('}ECUC-CONTAINER-VALUE'):
                walk(s, p)
    walk(next(e for e in root.iter() if e.tag.endswith('}ECUC-CONTAINER-VALUE')), "")
    return out
# changed = {k: (old[k], new[k]) for k in old & new if old[k] != new[k]}
```

### 2. DBC 解析（cantools 库）

- 用途：通信矩阵审查——报文/信号清单、周期、DLC 校验、矩阵导出。输入 `.dbc`，输出信号清单 CSV / Markdown 矩阵。核心库：`pip install cantools`。

```python
import cantools
db = cantools.load_file("matrix.dbc")
for msg in db.messages:
    print(f"{msg.frame_id:#06X} {msg.name} DLC={msg.length} 周期={msg.cycle_time}ms")
    for sig in msg.signals:
        print(f"  {sig.name}: {sig.start}+{sig.length}bit "
              f"factor={sig.scale} offset={sig.offset} unit={sig.unit or '-'}")
# 校验：sig.start+sig.length > msg.length*8 → 矩阵本身有错
# 解码：db.decode_message(msg.name, b'\x01\x02...')
```

### 3. map 文件解析（段统计与符号反查）

- 用途：RAM/flash 用量跟踪、栈空间确认、崩溃地址反查符号（配合 HardFault PC）。输入 `.map`（GCC；IAR/armclang 正则要改），输出段大小表 / `地址 → 最近符号`。核心库：`re`。

```python
import re, bisect
sym_re = re.compile(r"^([0-9a-fA-F]{8,16})\s+\S+\s+([0-9a-fA-Fx]+)\s+(\S+)$")
syms = [(int(m[1], 16), m[3]) for line in open("app.map")
        if (m := sym_re.match(line.strip()))]          # [(地址, 符号名)...]

def lookup(addr):                  # 崩溃地址反查：取 <= addr 的最大符号
    s = sorted(syms)
    i = bisect.bisect_right([a for a, _ in s], addr) - 1
    return f"{s[i][1]}+0x{addr - s[i][0]:X}" if i >= 0 else "?"
```

### 4. 日志时间戳分析（丢帧/超时检测）

- 用途：路试/HIL 日志自动找 CAN 丢帧、任务超时、周期抖动。输入带时间戳文本日志，输出超阈值报文名单与最大间隔。

```python
import re
from collections import defaultdict
ts_re = re.compile(r"^\[(\d+\.\d+)\]\s+RX\s+(\w+)")    # [123.456] RX BMS_Status
last, gaps = {}, defaultdict(list)
for line in open("run.log"):
    if m := ts_re.match(line):
        t, name = float(m[1]), m[2]
        if name in last:
            gaps[name].append(t - last[name])
        last[name] = t
for name, ds in sorted(gaps.items()):
    period = max(set(ds), key=ds.count)                 # 众数≈标称周期
    if max(ds) > period * 1.5:
        print(f"{name}: 疑似丢帧，最大间隔{max(ds)*1e3:.0f}ms（周期≈{period*1e3:.0f}ms）")
```

### 5. X-macro 生成 DID 表代码

- 用途：DID/IO 配置改在 Excel/CSV，一行命令重新生成 C 表与 CAPL/测试表，杜绝手工同步错。输入 `dids.csv`（名称,DID,长度,属性），输出 `Did_Cfg.h`。

```python
import csv
rows = list(csv.DictReader(open("dids.csv", encoding="utf-8-sig")))
with open("Did_Cfg.h", "w", encoding="utf-8") as f:
    f.write("/* 自动生成，勿手改 */\n#define DID_LIST(X) \\\n")
    for r in rows:
        f.write(f"    X({r['名称']}, 0x{int(r['DID'],0):04X}, "
                f"{r['长度']}, DID_{r['属性']}) \\\n")
# C 侧：DID_LIST(X) 一处展开成枚举/表/断言，改 CSV 重新生成即可
```

### 6. CRC 工具

- 用途：标定块/E2E/刷写包校验——命令行随时算，和下位机对拍。输入任意二进制/十六进制串，输出 CRC32/CRC16-CCITT 值。

```python
import zlib
data = open("block.bin", "rb").read()
print(f"CRC32 = 0x{zlib.crc32(data) & 0xFFFFFFFF:08X}")

def crc16(buf, init=0xFFFF):        # CRC16-CCITT-FALSE，多项式 0x1021
    crc = init
    for b in buf:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc
```

### 7. CANoe CAPL 辅助生成

- 用途：从 DBC 批量生成 CAPL 骨架——`on message` 收包检查、发送函数、测试用例表。输入 `.dbc`，输出 `generated.can` 片段，拷进 CANoe 再精修。核心库：`cantools` + 模板字符串。

```python
tpl = "on message {msg_name}\n{{\n    {checks}\n}}\n"   # CAPL 骨架模板
out = []
for msg in db.messages:
    checks = "\n    ".join(
        f'if (this.{s.name} != expected) {{ testStepFail("{s.name}"); }}'
        for s in msg.signals[:3])
    out.append(tpl.format(msg_name=msg.name, checks=checks))
open("generated.can", "w").write("\n".join(out))  # 拷进 CANoe 再精修
```

### 8. BMHD / 启动头校验值计算

- 用途：MPC5xxx / S32K3 等带 Boot Mode Header（BMHD）的芯片，改完启动头（起始地址等）后重算校验，避免"地址对但 CRC 错 → 进不去 boot"。输入 BMHD 字段，输出填好 CRC 的二进制头。**字段布局与 CRC 覆盖范围以芯片参考手册 BMHD 章节为准，各家不同，别照抄。**

```python
import struct, zlib

def make_bmhd(start_addr):            # 伪代码骨架：布局仅为示意！
    # 典型：CRC32 覆盖"除 CRC 字段自身外"的头内容；0x5257=VALID 示例值
    body = struct.pack("<IIIIIII", 0x5257, start_addr, 0, 0, 0, 0, 0)
    crc = zlib.crc32(body) & 0xFFFFFFFF
    return struct.pack("<I", crc) + body   # 字段序/CRC 位置以手册为准
open("bmhd.bin", "wb").write(make_bmhd(0x1000000))
```

## 易错点与陷阱

1. **脚本输出当唯一真相**：CSV/报告是"评审辅助"，最终以工具（DaVinci/CANoe）里的实时配置为准——文件可能不是最新导出的。
2. **编码问题**：Windows 下读 CSV 用 `encoding="utf-8-sig"`、写报告给 Excel 用 `utf-8-sig`，否则中文列名乱码。
3. **格式漂移**：map 文件格式随工具链版本变化，正则写死易碎；解析失败要显式报错而不是静默出空表。
4. **CRC 参数搞错**：多项式/初值/异或值/字节序/覆盖范围任何一个不对都"值不对但像对的"，先拿芯片手册的示例值对拍。
5. **生成代码不声明来源**：X-macro/CAPL 生成物文件头一定写"自动生成，勿手改"，并让生成命令可追溯（脚本+输入文件入库）。

## 面试高频题

1. **你会为嵌入式项目准备哪些提效脚本？**
   答：按产物分类——配置（ARXML diff/导出）、通信（DBC 解析）、内存（map 分析）、测试（日志丢帧检测、CRC 对拍）、代码生成（DID 表 X-macro）、启动（BMHD 校验）。核心是"机器读工程产物，人只看结论表"。

2. **为什么 DID 表用代码生成而不是手写？**
   答：单一数据源（CSV）+ 生成器，改配置只改一处，枚举/表/CAPL 同步更新，杜绝"文档与代码两张皮"；配合版本管理可 diff、可回溯。

3. **HardFault 后只有崩溃地址，怎么反查出错的函数？**
   答：解析链接生成的 .map 文件提取（地址, 符号）表并排序，用二分查找取 ≤ 崩溃地址的最大符号，输出"符号名+偏移"（如 `App_FanCtrl+0x1A`）。注意 map 格式随工具链版本漂移，正则解析失败要显式报错而不是静默出空表；也可以配合 addr2line（ELF 带 -g 时）双路互证。
