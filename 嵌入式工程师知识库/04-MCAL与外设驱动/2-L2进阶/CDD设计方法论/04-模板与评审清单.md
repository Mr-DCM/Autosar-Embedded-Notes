# 04-模板与评审清单

> 一句话定位：把前三篇的规矩收成两件套——一份可以直接开新 CDD 项目的文件模板骨架，和一张 19 条、分四组的评审清单，每条都是"检查什么+为什么"。
> 等级：L2 ｜ 前置：[02-中断挂接规范](02-中断挂接规范.md) + [03-与BSW-OS集成](03-与BSW-OS集成.md)

## 机制详解

### 文件模板骨架总览

一个规范 CDD 的最小文件集（以 Cdd_Xxx 为例，复制改名即开工）：

| 文件 | 内容 | 稳定性 |
|---|---|---|
| Cdd_Xxx.h | 对外 API、类型、回调原型 | 相对稳定（接口冻结后少动） |
| Cdd_Xxx.c | 逻辑实现：状态机、MainFunction、ISR | 随需求演进 |
| Cdd_Xxx_Cfg.h | 全部可配参数宏（通道数/缓冲长/周期） | 配置项，平台相关 |
| Cdd_Xxx_Cfg.c | 配置表（结构体数组，可工具生成） | 每项目重生成 |
| Cdd_Xxx_Platform.h/.c | 双平台差异（寄存器路径/内联） | 平台子目录隔离 |
| Cdd_Xxx_Irq.h（或并入.c） | ISR 声明与中断号绑定 | 与 OS 配置对应 |

布局直觉：**接口 .h 冻结、配置 _Cfg 集中、平台差异隔离**——评审时"改动落在哪个文件"一眼可判性质。

### 模板代码骨架

```c
/* ============ Cdd_Xxx.h：对外只见语义 ============ */
#ifndef CDD_XXX_H
#define CDD_XXX_H
#include "Std_Types.h"

typedef enum { CDD_XXX_OK = 0, CDD_XXX_BUSY, CDD_XXX_NOT_INIT,
               CDD_XXX_PARAM, CDD_XXX_HW_ERR } Cdd_Xxx_RetType;

typedef void (*Cdd_Xxx_NotifyType)(uint8 ch, Cdd_Xxx_RetType result);

void            Cdd_Xxx_Init(void);
void            Cdd_Xxx_DeInit(void);
Cdd_Xxx_RetType Cdd_Xxx_Start(uint8 ch);
Cdd_Xxx_RetType Cdd_Xxx_Stop(uint8 ch);
Cdd_Xxx_RetType Cdd_Xxx_GetStatus(uint8 ch);
void            Cdd_Xxx_MainFunction_10ms(void);
void            Cdd_Xxx_RegisterNotify(uint8 ch, Cdd_Xxx_NotifyType cb);
#endif /* CDD_XXX_H */

/* ============ Cdd_Xxx_Cfg.h：全部可配参数 ============ */
#define CDD_XXX_CH_COUNT        (2u)     /* 通道/实例数 */
#define CDD_XXX_BUF_LEN         (64u)    /* 缓冲长度 */
#define CDD_XXX_IRQ_PRIO        (12u)    /* 中断优先级：见全工程优先级总表 */
#define CDD_XXX_IRQ_CAT         (2u)     /* 中断类别：1=Cat1 / 2=Cat2 */

/* ============ Cdd_Xxx.c：内部结构（节选） ============ */
#include "Cdd_Xxx.h"
#include "Cdd_Xxx_Cfg.h"
#include "Os.h"
#if (CDD_XXX_PLATFORM == CDD_XXX_PLATFORM_TC377)
#include "Cdd_Xxx_Tc377.h"
#else
#include "Cdd_Xxx_S32K.h"
#endif

/* ---- 内部类型与状态机 ---- */
typedef enum { XXX_UNINIT, XXX_IDLE, XXX_BUSY, XXX_ERROR } Cdd_Xxx_StateType;

typedef struct {
    Cdd_Xxx_StateType    state;
    uint8                ch;
    volatile boolean     evtDone;      /* ISR→MainFunction 的事实标志 */
    Cdd_Xxx_NotifyType   notify;       /* 完成回调（任务上下文调用） */
    uint32               errCnt;       /* 诊断计数 */
} Cdd_Xxx_ChCtxType;

/* ---- 模块级变量（走 MemMap 段） ---- */
#define CDD_XXX_START_SEC_VAR_POWER_ON_INIT
#include "Cdd_Xxx_MemMap.h"
static Cdd_Xxx_ChCtxType Cdd_Xxx_Ctx[CDD_XXX_CH_COUNT];
static boolean Cdd_Xxx_Initialized = FALSE;
#define CDD_XXX_STOP_SEC_VAR_POWER_ON_INIT
#include "Cdd_Xxx_MemMap.h"

/* ---- 中断（Cat2 样例） ---- */
ISR(Cdd_Xxx_Handler)
{
    /* 只做：清标志、置事实标志、激活任务 */
    Cdd_Xxx_Hw_ClearIrq(0u);
    Cdd_Xxx_Ctx[0u].evtDone = TRUE;
    (void)ActivateTask(Task_CddXxxProc);
}

/* ---- 周期主函数：非阻塞推进 ---- */
void Cdd_Xxx_MainFunction_10ms(void)
{
    uint8 i;
    if (Cdd_Xxx_Initialized != TRUE) { return; }
    for (i = 0u; i < CDD_XXX_CH_COUNT; i++) {
        if (Cdd_Xxx_Ctx[i].evtDone) {              /* ISR 报的事实 */
            Cdd_Xxx_Ctx[i].evtDone = FALSE;
            if (Cdd_Xxx_Ctx[i].notify != NULL_PTR) {
                Cdd_Xxx_Ctx[i].notify(i, CDD_XXX_OK);  /* 任务上下文回调 */
            }
        }
        /* 状态机推进/超时监控，禁止自旋等待 */
    }
}

/* ---- Init/DeInit：使能放最后 ---- */
void Cdd_Xxx_Init(void)
{
    uint8 i;
    for (i = 0u; i < CDD_XXX_CH_COUNT; i++) { /* 初始化上下文 */ }
    Cdd_Xxx_Hw_Init();                     /* 平台层：配寄存器 */
    Cdd_Xxx_Initialized = TRUE;
    Cdd_Xxx_Hw_EnableIrq();                /* 最后一步才开中断 */
}
```

### 评审清单：19 条，四组

用法：新 CDD 评审会过一遍，每条打钩或写整改意见；"检查什么"是动作，"为什么"是不做的代价。

**A 组：接口设计（5 条）**

1. 模块/文件/API 全部 `Cdd_` 前缀命名规范一致？——不一致则失去可辨识度，维护成本翻倍；
2. 对外头文件零寄存器概念（无平台头、无寄存器类型）？——泄漏实现细节会连坐上层，换平台全动；
3. SWC 只经 RTE 端口调用，无裸函数调用路径？——绕过 RTE 破坏分层与可替换性；
4. 集成形态唯一（BSW 模块式或 SWC 式，不双挂）？——双调度源会打架，行为不可预测；
5. 返回值/错误码枚举集中定义且覆盖 NOT_INIT/PARAM/BUSY/HW_ERR？——散落的错误码无法统一诊断与上报。

**B 组：中断安全（5 条）**

6. 每个中断四要素（号/类别/优先级/handler 名）登记且与 OS 配置一致？——名字或类别不符会导致跳错入口或未定义行为；
7. Cat1 里无任何 OS API 调用？——Cat1 不在 OS 上下文，调用即跑飞；
8. ISR 只做"清标志+置事实+激活任务"，无长循环/无日志？——长 ISR 阻塞其他中断，破坏全局实时性；
9. ISR 与任务共享变量 volatile+临界区/原子保护？——无保护则数据撕裂，偶发难复现；
10. 中断优先级落在 OS 允许区间且进了全工程优先级总表？——越界进保留区会让 OS 调度异常。

**C 组：资源与初始化（5 条）**

11. 资源清单完整（DMA 通道/中断号/GPIO/内存段）且与他 CDD 无冲突？——冲突在集成晚期爆发，定位极难；
12. Init 排在依赖（时钟/引脚/OS）就绪之后且登记进 EcuM/BswM 序列？——顺序错则寄存器写不进或偶发失效；
13. Init 内不开中断、使能是最后一步？——早开中断会写坏未就绪的数据结构；
14. Shutdown/DeInit 关中断+收资源两步完整？——带着活中断进低功耗会异常唤醒；
15. 跨核场景外设与中断归属唯一核、共享数据有屏障？——双核同写外设必错乱，且难复现。

**D 组：可测性与诊断（4 条）**

16. 提供 DET 检查点或参数校验（可编译关闭）？——无校验则错误带病扩散，问题浮现在远端；
17. 关键事件有诊断计数/状态可查（错误计数、最近错误码）？——现场问题无痕迹只能瞎猜；
18. 硬件访问有平台替换层，可在 PC 上做逻辑级单测？——逻辑混着寄存器则单测覆盖率上不去；
19. 模板文件齐全（.h/.c/_Cfg/平台层/MemMap），改动落点符合文件职责？——职责混乱的文件每次改动都是全文件回归。

## 配置要点（怎么用起来）

- **新立项**：复制模板目录 → 全局替换 Xxx → 过一遍 A 组清单再写第一行逻辑；
- **评审会**：19 条打印成表，逐条打钩，未过项写整改人与期限；
- **回归时**：任何改动先问"落在哪个文件"，配置变更评审 _Cfg、逻辑变更走 D 组、中断变更走 B 组；
- **度量**：CDD 行数、ISR 最大长度（静态估算）、MainFunction 最坏耗时——三件套进项目度量基线。

## 易错点与陷阱

1. **现象**：清单走过场，全钩但问题照出。**原因**：没有"为什么"的追问，评审变成仪式。**对策**：每条要求出示证据（配置片段/代码行/表格条目），不出示不算过。
2. **现象**：模板被项目魔改，第 3 个 CDD 已经面目全非。**原因**：模板没有版本与owner。**对策**：模板进版本库统一维护，项目级扩展走"提案+合入"。
3. **现象**：清单条目与实际代码两张皮。**原因**：清单不随规范更新（比如新增跨核条目）。**对策**：规范文档与清单同步改版，条目编号稳定不重排。
4. **现象**：ISR 长度超标但无人察觉。**原因**：无度量，评审靠感觉。**对策**：静态工具/代码走查估算最坏执行时间，超限必须在任务级消化。
5. **现象**：双平台各自复制修改后无法合流。**原因**：平台差异没进 _Platform 层，散在逻辑里。**对策**：差异集中隔离（模板 C 组文件），合流评审对 diff。

## 面试高频题

**Q1：一个规范的 CDD 最小文件集包含哪些文件？各自职责？**
答：Cdd_Xxx.h（对外 API/类型/回调原型，接口冻结后少动）、Cdd_Xxx.c（状态机/MainFunction/ISR 逻辑）、Cdd_Xxx_Cfg.h/.c（全部可配参数宏与配置表，每项目重生成）、Cdd_Xxx_Platform.h/.c（双平台寄存器差异隔离）、Cdd_Xxx_Irq.h（ISR 声明与中断号绑定）。布局三原则：接口 .h 冻结、配置 _Cfg 集中、平台差异隔离——评审时"改动落在哪个文件"一眼可判性质。

**Q2：CDD 评审清单怎么防止"走过场全打钩"？**
答：每条检查要求出示证据（配置片段/代码行/表格条目），不出示不算过；清单与规范文档同步改版、条目编号稳定不重排；配合度量基线（CDD 行数、ISR 最大长度静态估算、MainFunction 最坏耗时）让"超限"有数字依据而不是评审感觉；模板进版本库统一维护，项目级扩展走提案合入。

**Q3：CDD 模板里为什么变量要包 MemMap 段、回调要在任务上下文调用？**
答：MemMap 段（START/STOP_SEC_VAR_xxx）让链接器按 AUTOSAR 内存映射约定把变量精确落段（如 POWER_ON_INIT 段支持快速启动时跳过初始化），与全工程内存布局约定一致。回调限定任务上下文（MainFunction 里调）而不是 ISR 里直接调：避免上层回调以不可控长度阻塞中断，ISR 只置事实标志（evtDone），耗时处理留给任务级——中断延迟可预算。

**Q4：双平台（TC377/S32K）的 CDD 怎么组织才能合流不痛？**
答：平台差异全部收进 _Platform 层（寄存器路径/内联差异），逻辑层只调统一接口，条件编译按 CDD_XXX_PLATFORM 宏选平台头；禁止把 #if 散在逻辑里——否则两平台各自复制修改后无法合流。回归评审时对 _Platform 文件做 diff 审查即可覆盖差异面。
