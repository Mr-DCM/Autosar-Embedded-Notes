# 03-TC377-GTM

> 一句话定位：TC377 上所有 MCAL 定时器类模块（Pwm/Gpt/Icu）的硬件底座都是 GTM——MCAL Pwm 的每个通道最终落到某个 TOM/ATOM 通道上，时钟来自 CMU；本篇只讲"配置怎么落下去"，内部机制点到即止。
> 等级：L2→L3 ｜ 前置：[01-PWM原理](01-PWM原理.md)

## 太长不看

- **人话直觉**：GTM 是芯片里一个独立的"定时器大仓库"，MCAL Pwm 只是租了仓库里几个货架（TOM/ATOM 通道）摆自己的波形。
- **本篇解决**：EB tresos 里配的 Pwm 通道，落到 GTM 哪个通道、走哪条 CMU 时钟、怎么出到引脚——配置路径一条线；"不出波形"知道先查什么。
- **赶时间记住 3 条**：
  1. MCAL Pwm 通道 → GTM TOM/ATOM 通道的映射在**配置工具里定**，不是引脚天生固定的；
  2. **CMU 时钟频率 = 分辨率**：tick 100MHz 即 10ns 粒度，周期上限受通道计数器位宽约束；
  3. 无波形排查顺序：GTM 总时钟 → CMU 使能 → 通道映射 → 引脚输出映射（详见 [02 区 GTM 篇](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/01-GTM架构概览.md)）。

## 原理

### GTM 一屏图：只看和 PWM 相关的三块

GTM（Generic Timer Module）内部结构庞大（TOM/ATOM/TIM/ARU/CMU/MAP…），**深水区见 02 区专篇**：[01-GTM架构概览](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/01-GTM架构概览.md)、[02-TOM与ATOM](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/02-TOM与ATOM.md)、[03-与MCAL-Pwm的关系](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/03-与MCAL-Pwm的关系.md)。本篇只需这三块：

```plantuml
@startuml
title GTM 中与 MCAL Pwm 相关的最小视图
skinparam defaultFontName "Microsoft YaHei"
package "GTM" {
  [CMU\n时钟管理：产生固定频率时钟簇] as CMU
  package "TOM（16bit，普通 PWM 够用）" {
    [TOM 通道 0..7 × 多子模块]
  }
  package "ATOM（32bit，更精细/复杂场景）" {
    [ATOM 通道 0..7 × 多子模块]
  }
  [MAP\n输出映射：通道→引脚] as MAP
}
[MCAL Pwm\n逻辑通道] --> TOM 通道 0..7 × 多子模块
[MCAL Pwm\n逻辑通道] --> ATOM 通道 0..7 × 多子模块
CMU ..> TOM 通道 0..7 × 多子模块 : 提供计数时钟（定分辨率）
CMU ..> ATOM 通道 0..7 × 多子模块 : 提供计数时钟
TOM 通道 0..7 × 多子模块 --> MAP
ATOM 通道 0..7 × 多子模块 --> MAP
MAP --> [芯片引脚\n(Port 复用配合)] : 波形最终出口
@enduml
```

- **CMU（Clock Management Unit）**：把 GTM 总时钟分频成若干固定频率时钟（时钟簇），每个通道从簇里挑一个当 tick——**挑哪个频率，就定了这路 PWM 的分辨率和最大周期**；
- **TOM/ATOM**：真正产生波形的通道（16/32bit 计数器+比较值模型，就是 [01-PWM原理](01-PWM原理.md) 那张图的硬件化）；
- **MAP**：把 GTM 内部通道输出路由到物理引脚——所以"通道号"和"引脚号"在 TC377 上是两件事，中间隔着输出映射。

### CMU 时钟域与 PWM 分辨率：一道算术题

设 CMU 提供的通道时钟为 f_clk，通道计数器 N bit：

```text
分辨率（最小时间步长）= 1 / f_clk          例：100MHz → 10ns
最大周期 = 2^N × 分辨率                    例：16bit、100MHz → ≈655µs（约 1.5kHz 下限）
频率上限 = 1 / (2 × 分辨率)（至少高+低各一步）
```

这就是"为什么存在 CMU 配置项"：不同通道要不同分辨率/周期范围，一条时钟簇喂不饱所有人，所以做成可选。选型口诀：**分辨率不够→升时钟；周期不够→降时钟或换 32bit ATOM**。

### MCAL Pwm 通道的配置落点

在 EB tresos 里配一个 Pwm 通道，实际落下四层东西（每层都可能是"没波形"的凶手）：

| 层 | 配的是什么 | 出错现象 |
|---|---|---|
| GTM 总使能/全局时钟 | GTM 模块本身与总时钟 | 一切定时器全死 |
| CMU 时钟选择 | 通道用哪个固定频率时钟 | 频率不对/分辨率怪 |
| TOM/ATOM 通道分配 | 逻辑通道绑到哪个物理通道、周期/比较值 | 该路无波形，别路正常 |
| 输出映射+Port 复用 | 通道输出→哪个引脚 | 波形"在芯片里"就是出不来 |

### 死区在 TC377 上的现实

互补+死区需求（电机半桥）在 GTM 上不像 S32K FTM 那样有单一"死区开关"的直觉入口：要么用厂商 MCAL 提供的死区/互补相关参数（以你手头驱动版本手册为准），要么双通道错相手工构造，要么走 CCU6（英飞凌电机传统强项）。**评审时先问清楚用的是哪条路，别默认"配了就安全"**。

## 双平台硬件单元对照

| 通用概念 | TC377（本篇） | S32K（对照） |
|---|---|---|
| PWM 硬件 | GTM TOM（16bit）/ATOM（32bit） | eMIOS UC（OPWMB/OPWMCB）、FTM |
| 时钟体系 | CMU 固定频率时钟簇 | PCC 选源+分频，Master Bus 共享 |
| 通道-引脚关系 | 经 MAP 输出映射，灵活但多一层 | 基本固定对应 |
| 死区 | 驱动参数/双通道错相/CCU6（按项目路线） | FTM DTC 内建 |
| 分辨率来源 | CMU 时钟频率 | 时钟源频率 |
| 资源互斥 | TOM/ATOM/TIM 共享 GTM，Pwm/Gpt/Icu 统一规划 | eMIOS 通道互斥 |

## MCAL 配置要点

| 配置项 | 含义 | 典型值 | 易错点 |
|---|---|---|---|
| GTM 使能与总时钟 | 模块级开关与 fGTM | 由 Mcu/厂商配置 | 总开关没开，所有 GTM 模块（含 Gpt/Icu）集体沉默 |
| CMU 时钟簇选择 | 通道 tick 频率 | 100MHz 高分辨率档 | 选了低频档却要高频 PWM，频率上不去 |
| Pwm 通道→TOM/ATOM 分配 | 逻辑到物理通道 | 通道规划表统一分 | 撞了 Gpt/Icu 的通道，配置检查告警被无视 |
| 通道计数器位宽选择 | TOM 16bit / ATOM 32bit | 长周期用 ATOM | 低频+高分辨率需求塞给 16bit，周期溢出 |
| 周期/占空比（tick） | 波形参数 | 按 CMU 频率换算 | tick 频率理解错，频率偏差一倍 |
| 输出映射+Port 复用 | 通道→引脚两级路由 | 与原理图一致 | 映射到另一颗脚，示波器守错了位置 |
| 通知 | 周期/边沿中断（GTM 中断节点） | 采样同步 | 中断优先级/核分配没配（多核下路由错核） |

## 代码示例

```c
/* 应用层依旧是标准 API，GTM 细节全部被映射层吃掉 */
void App_BacklightRamp(uint8 targetPercent)
{
    /* 背光渐亮：步进改占空比，影子寄存器保证每步在下个周期边界无缝生效 */
    static uint8 cur = 0u;
    uint16 duty;

    if (targetPercent > cur) { cur++; } else if (targetPercent < cur) { cur--; }
    duty = (uint16)(((uint32)cur * 0x8000u) / 100u);   /* 0~0x8000 满量程 */

    Pwm_SetDutyCycle(PwmConf_PwmChannel_Backlight, duty);
}

void App_BacklightSafeOff(void)
{
    /* 故障路径：直接切空闲态，不依赖占空比归零的渐变过程 */
    Pwm_SetOutputToIdle(PwmConf_PwmChannel_Backlight);
}
```

## 易错点与陷阱

1. **所有定时器类功能集体沉默**——现象：Pwm/Gpt/Icu 全不工作。原因：GTM 模块级使能或总时钟没配（fGTM 未开，见 [03-外设时钟门控](../../../02-芯片与体系结构/2-L2进阶/TC377平台/时钟系统/03-外设时钟门控.md)）。对策：先查模块级，再查单通道。
2. **单路无波形**——现象：别的通道都好，就这路死。原因：通道映射或输出映射错（信号在 GTM 里有了，没到引脚）。对策：按"通道分配→输出映射→Port 复用"三层逐层确认；条件允许用另一路已验证的引脚交叉验证。
3. **频率偏差一倍**——现象：示波器量出 2×或 0.5× 目标。原因：CMU 时钟档理解错/周期参数单位混淆。对策：用"分辨率=1/f_clk"现场换算，别凭感觉填数。
4. **低频 PWM 出不来**——现象：100Hz 怎么配都不对。原因：高频 CMU 时钟下 16bit TOM 周期不够长。对策：换低频时钟档或 ATOM 32bit（先算 `2^N ÷ f_clk`）。
5. **通道撞车**——现象：新加 Pwm 通道后某 Gpt 节拍消失。原因：TOM/ATOM/TIM 同属 GTM 资源池，跨模块占用冲突。对策：维护全芯片 GTM 通道规划表，配置工具资源检查告警必须清零。
6. **通知进了错误的核**——现象：多核工程里回调偶发"不进"。原因：GTM 中断节点路由的核与使能通知的核不一致（见 [02-IR路由与多核分配](../../../02-芯片与体系结构/2-L2进阶/TC377平台/中断系统/02-IR路由与多核分配.md)）。对策：中断路由配置与软件 owner 核对齐。

## 面试高频题

1. **MCAL Pwm 通道和 GTM 通道是什么关系？**
   答：逻辑通道经配置映射到 TOM/ATOM 物理通道+CMU 时钟+输出映射+引脚复用；映射是配置出来的，不是引脚固定的。
2. **CMU 时钟为什么做成多簇可选？**
   答：不同通道需要不同分辨率/周期范围，一条频率无法同时满足"高分辨率"与"长周期"；簇是这组矛盾的解。
3. **怎么估一路 PWM 能配的频率范围？**
   答：上限=分辨率倒数量级（至少高/低各一步），下限=计数器位宽×分辨率；动手先算这道算术。
4. **TC377 上 Pwm/Gpt/Icu 为什么要统一做通道规划？**
   答：三者底层共享 GTM 资源池，配置期不规划，集成期必撞车。
