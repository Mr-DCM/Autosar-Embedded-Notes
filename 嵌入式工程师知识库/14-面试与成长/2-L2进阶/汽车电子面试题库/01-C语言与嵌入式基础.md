## 基础题（8 题——挂了直接出局）

**Q：static 关键字有哪几种用法？**

答：三种——

- 修饰**局部变量**：生存期提升到整个程序（放 .data/.bss），作用域不变，函数重入时值保留；
- 修饰**全局变量**：链接属性从 external 收成 internal，仅本编译单元可见；
- 修饰**函数**：同理只在本文件可见，避免命名冲突。

驱动工程里最常见的是后两种：模块内部函数全部 static，头文件只暴露接口，天然形成"黑盒 + 契约"的分层。

出处：[关键字与存储类](../../../01-编程语言/1-L1基础/基础语法巩固/01-关键字与存储类.md)

**Q：volatile 是干什么的？哪些场景必须加？**

答：告诉编译器"该对象可能被程序控制流之外的因素修改"，每次访问必须真读真写内存，禁止缓存到寄存器、合并或消除访问。

三个必加场景：①内存映射的外设寄存器（状态会被硬件改）；②中断服务程序与主循环共享的标志变量；③多核/DMA 共享的内存。

经典反例：`while (!ready);` 不加 volatile 会被优化成"读一次 + 死循环"——开优化就死机的头号病根。

出处：[volatile 的正确使用](../../../01-编程语言/2-L2进阶/寄存器编程/01-volatile的正确使用.md)

**Q：`const int *p`、`int * const p`、`const int * const p` 分别是什么意思？**

答：口诀"const 靠近谁，谁不能变"：

| 声明 | 数据可改 | 指针可改向 |
|---|---|---|
| `const int *p` | 否 | 是 |
| `int * const p` | 是 | 否 |
| `const int * const p` | 否 | 否 |

API 入参 const 化是 MISRA 与代码评审的基本功——`SendData(const uint8_t *buf, uint16_t len)` 一眼承诺"发送函数不改你的数据"。

出处：[const 与 volatile 指针](../../../01-编程语言/1-L1基础/指针专题/04-const与volatile指针.md)

**Q：数组和指针有什么区别？**

答：数组是一块连续内存实体，指针是一个存地址的变量。四个可观测差异：

- `sizeof(arr)` 得整块大小，`sizeof(p)` 得指针宽度；
- 数组名在多数表达式中退化为首地址指针（例外：sizeof、& 两个场合）；
- 作函数形参时 `int a[]` 退化成 `int *a`，函数内拿不到长度——长度必须另传；
- `&arr + 1` 跨整个数组，`&a[0] + 1` 只跨一个元素。

分不清的根源是把"数组名退化"当成了"数组就是指针"。

出处：[指针与数组](../../../01-编程语言/1-L1基础/指针专题/01-指针与数组.md)

**Q：栈和堆的区别？**

答：一张表说清——

| 维度 | 栈 | 堆 |
|---|---|---|
| 分配方 | 编译器自动（函数栈帧） | 程序员 malloc/free |
| 速度 | 移动栈指针，纳秒级 | 搜索空闲块，会碎片化 |
| 大小 | 有限（RTOS 任务栈常 1~4KB） | 受 RAM 总量限制 |
| 典型事故 | 栈溢出、局部变量返回悬垂 | 泄漏、双重释放、野指针 |

汽车 MCU 项目普遍禁用堆：实时性不确定 + 碎片不可控。

出处：[栈与堆](../../../01-编程语言/2-L2进阶/内存管理/02-栈与堆.md)

**Q：`struct { char a; int b; short c; };` 的 sizeof 是多少？为什么？**

答：默认对齐（int 4 字节对齐）下是 **12**：a 占偏移 0；b 对齐到 4~7；c 落 8~9；尾部按最大成员 4 对齐补齐到 12。

存在填充的根因：CPU 访问对齐数据最快（一次总线事务），非对齐访问在 Cortex-M 上可能被支持但变慢，在 TriCore 等核上直接触发对齐 Trap。追问会引到 `__attribute__((packed))` 与 `#pragma pack` 的代价（见进阶 Q14）。

出处：[内存对齐与填充](../../../01-编程语言/2-L2进阶/内存管理/03-内存对齐与填充.md)

**Q：什么是大小端？工程上哪里会踩坑？**

答：大端（Big-Endian）：高位字节存低地址，符合人读数习惯；小端（Little-Endian）：低位字节存低地址。x86/ARM Cortex-M 默认小端，TriCore 也是小端，PowerPC 传统上大端——跨平台移植最容易翻车。

工程坑位：①CAN 信号在 DBC 里分 Motorola（大端式排布）与 Intel（小端式排布），错用则解析值完全错；②诊断 DID 多字节数据必须按 ODX/CDD 约定字节序；③结构体直接强转 char* 发送到总线上时，对端解析顺序取决于本机端序——所以协议字段必须显式移位拼装。判断代码见区分度 Q16。

出处：[内存对齐与填充](../../../01-编程语言/2-L2进阶/内存管理/03-内存对齐与填充.md)、[命名与字节序规范](../../../06-诊断与标定/2-L2进阶/DID与RID设计/01-命名与字节序规范.md)

**Q：中断服务函数（ISR）里为什么不能调 printf/malloc/做浮点运算？**

答：四条理由：

- printf/malloc 内部可能持锁或长耗时，中断上下文里"阻塞"等于死锁或丢实时性；
- malloc 加长中断执行时间，把更低优先级中断全堵住；
- 浮点运算要保存 FPU 上下文，ISR 框架通常不保存，返回后 FPU 寄存器被污染；
- MISRA 与车厂规范直接禁止在 1 类/2 类 ISR 里调用非重入函数。

正确姿势：ISR 只置标志、写缓冲、给信号量，处理丢给任务——"顶半底半"分工。

出处：[ISR 与任务交互](../../../08-操作系统/1-L1基础/RTOS通用原理/中断管理/03-ISR与任务交互.md)

## 进阶题（7 题——拉开差距）

**Q：位域和位操作，汽车代码里为什么偏爱后者？**

答：位域（bitfield）的内存排布、跨字节顺序、成员符号性都由编译器实现决定，C 标准不保证——换编译器或平台后寄存器映射可能整个错位，这在"配置必须可复现"的汽车工程里是致命伤。

所以寄存器与协议字段统一用显式掩码位操作：`reg = (reg & ~MASK) | (val << POS);`——一次读改写、语义可见、可静态检查。位域只适合"不落硬件、纯内存"的结构压缩场景（如 RAM 紧张时打包标志位）。

出处：[位域 vs 位操作](../../../01-编程语言/1-L1基础/位操作/02-位域vs位操作.md)

**Q：`#define SQUARE(x) x*x` 有什么坑？怎么写才对？**

答：宏是文本替换，两个坑：

- `SQUARE(a+1)` 展开成 `a+1*a+1`——运算符优先级炸了；
- `SQUARE(i++)` 让 i 自增两次——副作用被双重求值。

正确写法：参数与整体都加括号 `#define SQUARE(x) ((x)*(x))`，且实参避免副作用。追问"为什么不用 inline 函数"——inline 有类型检查、无双重求值；宏仅存的优势是编译期拼接与泛型（如生成寄存器访问宏）。

出处：[预处理与宏](../../../01-编程语言/1-L1基础/基础语法巩固/02-预处理与宏.md)

**Q：函数指针怎么用？举一个你项目里的例子。**

答：三步走：

```c
typedef void (*CanRxCallback_t)(const uint8_t *data, uint8_t len); /* 1 定义类型 */
static CanRxCallback_t s_handlers[CAN_ID_MAX];                      /* 2 注册表 */
s_handlers[MSG_ENGINE] = EngineMsgHandler;                          /* 3 挂接 */
s_handlers[id](buf, len);                                           /*   分发调用 */
```

项目实例：CAN 驱动收包后按 ID 查表分发——回调替代巨型 switch，新增报文不改驱动代码。AUTOSAR 里全是同型机制：Com 的信号失效通知、NvM 的作业回调、EcuM 的唤醒回调，本质都是函数指针挂接。

出处：[函数指针与回调](../../../01-编程语言/1-L1基础/指针专题/03-函数指针与回调.md)

**Q：程序的内存五大区是什么？在 map 文件里分别对应哪段？**

答：①代码区 .text（ROM，常量 .rodata 也在 ROM）；②已初始化数据区 .data（初值存 ROM，启动时拷到 RAM）；③未初始化数据区 .bss（启动时清零，不占 ROM）；④堆 heap（动态分配，MCU 工程常裁掉）；⑤栈 stack（局部变量与函数调用）。

map 文件能直接看到各段地址与大小，是查"RAM 为什么爆了""全局变量初值为什么丢了（.data 拷贝没跑）"的第一现场。

出处：[五大内存区](../../../01-编程语言/2-L2进阶/内存管理/01-五大内存区.md)、[map 文件分析](../../../10-工具链与工程化/2-L2进阶/编译器/03-map文件分析.md)

**Q：volatile 能保证原子性吗？不能的话怎么解决？**

答：**不能**。volatile 只禁止编译器优化访问，管不了指令级原子性——`count++` 是"读-改-写"三步，任何一步都可能被中断打断，两个上下文各加一次可能丢一次更新。

解决方案按代价排序：

- 单核：短暂关中断（SuspendAllInterrupts / EnterCritical）；
- 体系原语：TriCore 的原子交换/位操作指令，或 LDREX/STREX 型独占访问；
- 标志类：单写多读的 `volatile uint8_t` 天然单字节原子；
- 任务上下文：OS 互斥量（注意别在中断里用会阻塞的锁）。

出处：[volatile 的正确使用](../../../01-编程语言/2-L2进阶/寄存器编程/01-volatile的正确使用.md)、[临界区](../../../08-操作系统/1-L1基础/RTOS通用原理/中断管理/02-临界区.md)

**Q：#pragma pack(1) 有什么代价？什么时候不得不用？**

答：压缩对齐省 RAM、让结构体与线上报文字节一一对应；代价是：①非对齐成员访问变慢（总线拆成两次）；②某些核（TriCore、部分老 ARM）非对齐访问直接触发异常；③对齐相关的原子性更难保证。

取舍口径：**协议解析层**（必须按字节布局）用 pack(1) + memcpy 进出缓冲；**内部数据结构**保持自然对齐；绝对禁止"pack 结构体指针直接强转访问非对齐成员"。

出处：[内存对齐与填充](../../../01-编程语言/2-L2进阶/内存管理/03-内存对齐与填充.md)

**Q：MISRA C 为什么在车厂是硬要求？你了解哪几类规则？**

答：车载软件的安全等级（ISO 26262）要求代码可预测、可静态检查、可审计——MISRA 把"容易写错的 C 特性"圈出来禁止或限制。

规则三类：**强制**（Mandatory，如禁用 setjmp/longjmp）、**必须**（Required，如禁用 malloc，偏离需书面许可与评审）、**建议**（Advisory）。高频条目：禁递归、指针运算受限、禁隐式转换、switch 必有 default、函数单一出口、不用魔数。工程上用 Polyspace/Cppcheck 等静态分析工具在 CI 卡关。

出处：[MISRA-C 规则分类导读](../../../01-编程语言/2-L2进阶/代码规范与MISRA-C/02-MISRA-C规则分类导读.md)、[高频违规条目解析](../../../01-编程语言/2-L2进阶/代码规范与MISRA-C/03-高频违规条目解析.md)

## 区分度题（5 题——聊出深度）

**Q：手写一段代码判断当前机器是大端还是小端。**

答：两种写法——

```c
/* 指针法：看低地址放的是不是低字节 */
uint16_t x = 0x0102u;
uint8_t  *p = (uint8_t *)&x;
return (*p == 0x02u);              /* 真=小端 */

/* 联合体法：成员共享首地址 */
union { uint16_t u16; uint8_t u8[2]; } t;
t.u16 = 1u;
return (t.u8[0] == 1u);            /* 真=小端 */
```

加分点：说明"union 各成员从同一地址开始布局"是标准保证的，而位域排布不是——一句话把两题串起来。

出处：[指针与数组](../../../01-编程语言/1-L1基础/指针专题/01-指针与数组.md)、[指针常见笔试题](../../../01-编程语言/1-L1基础/指针专题/05-常见笔试题.md)

**Q：memcpy 遇到源和目标内存重叠会怎样？怎么办？**

答：C 标准规定 memcpy 的 src/dest 不得重叠，重叠即未定义行为——正向逐字节拷贝时，若 dest 落在 (src, src+n) 内，前面的写入会污染尚未读取的源数据。

正解是 memmove：先比较方向，dest 在后则从高往低倒着拷，保证先读后写。这题几乎必挂的点在于硬说"没问题"——手写与追问全解见 [memcpy 与 strcpy](../../1-L1基础/手写代码题/01-memcpy与strcpy.md)。

出处：[内存泄漏与越界排查](../../../01-编程语言/2-L2进阶/内存管理/06-内存泄漏与越界排查.md)

**Q：单生产者-单消费者的环形缓冲区为什么可以不加锁？**

答：三个前提成立时可以：

- 读写指针各只有一个写者：生产者只写 head、消费者只写 tail，自身无竞争；
- 指针声明 volatile 且为单字长——读写本身原子；
- 容量取 2 的幂，取模用位与，避免除法。

关键是双方只读对方指针、只写自己指针；数据与指针的更新顺序要"先写数据、后推进指针"（必要时加读写屏障），消费者看到新 head 时数据必然已就位。CAN 接收缓冲、Dlt 日志缓冲都是这个套路。

出处：[环形缓冲区](../../../01-编程语言/2-L2进阶/数据结构与算法-C实现/01-环形缓冲区.md)、[读写时序与屏障](../../../01-编程语言/2-L2进阶/寄存器编程/04-读写时序与屏障.md)

**Q：看这段代码有什么问题：`while (!dma_done); process();`，dma_done 在 DMA 中断里置位？**

答：dma_done 没加 volatile，编译器认为循环条件不变，把它优化成"读一次 + 死循环"，甚至整段折叠掉——开 -O2 后死机的经典病根。修法：`volatile boolean dma_done;`。

追问一层：即使加了 volatile，"标志 + 数据"组合还要考虑内存屏障——必须保证 DMA 写入的数据在中断置标志**之前**对主循环可见，否则标志到了数据还没到。

出处：[volatile 的正确使用](../../../01-编程语言/2-L2进阶/寄存器编程/01-volatile的正确使用.md)、[竞态排查](../../../08-操作系统/1-L1基础/RTOS通用原理/死锁与竞态分析/02-竞态排查.md)

**Q：为什么汽车 MCU 项目里普遍禁用 malloc/free？确有变长需求怎么办？**

答：三条死罪：①时间不确定——分配耗时取决于堆碎片状况，破坏实时性；②碎片化——长期运行后可能"总量够但连不成块"，分配失败且无法复现；③泄漏/双重释放难查，而车规软件一跑就是十年。

替代方案：全部静态分配（MISRA + 车厂规范）；确有变长需求用**静态内存池**（启动时一次分区、固定块大小、运行期零碎片），或 FreeRTOS heap_4 这类可裁剪方案；AUTOSAR 工程则由 MemMap/内存分区接管所有段布局。

出处：[malloc 原理与碎片](../../../01-编程语言/2-L2进阶/内存管理/04-malloc原理与碎片.md)、[AUTOSAR-MemMap 机制](../../../01-编程语言/2-L2进阶/内存管理/05-AUTOSAR-MemMap机制.md)
