## 基础题（8 题——驱动岗入门线）

**Q：MCAL 是什么？它在 AUTOSAR 里的位置？**

答：MCAL = Microcontroller Abstraction Layer，微控制器抽象层，AUTOSAR BSW 最底层：直接操作寄存器，向上给 ECU 抽象层提供标准化 API（Mcu/Port/Dio/Adc/Pwm/Gpt/Icu/Spi/Can/Lin/Fls/Fee/Wdg…）。价值：换芯片只换 MCAL 配置与供应商包，上层不动。

一句话人设：MCAL 工程师=懂 AUTOSAR 合同（SWS 接口）+ 懂芯片手册（寄存器）的双语者。

出处：[MCAL 分层位置](../../../04-MCAL与外设驱动/1-L1基础/MCAL总览/01-MCAL分层位置.md)、[MCAL 第一课](../../../04-MCAL与外设驱动/00-入门导读/01-MCAL第一课-从点灯到分层驱动.md)

**Q：MCAL、iLLD、RTD 是什么关系？**

答：都是"厂商给的底层软件"，身份不同：**MCAL** 是 AUTOSAR 标准接口的驱动（配置工具生成，计费授权）；**iLLD** 是英飞凌 TC3xx 的底层库（接口自由、贴近寄存器、示例友好）；**RTD** 是 NXP S32K 的实时驱动包（含 MCAL+基础驱动+示例）。工程现实：AUTOSAR 项目用 MCAL；快速原型/裸机练习直接用 iLLD/RTD。两者可以共存——CDD 里调 iLLD、对外包成 AUTOSAR 接口是常见打法。

出处：[MCAL vs iLLD vs RTD](../../../04-MCAL与外设驱动/1-L1基础/MCAL总览/02-MCAL-vs-iLLD-vs-RTD.md)

**Q：Port 和 Dio 两个模块怎么分工？**

答：**Port** 管"配置态"：引脚复用（ALT 功能）、方向、上下拉、驱动强度、开漏——初始化时一次性配好；**Dio** 管"运行态"：读写通道/端口/组（Dio_WriteChannel/ReadPort），不做任何配置。为什么拆开：配置与使用分离，运行时禁止改配置（防误用），也符合"静态配置"的车规口味。

出处：[Port 配置](../../../04-MCAL与外设驱动/1-L1基础/Port与Dio/01-Port配置.md)、[Dio 接口](../../../04-MCAL与外设驱动/1-L1基础/Port与Dio/02-Dio接口.md)

**Q：看门狗原理是什么？为什么要窗口型？**

答：计数器倒数，软件必须周期"喂狗"（重装），超时未喂→复位。普通狗只防"忘了喂"；**窗口型**还规定"不能早喂"——喂狗动作必须落在 [下限,上限] 窗口内，程序跑飞后空转狂喂同样被咬。车规再加一层 WdgM 监督（见 [05-操作系统与RTOS](05-操作系统与RTOS.md) 末题）。配置要点：窗口与喂狗任务的周期严格匹配，喂太勤/太懒都复位。

出处：[看门狗原理](../../../04-MCAL与外设驱动/2-L2进阶/Wdg/01-看门狗原理.md)

**Q：上拉电阻的作用？I2C 为什么必须上拉？**

答：上拉把悬空输入拉到确定电平（防浮空抖动）、OC/OD 输出靠它建立高电平。I2C 的 SDA/SCL 是开漏+线与结构：输出低=拉下，输出高=释放由上拉拉高——只有这样才能实现多从机"谁都可能拉低"的仲裁与时钟拉伸。阻值选型：太大边沿变慢（RC），太小灌电流超标，常见 2.2k~4.7k@3.3V/400kHz。

出处：[原理与作用](../../../03-硬件基础/1-L1基础/上拉下拉电阻/01-原理与作用.md)、[I2C 为何必须上拉](../../../03-硬件基础/1-L1基础/上拉下拉电阻/04-I2C为何必须上拉.md)

**Q：KL30 和 KL15 是什么？**

答：汽车电气网络命名的两根常电/点火线：**KL30** 接蓄电池正极（常电，睡眠时也要维持静态电流）；**KL15** 是点火开关 ON 档电（唤醒源之一）。ECU 供电架构：KL30 → 保护器件 → DCDC/LDO → 各路电源；KL15 检测电路做唤醒输入。睡眠电流预算（整车静态电流）就落在 KL30 这条链上——假醒/漏电问题都从这查起。

出处：[KL30-KL15 供电](../../../03-硬件基础/2-L2进阶/ECU硬件常识/01-KL30-KL15供电.md)、[唤醒电路](../../../03-硬件基础/2-L2进阶/ECU硬件常识/02-唤醒电路.md)

**Q：ADC 采样的完整链路是什么？采样时间为什么要和源阻抗匹配？**

答：链路：信号源 → 前端调理（分压/滤波/跟随器）→ 多路选择 → 采样保持电容充电 → SAR 逐次逼近 → 数据寄存器。采样时间内保持电容要充到目标精度——源阻抗越大、要求的分辨率越高，需要的采样时间越长；否则"充不满"，读数偏低且随上一次通道残留漂移。手册给"源阻抗 vs 采样时钟"对照表，超了就加运放跟随或延长采样窗口。

出处：[原理与转换链路](../../../04-MCAL与外设驱动/2-L2进阶/Adc/01-原理与转换链路.md)、[采样时间与源阻抗](../../../03-硬件基础/2-L2进阶/模拟电路/ADC采样原理/03-采样时间与源阻抗.md)

**Q：PWM 的占空比和频率怎么理解？死区是干什么的？**

答：频率=周期的倒数，决定"开关多快"；占空比=高电平时间占比，决定"平均输出"（电机速度、LED 亮度）。死区：半桥/全桥上下管切换瞬间，两管都关一小段时间，防直通短路——由硬件模块自动插入。车规问题常是"死区太大输出波形削顶、太小炸管"，要按管子开关时间+驱动延时计算。

出处：[PWM 原理](../../../04-MCAL与外设驱动/2-L2进阶/Pwm/01-PWM原理.md)

## 进阶题（7 题——拉开差距）

**Q：TC377 的 GTM 是什么架构？TOM/ATOM 干什么用？**

答：GTM（Generic Timer Module）是英飞凌 TC3xx 的大一统定时器矩阵：时钟分发（CMU）→ 各种通道模块（TOM/ATOM/ARU/ADC 触发/SPE 等）→ 输出映射（OUTSEL/IOCM）到引脚。**TOM** 常规模块够做普通 PWM；**ATOM** 增强版支持硬件死区、故障时的输出强制（安全态）、更精细的并行加载——电机/安全相关 PWM 用 ATOM。MCAL 的 Pwm 模块底层就是映射到 GTM 通道。

出处：[GTM 架构概览](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/01-GTM架构概览.md)、[TOM 与 ATOM](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/02-TOM与ATOM.md)、[与 MCAL Pwm 的关系](../../../02-芯片与体系结构/2-L2进阶/TC377平台/GTM/03-与MCAL-Pwm的关系.md)

**Q：S32K 的 PWM 用什么硬件？eMIOS 和 FTM 有什么区别？**

答：S32K3 用 eMIOS（增强型模块化 IO 子系统，统一计数器总线 UC、支持 OPWFMB/SAIC 等多种模式），S32K1 常用 FTM（FlexTimer，源自电机控制场景）。区别：eMIOS 通道模式更丰富、可跨通道硬件联动；FTM 简单直接、双通道互补输出+硬件死区。MCAL Pwm 配置时映射到对应硬件通道。

出处：[S32K eMIOS FTM](../../../04-MCAL与外设驱动/2-L2进阶/Pwm/02-S32K-eMIOS-FTM.md)、[TC377 GTM](../../../04-MCAL与外设驱动/2-L2进阶/Pwm/03-TC377-GTM.md)

**Q：DMA 是什么？什么场景值得用 DMA？**

答：DMA 控制器代替 CPU 搬数据：配置源/目的地址、块长、触发源（如 SPI RX 满），硬件自动搬运并给中断/回调。判断公式：数据量大 × 逐字节搬运打断 CPU 频繁 → 上 DMA。典型：大块 SPI 采样流（旋变/ADC 数据帧）、CAN 报文批量、Flash 编程数据、日志搬运。收益：CPU 解放 + 传输速率不受任务调度抖动影响。

出处：[DMA 原理](../../../04-MCAL与外设驱动/3-L3高级/DMA专题/01-DMA原理.md)、[总线与 DMA](../../../02-芯片与体系结构/2-L2进阶/体系结构通用/04-总线与DMA.md)

**Q：MCU 时钟树怎么配？外设时钟门控是干什么的？**

答：典型链路：晶振/内部 RC → PLL 倍频到核频（如 200~300MHz）→ 分频器树（CPU/总线/外设各取所需）。S32K 侧叫 SCG/PCC，TC377 侧叫 CCU：先配源、锁相等待稳定、再逐级使能分频。**外设时钟门控**：不用外设就关它的时钟——省电（睡眠电流硬指标）也防"没初始化的外设误触发中断"。排障钩子：外设"寄存器写不进"十有八九时钟没使能。

出处：[CCU 与时钟树](../../../02-芯片与体系结构/2-L2进阶/TC377平台/时钟系统/01-CCU与时钟树.md)、[外设时钟门控](../../../02-芯片与体系结构/2-L2进阶/TC377平台/时钟系统/03-外设时钟门控.md)、[SCG 与 PCC](../../../02-芯片与体系结构/1-L1基础/S32K平台/时钟系统/01-SCG与PCC.md)

**Q：SPI 的四种模式是什么？怎么选？**

答：CPOL（空闲时钟极性 0/1）× CPHA（采样边沿第 1/第 2 个）= 4 种模式。选法：查从设备手册时序图——空闲时 SCK 高电平选 CPOL=1；数据在第一个边沿被从机锁存选 CPHA=0。工程铁律：同一 SPI 总线挂多个不同模式的从机，切片选时要同步切模式；通信"数据错位一格"的排障先查 CPOL/CPHA 与 LSB/MSB First。

出处：[SPI 时序](../../../04-MCAL与外设驱动/2-L2进阶/Spi/01-SPI时序.md)

**Q：CDD 是什么？和 MCAL、SWC 怎么划边界？**

答：CDD = Complex Device Driver，AUTOSAR 官方留的"后门"：管那些 MCAL 覆盖不了或不需要标准化的驱动（专用传感器协议、算法型外设、安全电机控制）。定位三原则：①对外提供标准化风格的接口（供 RTE/SWC 调用）；②内部可以直接摸寄存器；③OS 与中断要按 BSW 集成规范挂接（1/2 类 ISR、排斥区）。边界反例：能用 MCAL 标准模块的（CAN/ADC 普通用法）别塞进 CDD——"后门"开太大架构就烂了。

出处：[CDD 定位与边界](../../../04-MCAL与外设驱动/2-L2进阶/CDD设计方法论/01-CDD定位与边界.md)、[寄存器到 IoHwAb 分层](../../../04-MCAL与外设驱动/1-L1基础/驱动分层思想/01-寄存器到IoHwAb分层.md)

**Q：Fee 怎么用 DFlash 模拟 EEPROM？**

答：EEPROM 有"按字节改写"特性，MCU 片上只有按扇区擦除的 Flash。Fee 的招数：把逻辑块数据顺序追加写到 DFlash 的"工作区"，写满/老化后再整块搬到新扇区（磨损均衡），掉电安全靠"双份+有效标志+CRC"。上层 NvM 只看到"块"，完全无感。追问点：写寿命预算（擦写次数×扇区数 vs 车辆寿命）、写入耗时对下电时序的影响。

出处：[Fee 模拟 EEPROM](../../../04-MCAL与外设驱动/2-L2进阶/Fls与Fee/02-Fee模拟EEPROM.md)、[Fls 驱动](../../../04-MCAL与外设驱动/2-L2进阶/Fls与Fee/01-Fls驱动.md)

## 区分度题（3 题——聊出深度）

**Q：S32K 的 BCTU 是什么？它和 ADC、PWM 怎么组成触发链？**

答：BCTU = Back-to-Back 转换触发单元：硬件级联动"PWM 输出某相位 → 触发指定 ADC 通道组转换 → 转完直接 DMA 搬走"整条链零软件参与。价值：采样点精确对齐电机控制角度（FOC 电流采样必须在特定 PWM 相位），软件触发做不到这个确定性。TC377 对应 EVADC 的硬件触发源路由（GTM→EVADC）。能画出"PWM→BCTU/EVADC→DMA→内存"的图就是满分答案。

出处：[S32K ADC-BCTU](../../../04-MCAL与外设驱动/2-L2进阶/Adc/03-S32K-ADC-BCTU.md)、[TC377 EVADC](../../../04-MCAL与外设驱动/2-L2进阶/Adc/02-TC377-EVADC.md)

**Q：MCAL 的中断怎么和 OS 挂接？说说你的实践。**

答：三件事：①分类——简单高频的挂 1 类中断（不经 OS，最快），需要 ActivateTask/SetEvent 的挂 2 类（OS 封装，能调 API）；②优先级——按 02 区的 SRC/IR 路由表分配，避免与 OS 内核区冲突（通常预留一段给内核）；③封装——ISR 入口里清标志、读数据、SetEvent 丢给任务，ISR 主体 <几 µs。实践叙事：某 SPI CDD 初版在中断里做完整协议解析，2 类 ISR 跑 80µs 拖垮 1ms 任务——改成"中断只搬数、任务解析"后恢复。

出处：[中断挂接规范](../../../04-MCAL与外设驱动/2-L2进阶/CDD设计方法论/02-中断挂接规范.md)、[与 BSW-OS 集成](../../../04-MCAL与外设驱动/2-L2进阶/CDD设计方法论/03-与BSW-OS集成.md)

**Q：PWM 输出不对（占空比/频率异常），怎么排查？**

答：分层定位路径——

- 示波器量引脚：有波形但不对 → 参数/时钟问题；没波形 → 引脚配置或模块使能问题；
- 查时钟：模块输入时钟是否使能（时钟门控）、分频是否按预期（GTM CMU/ eMIOS 全局分频）；
- 查映射：通道到引脚的复用（Port ALT）与 GTM OUTSEL 输出映射是否接上；
- 查参数：周期/占空比寄存器的计数值换算、安全模式下是否被强制输出（ATOM 故障态）；
- 查软件：MCAL Pwm 的通道配置（idle 状态、极性）与 SetDutyCycle 调用是否生效。

按这个顺序讲，展示的是"先物理后寄存器、先时钟后参数"的确定性方法论。

出处：[MCAL 配置要点（Pwm）](../../../04-MCAL与外设驱动/2-L2进阶/Pwm/04-MCAL配置要点.md)、[MCAL 配置与生成流程](../../../04-MCAL与外设驱动/1-L1基础/MCAL总览/03-配置与生成流程.md)
