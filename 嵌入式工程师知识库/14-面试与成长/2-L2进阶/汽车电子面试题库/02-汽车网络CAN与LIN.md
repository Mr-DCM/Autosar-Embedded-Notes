## 基础题（8 题——答错必挂）

**Q：CAN 标准数据帧由哪些字段组成？**

答：SOF（1 位）→ 仲裁段（11 位 ID + 1 位 RTR）→ 控制段（IDE + r0 + 4 位 DLC）→ 数据段（0~8 字节）→ CRC 段（15 位 CRC + 1 位界定符）→ ACK 段（2 位）→ EOF（7 位）。标准帧最长约 108~111 位，考虑位填充后 8 字节数据帧典型占约 130 位。

追问 DLC 与实际长度的关系：经典 CAN 只允许 0~8，填 9 以上非法；CAN-FD 则按 1/2/3/4/5/6/7/8/12/16/20/24/32/48/64 的长度码映射。

出处：[帧格式](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/01-帧格式.md)

**Q：CAN 仲裁机制是什么？为什么 ID 小的优先？**

答：总线物理层"显性 0 覆盖隐性 1"——线与。所有节点同时发帧，逐位比较 ID：节点发隐性 1 却在总线上读到显性 0，说明有更高优先级者在发，立即退出发送（仲裁失败转接收），不破坏对方帧。

所以 ID 数值越小优先级越高，且非破坏性仲裁保证了高优先级帧不受损。加分点：仲裁失败的节点在总线空闲时自动重发；报文 ID 同时决定优先级——把安全相关报文（如制动）配小 ID。

出处：[仲裁与填充](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/03-仲裁与填充.md)

**Q：CAN 位时序分哪几段？采样点一般配在哪，为什么？**

答：一位分为四段：同步段 SYNC_SEG（1 tq）+ 传播段 PROP_SEG + 相位缓冲段 1（PS1）+ 相位缓冲段 2（PS2），采样点位于 PS1 与 PS2 之间。总 tq 数 = 波特率倒数（如 500kbit/s @ 40MHz 时钟 → 80tq 太多，通常 1tq=50ns 级别取 16~20tq）。

车规惯例采样点 75%~87.5%（500k 常配 80%）：留足传播段容纳线缆/收发器延时，剩余相位缓冲用于重同步容差。整条总线所有节点采样点必须一致，否则互通性出问题（Autosar/车厂一致性测试硬指标）。

出处：[位时序与采样点](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/02-位时序与采样点.md)

**Q：错误帧由什么构成？什么时候发？**

答：由 6 个连续同极性位的错误标志 + 8 位错误界定符组成。任何节点检出位错误、填充错误、CRC 错误、格式错误或 ACK 错误时，在下一比特位起发送错误标志。

主动错误状态的节点发主动错误标志（6 位显性），会强占总线让所有节点报错重发；被动错误状态的节点只能发被动错误标志（6 位隐性），基本影响不到别人——这正是错误分级隔离的用意。

出处：[错误帧](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/04-错误帧.md)

**Q：TEC/REC 错误计数器怎么演进？三个错误状态如何切换？**

答：发错误计数器 TEC / 收错误计数器 REC：检出错误 +8（发送方更多），成功收发递减（TEC -1、REC -1 或 -8），总线异常时快速累积。

三态切换：**Error Active**（TEC、REC 都 <128）正常收发；**Error Passive**（任一 ≥128）只能发被动错误标志、发帧后要等 Suspend 8 位；**Bus Off**（TEC ≥256）完全脱离总线，收发俱停。

出处：[错误计数器与状态](../../../05-汽车网络通讯/1-L1基础/CAN/总线错误与恢复/01-错误计数器与状态.md)

**Q：节点进入 Bus Off 后怎么办？**

答：Bus Off 后硬件不再收发，恢复必须由软件（CanSM/CDD）发起：先等 128 组 11 个连续隐性位（总线空闲判定），再重置控制器回 Error Active。

工程策略分快慢恢复：立即恢复 + 计数限次（如 1s 内 3 次），超过阈值则认为硬件故障，置 DTC、进入降级模式，避免"打摆子"式反复冲击总线。AUTOSAR 里由 CanSM 的 BusOff 通知回调驱动状态机。

出处：[busoff 恢复策略](../../../05-汽车网络通讯/1-L1基础/CAN/总线错误与恢复/02-busoff恢复策略.md)

**Q：CAN 和 LIN 的区别？什么场景选 LIN？**

答：| 维度 | CAN | LIN |
|---|---|---|
| 速率 | ≤1Mbit/s（FD 数据段可 2~8M） | ≤19.2kbit/s |
| 拓扑 | 多主、总线型、120Ω×2 终端 | 单主多从、12V 单线 |
| 仲裁 | 硬件仲裁无冲突 | 无仲裁，主节点轮询调度 |
| 成本 | 收发器+双绞线，高 | UART+便宜从机，低 |

选 LIN 的场景：低速、低成本、对实时性不敏感——雨刮、车窗、座椅、空调风门；主干网与动力链一律 CAN(FD)。

出处：[主从与调度表](../../../05-汽车网络通讯/1-L1基础/LIN/协议原理/01-主从与调度表.md)

**Q：CAN 终端电阻为什么是 120Ω？为什么要两端各一个？**

答：双绞线特征阻抗约 120Ω，终端电阻与线缆阻抗匹配才能吸收信号能量、消除反射。两点注意：①整条总线只在**两端**各并一个 120Ω，中间节点不加——并联越多等效电阻越小，显性电平被拉塌；②万用表量 CAN_H/CAN_L 应约 60Ω（两个 120Ω 并联）——60Ω 正常，120Ω 说明断了一端，40Ω 说明多焊了电阻。这是现场排障第一动作。

出处：[终端电阻与拓扑](../../../05-汽车网络通讯/1-L1基础/CAN/收发器与物理层/03-终端电阻与拓扑.md)

## 进阶题（7 题——拉开差距）

**Q：CAN-FD 相比经典 CAN 改了什么？**

答：四个关键点：①仲裁段速率不变（≤1M），数据段切换高速（BRS 位声明，常见 2~5Mbit/s）；②数据段最长 64 字节（经典 8）；③新增 ESI 位标记发送方错误状态；④CRC 扩到 21 位并加填充计数场（stuff count）防错漏。共存要求：网络里混跑经典节点时，经典节点对 FD 帧按错误处理——所以升级 FD 要全网同升，或做隔离网关；收发器也要选支持 FD 的型号（环回延时更小）。

出处：[FD 帧与 BRS](../../../05-汽车网络通讯/1-L1基础/CAN/CAN-FD/01-FD帧与BRS.md)、[与经典 CAN 共存](../../../05-汽车网络通讯/1-L1基础/CAN/CAN-FD/02-与经典CAN共存.md)

**Q：CAN 位填充规则是什么？哪些字段不填充？**

答：发送端连续 5 个同极性位后自动插入 1 个反极性位；接收端删除之。目的：保证沿密度，给 PLL 重同步提供素材，同时拉开帧内位序列防止误识别 SOF/EOF。参与填充的区段：SOF 到 CRC 序列；**CRC 界定符、ACK、EOF 不参与**。经典考点：为什么最大填充开销约 20%（每 4 位插 1），以及填充位本身也参与后续连续计数。

出处：[仲裁与填充](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/03-仲裁与填充.md)

**Q：为什么需要 CanTp？帧类型有哪些？**

答：诊断报文（如刷写、读大数据 DID）远超 8 字节，CanTp（ISO 15765-2）在 CAN 之上做分段重组：**SF** 单帧（≤7 字节）、**FF** 首帧（含总长）、**CF** 连续帧（带序号 SN）、**FC** 流控帧（接收方回：CTS/WAIT/OVFLW + 块大小 BS + 帧间隔 STmin）。

加分点：BS/STmin 是"接收方节流阀门"——发送方每发 BS 个 CF 要停下来等下一个 FC；Cr/Cr 超时（N_As/N_Ar/N_Bs/N_Br/N_Cr）参数决定异常判定。AUTOSAR 里 CanTp 位于 CanIf 之上、Dcm/PduR 之下。

出处：[CanTp 分段 15765-2](../../../05-汽车网络通讯/2-L2进阶/传输层/01-CanTp分段15765-2.md)

**Q：AUTOSAR NM 状态机走一遍？**

答：核心状态：**Bus-Sleep** →（本地网络请求唤醒）→ **Repeat Message State**（以 RepeatMessage 位发若干 NM 报文，宣告自己在线）→ **Normal Operation State**（若仍需联网）→ **Ready Sleep State**（无网络请求时进入，只收不发）→ 全网都 Ready Sleep 且定时器到 → 回 Bus-Sleep。

NM 报文 8 字节：源节点 ID + 控制位（Repeat Message/主动睡眠）+ 用户数据。加分点：任何一节点还想用网就持续发 NM，别人跟着保持醒——"全员同意才睡"；部分唤醒（假醒）问题见区分度 Q20。

出处：[AUTOSAR NM 状态机](../../../05-汽车网络通讯/2-L2进阶/网络管理/02-AUTOSAR-NM状态机.md)、[OSEK NM](../../../05-汽车网络通讯/2-L2进阶/网络管理/01-OSEK-NM.md)

**Q：DBC 文件里能看到什么？拿到新 DBC 第一件事做什么？**

答：DBC 描述：节点（BU）、报文（BO：ID/名称/长度/发送者）、信号（SG_：起始位、长度、字节序 Intel/Motorola、缩放 offset/scale、单位、值表）、报文周期与发送类型（周期/事件）。第一件事：对照通讯矩阵核对周期报文的 ID 与周期，再检查关键信号的字节序——信号值"忽大忽小跳变"十有八九是字节序/起始位解析错了。

出处：[DBC](../../../05-汽车网络通讯/1-L1基础/通讯数据库/01-DBC.md)

**Q：CAN 唤醒流程是什么？假醒是怎么回事？**

答：睡眠时收发器监听总线，检测到唤醒模式（典型：CAN_H 上约 500µs~1.2ms 的显性脉冲序列）后拉醒 INH/WAKE 引脚 → ECU 上电/使能 → 软件初始化 CAN → 发 NM 报文确认全网在线。

假醒：总线上一个毛刺（如电磁干扰、别的节点瞬态）唤醒了不该醒的 ECU，电流白耗。治理：软件确认（如 2s 内没收到有效 NM 报文就重回睡眠）、硬件端 TJA1145 类"过滤唤醒源"收发器、部分网络让无关节点保持睡眠。

出处：[唤醒与休眠](../../../05-汽车网络通讯/1-L1基础/CAN/收发器与物理层/02-唤醒与休眠.md)、[睡眠与假醒](../../../05-汽车网络通讯/2-L2进阶/网络管理/03-睡眠与假醒.md)

**Q：远程帧和过载帧现在还用吗？**

答：远程帧（RTR=1，无数据、请求同 ID 数据帧）理论上是"数据请求机制"，实际工程**基本弃用**——响应延迟不定、优先级倒挂问题；AUTOSAR 甚至不支持其常规使用。过载帧用于接收方来不及处理时 delay 下个帧，现代控制器收发性能充裕，也极少出现。面试答"知道机制 + 工程不用 + 为什么"即为满分。

出处：[帧格式](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/01-帧格式.md)

## 区分度题（5 题——聊出深度）

**Q：总线上偶发错误帧增多，怎么排查？**

答：方法论"先硬后软、先静后动"：

- 一量：万用表量终端电阻（约 60Ω）与 CAN_H/CAN_L 对地/电源阻值——排除短路断路；
- 二看：示波器/CANoe 看波形——显隐性电平幅值、边沿振铃、干扰毛刺；幅值不够查终端电阻/拓扑分支长度；
- 三分：逐节点摘除（或 CANoe 里逐个屏蔽），锁定错误帧来源节点；
- 四问：错误计数器 TEC/REC 谁在涨——发送错误集中在"发送方配置错（采样点/波特率不一致）"，接收错误集中在"物理层干扰"。

真实案例叙事见排障实录，与 09 区 busoff 排查同源。

出处：[总线错误排障实录](../../../05-汽车网络通讯/1-L1基础/CAN/总线错误与恢复/03-排障实录.md)、[busoff 排查](../../../09-调试与测试/3-L3高级/调试方法论/03-busoff排查.md)

**Q：LIN 调度表怎么工作？帧超时怎么处理？**

答：主节点按调度表轮询：表里每项是"帧头槽位+目标从机帧"，主节点发帧头（同步间隔+同步字+PID），从机按 PID 应答数据（或主节点自己发数据给从机）。调度表按场景切换（如"常览表/诊断表/睡眠表"）——切表是 LIN 网络管理的核心动作。

帧超时：主节点发完帧头后在规定时间内没收到完整应答 → 报 LIN 错误；策略是跳过该槽位继续调度，并按错误计数升级（置 DTC/降级功能），不能让一个坏从机拖死整个调度表。

出处：[主从与调度表](../../../05-汽车网络通讯/1-L1基础/LIN/协议原理/01-主从与调度表.md)、[帧超时](../../../05-汽车网络通讯/1-L1基础/LIN/排障/01-帧超时.md)

**Q：LIN checksum 有哪两种？怎么选？**

答：**Classic（V1.x）**：对数据场求和取反，不含 PID；**Enhanced（V2.x）**：数据场 + PID（含保护位）一起算。选择规则：从机按 LDF 版本定——LIN 2.x 节点用 enhanced；老节点混网时可能要 classic。排障口诀：换了从机/换了对端后"数据全对但 checksum 报错"，先查两端口径不一致。

出处：[checksum 类型](../../../05-汽车网络通讯/1-L1基础/LIN/排障/02-checksum类型.md)

**Q：采样点/波特率配错的现场表现是什么？**

答：特征是"低负载正常、高负载偶发错误、特定节点互不通"：波特率偏差 <0.5% 内能容忍，偏差大时重同步追不上，表现为 CRC/位错误累积；采样点不一致时短帧能通、长帧（位多、漂移累积）错误率上升，且往往"节点 A 能收 B、B 收不了 A"的单向怪象。工具定位：CANoe 的位时序一致性检查（一致性测试项），或示波器量单帧位宽换算实际波特率。

出处：[位时序与采样点](../../../05-汽车网络通讯/1-L1基础/CAN/协议原理/02-位时序与采样点.md)

**Q：部分网络（Partial Networking）解决什么问题？**

答：整车睡眠时仍需个别 ECU"半醒"监听特定报文（如智能大灯被遥控唤醒），传统做法只能全网醒或加独立接收芯片。PN 机制：报文带 PN ID 标签，收发器（如 TJA1145/FD 收发器）硬件按标签过滤——只有命中本 ECU 关心的 PN ID 才唤醒 MCU，其余报文一律不理。

价值：整车静态电流大幅下降（百 mA 级→几十 mA 级），是新能源车续航/停车场场景刚需。答到"硬件过滤唤醒+软件确认"两层即满分。

出处：[部分网络](../../../05-汽车网络通讯/2-L2进阶/网络管理/04-部分网络.md)、[收发器选型 TJA1145](../../../05-汽车网络通讯/1-L1基础/CAN/收发器与物理层/01-收发器选型TJA1145.md)
