# 内部 RC 时钟

> 一句话定位：MCU 片内 RC 振荡器（Internal RC Oscillator）零成本、μs 级起振，但 ±1~2% 量级的精度决定了它只配当"启动时钟"与"无关时序场景时钟"——凡是和通讯位时序、精确时基沾边的活都得交给晶振/PLL。
> 等级：L2 ｜ 前置：[晶振原理与负载电容计算](01-晶振原理与负载电容计算.md)

## 原理

### 1. RC 振荡器的工作方式（对比晶体）

片内 RC 振荡器的本质是"电流源给电容充放电 + 比较器/施密特触发器翻转"：

```
        ┌────────────┐        ┌──────────┐
 电流源 │  给 C 充电  │───────▶│ 施密特   │──┬──▶ 时钟输出
 Ichg→  │  放电       │        │ 触发器   │  │
        └────────────┘        └──────────┘  │
              ▲                    │        │
              └────────────────────┴────────┘
                     翻转阈值交替选充/放电流

  频率 f ≈ 1 / (k·R·C)   ← R、C 是片内硅器件，随工艺/温度/电压漂移
```

- 晶体靠石英的机械谐振，Q 值 10⁴~10⁶，ppm 级稳定（见[晶振原理篇](01-晶振原理与负载电容计算.md)）
- RC 靠硅电阻/电容充放电，**没有物理谐振结构**，频率由半导体工艺参数决定——这是精度差的物理根源
- 出厂时工厂用激光/熔丝校准（factory trim）把 25°C 频率修到标称值附近，典型 ±1~2%
- 全温区（−40~125°C）无补偿时可能漂到 ±3~5%；带片上温度补偿的高精度内部 RC 可达 ±0.5%~1%（以具体芯片 DS 为准）

### 2. 内部 RC vs 外部晶振：一张表看懂分工

| 指标 | 内部 RC | 外部晶振 |
|---|---|---|
| 出厂精度（25°C） | ±1~2% 量级 | ±10~30 ppm |
| 全温区漂移 | 可达 ±3~5% | ±15~30 ppm（AT 切） |
| BOM 成本 | 0 | 晶体 + 2 颗电容 |
| PCB 面积 | 0 | 晶体就近布局占板 |
| 起振时间 | μs 级 | ms 级（典型 1~10 ms） |
| 能否当 CAN 主时钟 | 不能（容差烧穿预算） | 能 |
| 典型用途 | 复位默认源、低功耗慢时钟、无关时序外设 | 主时钟、通讯位时序 |

### 3. 为什么不能当 CAN 节点主时钟

CAN 位时序的振荡器容差预算按 ±0.5% 量级设计（推导过程见[晶振原理篇](01-晶振原理与负载电容计算.md)的采样点漂移算例，此处不重复）：

```
内部 RC 误差账（最坏情况）：
  出厂校准      ±1~2%
  温度漂移      再叠加 1~3%（全温区）
  电源电压影响  再叠加 0.5~1% 量级
  ─────────────────────────
  合计可达 ±3~5%  ≫ CAN 预算 ±0.5%
```

结论：**任何"省一颗晶振、拿内部 RC 凑合当 CAN 时钟"的决定都会直接烧穿容差预算**，表现为高低温下偶发位错误/CRC 错误，且常温测试发现不了。

但内部 RC 不是废物，无关时序场景完全可用：

- IO 控制、LED、继电器驱动等慢速输出
- ADC 轮询采集（采样时刻不要求精确等间隔）
- 看门狗计数（超时量级判断，不要求精确）
- 低功耗模式的慢速时钟（WDG/RTC 概量级计时）
- LIN 从机：靠起始位同步主机，临界可行但高风险（温漂叠加易超 ±1.5~2% 要求，见[晶振原理篇](01-晶振原理与负载电容计算.md)第 4 节），量产仍推荐晶振

### 4. 复位后的默认时钟几乎总是内部 RC

几乎所有 MCU 复位释放后**默认从内部 RC 振荡器取指令**（具体复位默认源查各芯片 RM 的时钟章节，如 "clock after reset"）：

- 原因一：晶振起振要 ms 级，复位后 CPU 必须立即执行第一条指令，RC μs 级就绪
- 原因二：外部器件可能虚焊/损坏，默认源必须是片内自带的，保证芯片"总能跑起来"
- 典型启动路径：复位 → 内部 RC（较低频率）→ BootROM/启动代码 → 配置并切换到晶振+PLL → 主频全速运行

## 计算与选型

### 设计步骤：这个外设允不允许用 RC 时钟

```
第 1 步：该外设输出是否进入"位时序敏感"通讯（CAN/CAN-FD/UART 高波特率）？
        是 → 必须晶振/PLL 派生时钟，结束
第 2 步：是否要求精确绝对时基（计时/计量/CAN-FD 数据相位）？
        是 → 晶振，结束
第 3 步：定时精度要求是否优于 ±2%（如某控制环路周期抖动预算）？
        是 → 晶振；否 → RC 可行
第 4 步：RC 可行时，仍要查 DS：全温区+全电压范围的 RC 频率偏差包络，
        确认最坏情况仍满足外设需求（如 UART 低波特率 9600 时 ±2% 尚可容忍）
```

### 时钟切换流程（通用 4 步，寄存器名以 RM 为准）

```
第 1 步：使能目标时钟源（晶振使能位 / PLL 使能位）
第 2 步：轮询"就绪/锁定"标志
        - 晶振：稳定标志（起振稳定，ms 级）
        - PLL：锁定标志 LOCK（锁定前输出禁止使用）
第 3 步：写切换寄存器选择新源
        - 很多平台有写保护 key（防误写），先解锁再写
第 4 步：读回确认当前源；按需关闭旧源（内部 RC 可留作 CSS 备份）
```

伪代码（平台无关）：

```c
/* 时钟切换骨架：先就绪、再切换、后确认 */
MCU_EnableOsc(OSC_EXT);                       /* 1. 使能外部晶振 */
while (!MCU_IsOscStable(OSC_EXT)) { }         /* 2. 等稳定标志，典型带超时保护 */
MCU_SetSysClockSource(SYSCLK_OSC_EXT);        /* 3. 切换系统时钟源 */
while (MCU_GetSysClockSource() != SYSCLK_OSC_EXT) { }  /* 4. 读回确认 */
```

**核心纪律：先等目标源就绪，再切换**——目标源还没稳定就切换，总线时钟会出现毛刺（glitch），外设状态机可能错乱。

### 时钟安全监测（CSS / Clock Monitor）

时钟安全系统（Clock Security System，CSS，各平台名称不同）监测主时钟是否消失/超差，触发后自动回退或中断：

```
主时钟 ──▶ ┌──────────┐ 正常 ──▶ 继续运行
           │ 频率监测器 │
           └──────────┘ 失效 ──▶ ①自动切回内部 RC（保持跑）
                                ②触发 CSS 中断 → 软件：记录 DTC / 进安全状态 / 复位
```

- 双平台机制概念（寄存器细节见对应平台笔记）：
  - TC377：CCU（Clock Control Unit）含振荡器看门狗与失效检测，可配置失效后回退备份时钟，详见 [TC377 时钟系统](../../../02-芯片与体系结构/2-L2进阶/TC377平台/时钟系统/README.md)
  - S32K：SCG（System Clock Generator）带 Clock Monitor 单元，可配置 Loss of Clock 中断/复位，详见 [S32K 时钟系统](../../../02-芯片与体系结构/1-L1基础/S32K平台/时钟系统/README.md)
- 软件必须处理 CSS 中断：至少记录复位/事件原因并上报 DTC，安全相关系统按安全状态机处理

## ECU 实例

- 某车身控制器（TC377）：复位后默认内部 fRC（约 100 MHz 量级，以 RM 为准）跑启动代码，随后切 20 MHz 晶振 → PLL → 内核 200 MHz；CAN 初始化严格放在时钟切换完成之后，首帧零位错误（数字以该项目时钟配置表为准）
- 某低成本车窗控制器：为省 BOM 用内部 RC 做 LIN 从机，夏季整车烘烤试验（85°C）出现从机丢同步帧——温漂叠加超出 LIN 从机容差，量产版回退为晶体方案（以 LIN 规范与项目试验报告为准）
- 某网关 ECU：CSS 触发主时钟失效中断 → 软件记录 DTC（供电/时钟类）→ 主动复位恢复；售后通过该 DTC 定位出晶振虚焊批次

## 与软件的关联

1. **Mcu 驱动初始化顺序**是 AUTOSAR 上电第一阶段：时钟源选择、PLL 配置、分频设置全在 Mcu_Init，跑在 RC 上的代码要尽量短
2. **延时函数陷阱**：复位后跑在低频 RC 上时，用"循环次数"标定的软件延时（如 Flash 等待态、外设复位脉宽）如果按 PLL 频率标定，实际时长会错一个数量级
3. **启动时间预算**：晶振 ms 级起振 + PLL μs~ms 级锁定是上电到首条 CAN 报文的最小延迟组成部分，网络管理快速唤醒需求要把这段算进去
4. **低功耗模式**：睡眠常用内部 RC（或外部 32.768 kHz 表晶）维持低速运行，唤醒后先等主时钟稳定再开通讯（呼应[唤醒电路](../ECU硬件常识/02-唤醒电路.md)）
5. **CSS 中断处理**：中断里禁用依赖主时钟的外设、记录事件、按安全策略回退或复位（与 WdgM/EcuM 策略联动，见 [系统服务栈](../../../07-AUTOSAR架构/2-L2进阶/系统服务栈/README.md)）

## 易错点与陷阱

- 拿内部 RC 当 CAN 主时钟：常温台架测试可能"看起来没问题"，高低温整车路试才爆偶发 CRC 错误
- 时钟切换不等 LOCK 标志就切源：偶发外设初始化失败，难复现
- 切换后不读回确认：切换寄存器写失败（写保护未解）而软件以为切成功了
- 出厂校准值（trim）未加载或被误擦：RC 频率偏离标称 ±10% 以上，低波特率 UART 都会丢帧
- 在 RC 时钟阶段初始化依赖精确波特率的外设（UART/CAN）：外设分频按错误基准计算，波特率偏
- 忽略 CSS：晶振失效时系统时钟静默消失，表现为"整机死机无 DTC"——开了 CSS 才能留下证据

## 面试高频题

**Q1：内部 RC 振荡器为什么精度只有 ±1~2%，而晶振能到 ppm 级？**
A：RC 的频率由片内硅电阻/电容的充放电决定，受工艺偏差、温度、电压影响，无物理谐振结构；晶体靠石英机械谐振，Q 值 10⁴~10⁶，频率由晶格物理常数决定。RC 经出厂 trim 后 25°C 典型 ±1~2%，全温区更差。

**Q2：MCU 复位释放后用什么时钟？为什么？**
A：几乎都是内部 RC（查 RM 确认复位默认源）。因为晶振起振要 ms 级而 CPU 必须立即取指，且默认源必须不依赖任何外部器件（可能损坏），保证芯片总能启动；启动代码中再切换到晶振+PLL。

**Q3：时钟切换的标准流程是什么？最关键的纪律是什么？**
A：①使能目标源 → ②轮询就绪/锁定标志 → ③写切换寄存器（注意写保护 key）→ ④读回确认、按需关旧源。关键纪律是"先等目标源就绪再切换"，否则总线时钟出现毛刺导致外设错乱。

**Q4：什么是时钟安全系统（CSS）？软件要做什么？**
A：监测主时钟消失/超差的硬件机制，失效时自动回退内部 RC 或触发中断。软件要处理 CSS 中断：记录事件/DTC、按安全策略停依赖时钟的外设、复位或进安全状态。TC377 在 CCU、S32K 在 SCG 各有实现。

**Q5：哪些场景可以用内部 RC 时钟？**
A：与位时序、精确时基无关的场景——IO 控制、ADC 轮询、看门狗、低功耗慢时钟、低波特率 UART（需验最坏偏差包络）；CAN/CAN-FD 主时钟、精确计时、LIN 从机（临界）都不建议。
