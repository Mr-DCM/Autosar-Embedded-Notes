# 唤醒电路

> 一句话定位：ECU 睡眠是为了守住整车静态电流预算（mA 级），唤醒电路（本地/网络/诊断三类源）负责"该醒时一秒叫醒，不该睡时绝不误叫"——CAN 报文唤醒收发器→RXD 拉低→MCU 唤醒中断是其中最经典的链路。
> 等级：L2 ｜ 前置：[KL30-KL15供电](01-KL30-KL15供电.md)、[上拉下拉电阻](../../1-L1基础/上拉下拉电阻/01-原理与作用.md)

## 原理

### 1. 为什么必须睡眠：静态电流预算

车辆熄火后蓄电池独自放电，停放数周要能启动：

```
整车静态电流预算（量级示意）：
  60 Ah 蓄电池 × 放电深度 30% ÷ 停放 6 周(1008h) ≈ 20 mA 整车总预算
  └─ 几十个 ECU 分摊 → 单节点常 mA 级、关键常电节点甚至 μA 级
（数值随蓄电池容量/停放要求/主机厂规范差异极大，以项目整车电气规范为准）
```

睡眠的本质：MCU 进低功耗模式（停主时钟/关外设）、关闭功能电源域，只留**常电域**（wake 电路+RTC 级电路）值班——所以 [KL30 供电](01-KL30-KL15供电.md)里只有常电域挂在电池上。

### 2. 唤醒源分类

| 类别 | 唤醒源 | 典型例子 |
|---|---|---|
| 本地唤醒 | KL15/物理开关输入 | 点火、门锁开关、喇叭等硬线信号 |
| 网络唤醒 | CAN/LIN 报文（总线活动） | 任一节点发帧唤醒全网（网络管理报文） |
| 诊断唤醒 | 诊断请求 | UDS 3E/诊断仪接入唤醒 |
| 其他 | RTC 定时、传感器阈值 | 周期任务唤醒、震动唤醒等 |

本地唤醒链路（硬线）：开关电平变化 → MCU 电气唤醒输入脚（EWU 类引脚，睡眠态仍供电）→ 触发唤醒中断/复位。

### 3. CAN 收发器唤醒链路（核心）

支持休眠的 CAN 收发器有**低功耗待机模式**：收发器内部检测器值班监视总线差分，MCU 与主收发路都睡：

```wavedrom

  {name: 'RXD', wave: '1...0.......', node: '....c'},

```

链路分步：

1. 总线上出现显性位（任何报文的起始位）
2. 收发器**待机检测器**识别总线活动，将 RXD 拉低（唤醒标志）
3. RXD 下降沿触发 MCU 唤醒中断（或唤醒 MCU）
4. 软件在中断里：初始化时钟（先等主时钟稳定，见 [RC 时钟](../时钟电路/02-RC时钟.md)）→ 收发器切正常模式 → 开始收发
5. 注意：唤醒后的首帧报文本节点往往收不全（时钟未就绪）——网络管理设计允许丢首帧（见[网络管理](../../../05-汽车网络通讯/2-L2进阶/网络管理/README.md)）

### 4. LIN 唤醒：break 脉冲

LIN 从机在睡眠中监听总线，主机发**唤醒脉冲（wake-up pulse）**：总线被拉显性（低）持续约 250 μs~5 ms（概念区间，**以 LIN 规范版本为准**）：

```
睡眠中从机 ──总线下拉 250μs~5ms──▶ 识别为唤醒请求（区别于普通报文起始位）
                                  → 唤醒、等待主机首帧（最大等待时限以规范为准）
更短的脉冲（如 <50μs 量级）视为总线上毛刺，不唤醒——这就是抗扰与唤醒灵敏度的分界
```

### 5. 假醒（spurious wakeup）与软件对策

总线上毛刺/EMI 干扰/未滤净的瞬态都能触发收发器唤醒检测 → MCU 被叫醒但总线上没有有效报文：

```
假醒处理链：
  唤醒中断 → 读唤醒源寄存器（收发器唤醒标志/本地唤醒脚/RTC 各自是谁）
          → 重初始化时钟并开窗监听总线一段时间
          → 开窗内无有效报文 → 记录事件（可上报 DTC/计数）→ 回睡
          → 有有效网络管理报文 → 走正式唤醒流程（网络管理状态机，见下链）
```

不做假醒对策的后果：毛刺频繁叫醒 → 睡眠电流超标、节点反复上下电；与网络管理状态机（BusSleep/PrepareSleep 等）的配合详见[网络管理](../../../05-汽车网络通讯/2-L2进阶/网络管理/README.md)。

## 计算与选型

### 设计步骤：睡眠电流预算分解

```
第 1 步：拿到单节点睡眠电流目标（如 ≤100 μA，以项目规范为准）
第 2 步：分账：
        MCU 低功耗模式电流（ datasheet 典型 μA~mA 级，随保留外设浮动）
        + CAN 收发器待机电流（典型 μA 级）
        + 常电 LDO 静态电流（iq）
        + 唤醒输入上拉/分压网络漏电流
        + PCB 漏电/防护器件反偏漏（高温下不容忽视）
第 3 步：软件裁剪：睡眠前逐个关闭外设时钟/IO 模拟域（ADC/DAC 断电）
第 4 步：高温复测：漏电流随温度翻倍量级，85°C 数据才算数
```

### 睡眠电流超标排查（逐路断供法）

```
工具：μA 表（或源表 SMU）串入 KL30；可断跳线/0Ω 电阻
流程：
  ① 整板测 → 超标，记录超标量 X
  ② 逐路断供：拔 MCU 电源域跳线 / 断收发器 / 断常电 LDO 输出支路
     每断一路读一次电流，定位"断开后掉 X 的那一路"
  ③ 常见元凶：
     MCU 有外设忘关（ADC 模拟域/看门狗跑高速时钟）
     IO 上拉没断电（IO 接到已断电源域 → 反向灌电流）
     收发器未进待机（EN/STB 脚睡眠时没置对）
     上拉电阻取值太小（12V 经 1kΩ 上拉=12mA 级，直接爆表）
```

## ECU 实例

- 某车身 ECU：睡眠电流目标 ≤150 μA——MCU Standby 模式 8 μA + CAN 收发器待机 12 μA + 常电 LDO 静态 20 μA + 唤醒输入网络 ~5 μA，实测常温 60 μA、85°C 130 μA（以该项目实测报告为准）
- 假醒案例：整车台架 EMC 注扰测试中节点被毛刺唤醒后不回睡——软件加"唤醒开窗 200 ms 无有效报文则回睡+事件计数上报"后通过（计数 DTC 辅助定位注扰频段）
- 排查案例：某节点睡眠电流 8 mA 超标，逐路断供定位到"CAN 收发器 STB 脚睡眠时仍为正常模式使能电平"——进睡前忘了拉 STB，一行代码的修复

## 与软件的关联

1. **进睡前清单**（EcuM SLEEP 阶段）：关外设时钟、拉 STB/EN、IO 置安全态（防反向灌电）、使能唤醒源中断、进低功耗指令——漏一项就是 mA 级超标（见 [EcuM](../../../07-AUTOSAR架构/2-L2进阶/系统服务栈/EcuM/README.md)）
2. **唤醒后首件任务**：读唤醒源寄存器判别谁叫醒的（CAN/本地/RTC）——网络唤醒走 NM 状态机、本地唤醒走应用逻辑、无法判别则按假醒处理
3. **唤醒→首帧时间预算**：时钟起振+锁相+收发器就绪典型 ms~几十 ms 级，网络管理超时参数要容纳（快速唤醒需求压缩到更短，见[时钟树与 PLL](../时钟电路/03-时钟树与PLL.md)使能顺序）
4. **假醒计数与 DTC**：假醒频繁=硬件毛刺/EMI 线索，计数上报是诊断数据（见 [Dem 配置](../../../06-诊断与标定/2-L2进阶/Dem配置/README.md)）
5. **唤醒仲裁**：KL15 与网络唤醒同时有效/先后到达时的行为（立即全醒 vs 等待仲裁）由 EcuM/BswM 策略定义

## 易错点与陷阱

- 睡眠电流只测常温：高温漏电翻倍，产线过热老化才爆
- 收发器 STB/EN 忘切待机：收发器满血值守，白睡
- IO 接到已断电电源域：睡眠时反向灌电流，"神秘 mA"
- 唤醒中断里直接开 CAN：时钟未稳先收发，首帧必错（见[RC 时钟](../时钟电路/02-RC时钟.md)切换纪律）
- 假醒不处理：毛刺叫醒不回睡，静态电流超标+反复上下电
- 上拉电阻随手取 1k/4.7k：12V 硬线唤醒输入的分压网络漏电吃掉大半预算，用 100k 量级再配滤波
- LIN 唤醒脉冲宽度按记忆值设计：250μs~5ms 是概念区间，不同 LIN 版本限值不同，以规范为准

## 面试高频题

**Q1：ECU 为什么要睡眠？静态电流预算多大？**
A：熄火后蓄电池独自放电，停放数周须能启动，整车静态电流 mA 级预算分摊到单节点常为 μA~mA 级（以项目整车规范为准）。睡眠=关功能域只留常电唤醒电路值班。

**Q2：描述 CAN 报文唤醒 ECU 的完整链路。**
A：总线显性位→收发器待机检测器识别→RXD 拉低→MCU 唤醒中断→软件初始化时钟（等稳定）→收发器切正常模式→接管总线收发。唤醒后首帧通常收不全，网络管理允许。

**Q3：什么是假醒？软件怎么应对？**
A：毛刺/EMI 触发收发器唤醒检测，MCU 被叫醒但无有效报文。对策：唤醒中断读唤醒源寄存器判别来源，开窗监听一段时间，无有效报文则记录事件并回睡；频繁假醒计数上报 DTC 辅助定位。

**Q4：LIN 唤醒机制是什么？**
A：主机发唤醒脉冲把总线拉显性约 250 μs~5 ms（以 LIN 规范版本为准），睡眠中的从机识别该脉冲唤醒并等主机首帧；更短脉冲视为毛刺不唤醒——抗扰与灵敏度的分界。

**Q5：睡眠电流超标怎么排查？**
A：μA 表串入 KL30，逐路断供（跳线/0Ω 电阻分断 MCU 域/收发器/常电 LDO 支路），看断哪路电流掉下来。常见元凶：外设忘关、STB 没拉、IO 反向灌电、上拉网络取值太小。高温复测漏电流。
