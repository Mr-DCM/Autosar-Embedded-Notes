# 上拉电阻阻值选择计算

> 一句话定位：把"上拉取多大"从抄答案变成算出来——四步法：灌电流上限 → 上升时间 RC → 功耗预算 → 泄漏压降，每步给带数字的算例。
> 等级：L1 ｜ 前置：[原理与作用](01-原理与作用.md)

## 原理（四条约束的来源）

一只上拉电阻 Rpu 同时受四条约束，最终阻值必须同时满足：

| 步骤 | 约束来源 | 决定 |
|---|---|---|
| ① 灌电流上限 | 驱动器 VOL/IOL 规格（数据手册） | R 的**下限** |
| ② 上升时间 RC | 总线电容 × R 的充电速度 | R 的**上限** |
| ③ 功耗预算 | P = V²/R 与系统功耗/发热 | R 的**下限** |
| ④ 泄漏压降 | 输入泄漏 Ileak × R 的电平误差 | R 的**上限** |

合法区间 = **[max(①,③), min(②,④)]**。取不到交集说明拓扑或驱动能力本身有问题，不是换电阻能解决的。

四约束夹出的可行区间（以 I2C 算例 2 为例，R 轴对数示意）：

```
 R(Ω)   362          970         2.7k      4.7k            1M
        │←── ①GPIO灌流 ──→│←── ③功耗下限 →│
  ──────┼────────────────┼──────────────┼──────────────────────┼────→ R 增大
        │   不可行(伤驱动/功耗大)  │  ✓ 可行区间 ✓  │   不可行(慢/泄漏大) │
                                ↑②RC上限 ↑④泄漏上限
   R < Rmin：灌电流/功耗超标          R > Rmax：上升沿充不满、泄漏压降超裕量
   取交集内的标准值：本例取 2.2k（Cbus=50pF），轻载可放宽到 4.7k
```

## 计算与选型

### 算例 1：GPIO 按键上拉为什么是 10k

条件：3.3V 系统；GPIO 规格 VOL(max) = 0.4V @ IOL = 8mA；输入泄漏 ±1µA；引脚 + 走线电容约 10pF。

- **① 灌电流**：Rmin = (VDD − VOL)/IOL = (3.3 − 0.4)/8mA ≈ **362Ω** → 10k 远超下限 ✓
- **② 速度**：τ = R × C = 10k × 10pF = 100ns，上升沿 t_r ≈ 2.2τ = **220ns**——按键是人手速度（ms 级），毫无压力 ✓
- **③ 功耗**：按下时 P = 3.3²/10k ≈ **1.1mW**，长期按下也无需考虑封装 ✓
- **④ 泄漏**：ΔV = 1µA × 10k = **10mV**，对 3.3V 逻辑裕量忽略不计 ✓

结论：4.7k~100k 区间内都合法，行业习惯 10k。取小（1k）伤功耗与灌电流，取大（1M）泄漏与噪声先出问题。

### 算例 2：I2C 400kHz 上拉为什么取 2.2k~4.7k

条件：3.3V 总线；Fast-mode 400kHz，规范要求上升时间 t_r ≤ 300ns（以 NXP UM10204/I2C-bus 规范为准）；总线电容估算 50pF（每器件约 10pF × 4 个 + 走线）。

- **② 速度定上限**：t_r ≈ 2.2 × Rpu × Cbus →

```
Rmax = 300ns / (2.2 × 50pF) ≈ 2.7kΩ
（若 Cbus = 30pF：Rmax ≈ 4.5kΩ）
```

这就是"2.2k~4.7k"的由来：**上限随你的总线电容在这一段浮动**。

- **① 灌电流定下限**：I2C 器件 IOL 能力按规范 3mA@0.4V →

```
Rmin = (3.3 − 0.4)/3mA ≈ 970Ω
```

- **③ 功耗**：最坏总线长时间为低：P = 3.3²/2.2k ≈ 4.9mW，电阻无压力 ✓
- **④ 泄漏**：每器件 ≤±1µA，挂 4 个共 4µA × 2.2k ≈ 9mV，可忽略 ✓

结论：**970Ω ≤ Rpu ≤ 2.7kΩ（50pF 时）**，取标准值 2.2k；轻负载板（30pF）可放宽到 4.7k 省电。上升时间不满足的后果：高电平还没充到位主机已采样 → 误码/读不到 ACK（波形特征见 [04-I2C为何必须上拉](04-I2C为何必须上拉.md)）。

### 算例 3：ADC 分压网络电阻太大，读数漂移

条件：12V 电池电压检测，用 100k + 10k 分压：

```
Vnode = 12 × 10/(100+10) ≈ 1.09V
源阻抗 = 100k∥10k ≈ 9.1k
```

9.1k 已贴近很多 MCU 对源阻抗的建议上限（≤10k，以数据手册为准）。

**问题机理**：ADC 内部有采样保持电容（S/H，典型 5~10pF）。采样开关闭合瞬间由信号源给它充电，τ = (Rs + Ron) × Cs。软件配置的采样窗口太短时：

- 电容没充满 → 码值**系统性偏低**；
- 前一通道残留电荷影响本通道 → 读数**随采样顺序漂移**；
- 温度改变泄漏 → 读数**温漂**。

**对策**（三选一或组合）：

1. **减小分压电阻**：10k/1k，源阻抗降到 0.9k；代价是分压网络常驻电流 12V/11k ≈ 1.1mA，电池检测场景要权衡睡眠漏电；
2. **节点加电容**：并联 100nF，采样瞬间的电荷由电容供给（同时兼任滤波动能）；代价是建立时间变慢；
3. **延长采样时间**：Adc MCAL 加长采样窗口/降低采样率——纯软件手段，零成本。

### 选型速查表

| 场景 | 典型值 | 主要约束 |
|---|---|---|
| GPIO 按键 | 4.7k~10k | 习惯值，四条约束全宽裕 |
| I2C 100kHz（Standard-mode） | 4.7k~10k | t_r ≤ 1000ns，电容预算宽 |
| I2C 400kHz（Fast-mode） | 2.2k~4.7k | t_r ≤ 300ns 与 Cbus 反推 |
| nRESET 上拉 | 10k（+100nF 到地） | 兼作上电延迟 |
| 低有效输入通道 | 随分压网络设计 | 见 [汽车电路实例](../电压电流与基本定律/03-汽车电路实例.md) |
| ADC 分压下臂 | 源阻抗 ≤10k 或加 100nF | S/H 充电与泄漏 |
| 中断输入 | ≤100k | 泄漏压降限上限 |

## ECU 实例

- I2C 上拉 4.7k/2.2k 是原理图评审的常规检查项：挂载器件数、走线长度变化后要**复核 Cbus**；
- 汽车输入通道的分压+下拉阻值按 16V 最坏情况与功耗预算共同决定（2 倍余量算例见 [欧姆定律与功率](../电压电流与基本定律/01-欧姆定律与功率.md)）；
- 睡眠域的电池检测分压：常驻 mA 级电流不可接受 → 大阻值 + 节点电容 + 拉长采样窗口的组合，或高边开关只在采样瞬间通电。

## 与软件的关联

- **Adc 采样时间参数**就是算例 3 的软件解法：AdcGroup 转换时间、采样窗口（如 S32K LPADC 的采样保持设置，以手册为准）必须和硬件源阻抗匹配；
- **I2c 波特率与上拉**：400kHz 跑不起来先查上拉值与 Cbus，再怀疑软件时序；上拉是外部硬件时，MCAL 没有对应配置项，软件无能为力；
- **Port 内部上拉能力边界**：内部 20~50k 只配当按键上拉，任何总线/精密分压场景必须外部电阻——配置评审看到"内部上拉 + I2C"直接打回；
- **Dio 去抖窗口**下限由硬件 RC 决定、上限由功能需求定，中间是软件的自由度。

## 易错点与陷阱

- **只抄 4.7k 不算电容**：板子挂 8 个 I2C 器件、Cbus 上到 100pF+，2.2k 都可能不够；
- **大阻值分压直连 ADC**：源阻抗超限读数漂移，别先怀疑 ADC 坏了；
- **功耗按 3.3V 算惯了**：5V 上 1k = 25mW，12V 上 1k = 144mW，封装完全不同；
- **泄漏按单器件算**：多器件总线泄漏累加，高阻上拉时误差翻倍；
- **Rmin 用 VDD 而非 (VDD − VOL)**：忽略了低电平残留压降，算出的下限偏小。

## 面试高频题

1. **问：上拉电阻选择的四步法？**
   答：①驱动器灌电流上限定下限；②RC 上升时间定上限；③功耗预算定下限；④输入泄漏压降定上限；在四条交集内取标准值。

2. **问：I2C 400kHz 上拉怎么算？**
   答：Rmax = t_r/(2.2×Cbus)，t_r ≤ 300ns、Cbus 按器件数估算（50pF → 2.7k）；Rmin 由 3mA 灌电流定约 1k；常取 2.2k~4.7k。

3. **问：ADC 分压电阻为什么不能太大？**
   答：源阻抗大时采样保持电容在采样窗内充不满，码值偏低且随通道顺序/温度漂移；对策是减阻值、加节点电容或软件延长采样时间。

4. **问：按键上拉为什么大家都用 10k？**
   答：四条约束下 4.7k~100k 都合法，10k 是功耗、速度、抗噪、成本的中间习惯值；1k 浪费电流，1M 抗泄漏噪声差。
