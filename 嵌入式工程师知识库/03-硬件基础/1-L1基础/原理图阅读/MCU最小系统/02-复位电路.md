# MCU 复位电路：从 RC 到电压监控芯片

> 一句话定位：复位电路决定 MCU "从什么状态开始跑"——看懂 RC 上电复位、外部按钮与电压监控复位芯片三种形态，理解 NRST 低有效与释放时序，软件才能读懂复位源寄存器。
> 等级：L1 ｜ 前置：[电源与去耦](01-电源与去耦.md)

## 原理

### 1. 上电复位 RC 电路

```
VCC ──[R 10kΩ]──┬────→ nRST(MCU)
                 │
              [C 10μF]      上电瞬间 C 视同短路，nRST=低
                 │          随后 C 经 R 充电，电压爬升
                GND          越过 VIH 后复位释放
```

为什么需要：电源本身需要时间稳定（DCDC 软启动、各域建立）、晶振需要时间起振、外部器件（如收发器）也需就绪——复位引脚必须**保持低电平到这一切完成之后**。

### 2. 外部复位按钮 + 放电二极管

```
VCC ──[R 10kΩ]──┬───→ nRST
                 │
                 ├──[C 10μF]── GND
                 │
                 ├──|◀── 串联二极管(阳极接按钮侧)
                 │
              [按钮 RESET]
                 │
                GND
```

按钮按下把 nRST 拉到地；松开后靠 R 重新充电。**放电二极管的作用**：断电/按钮长按时快速把电容放掉，避免"快速重新上电时因电容残留电荷导致复位时间不足、芯片不复位"。没有这只二极管，快速掉电重启就可能失败。

### 3. 电压监控复位芯片（POR/BOR）为什么比 RC 可靠

| 对比项 | RC 复位 | 电压监控复位芯片（如 TPS3823/MCP130 类） |
|---|---|---|
| 触发依据 | 只有"时间"，不管电压 | 精确电压阈值（POR/BOR 阈值±1~2% 量级） |
| 电压缓慢跌落 | **盲区**：电压爬着降，RC 无从触发，MCU 在欠压区乱跑 | 低于阈值立即复位 |
| 复位脉宽 | 随 R/C 温漂变化 | 精确的最小脉宽（如 200ms 档） |
| 看门狗 | 无 | 部分型号集成 WDT 喂狗功能 |

结论：车规 ECU 基本都用电压监控复位芯片（或 MCU 内部 POR/BOR + 外部监控的组合），RC 只作辅助滤波。

### 4. NRST 引脚特性

- 低有效（nRST，reset when Low），引脚名上常带横线或 N 前缀
- 内部通常带上拉（弱上拉，几十 kΩ 量级，以 DS 为准），外部可不再接上拉
- 有的芯片 NRST 是 FT（5V 容忍）引脚，可被调试器拉高到目标电平（以 DS 引脚表为准）
- 允许外接小电容（如 100nF）滤毛刺，但别太大——大电容会拖慢调试器"connect under reset"的时序

### 5. 上电复位时序（WaveDrom）

```wavedrom
{signal: [
  {name: 'VCC', wave: '0.1.......'},
  {name: 'nRST(RC充电)', wave: '0...1....'},
  {name: '晶振', wave: 'x..2...3..', data: ['起振中', '稳定']},
  {name: 'MCU', wave: 'x....3....', data: ['开始取指执行']}
], head: {text: '上电复位时序：nRST 释放必须晚于电源稳定与晶振起振', tick: 0}}
```

读图要点：VCC 在第 1 拍建立，但 nRST 直到第 3 拍（RC 充电越过 VIH）才释放；晶振稳定与电源稳定都完成后，MCU 才取第一条指令。**三者谁先谁后，就是复位时间常数要"够长"的原因。**

## 计算与选型（时间常数算例）

RC 充电公式：`V(t) = VCC × (1 - e^(-t/τ))`，`τ = R × C`。

nRST 达到释放阈值 VIH（设 0.7×VCC）所需时间：

```
t = -τ × ln(1 - 0.7) = 1.2 τ

例：R = 10 kΩ，C = 10 μF → τ = 0.1 s → t ≈ 120 ms
```

120 ms 是否够？逐项核对（量级，以项目实测为准）：

| 事件 | 典型耗时量级 |
|---|---|
| DCDC 输出稳定（软启动） | 1~20 ms |
| MCU 内部 POR/BOR 完成自检 | 不足 1 ms |
| 晶振起振稳定 | 几 ms~几十 ms（见晶振篇） |
| 外部收发器/传感器上电就绪 | 几~几十 ms |
| 低温（-40℃）下以上各项全部变慢 | 2~3 倍余量 |

所以 100ms 级复位时间是常见的工程折中；改小 R/C 前先确认上述各项都有余量，且电压监控芯片在位兜底。

## ECU 实例

- 量产板：电压监控复位芯片（带精确阈值与最小复位脉宽）+ nRST 上的小电容滤毛刺
- 维修/调试板：保留 RESET 按钮与放电二极管，便于现场复位
- 多芯片板（MCU+SoC+SBC）：SBC（System Basis Chip，系统基础芯片）统一产生复位，软件复位树（谁复位谁）要与原理图一致
- nRST 引脚通常同时是调试接口成员：调试器复位线也接在这里（见调试口篇）
- 常见组合：复位芯片开漏输出 + 上拉到 MCU 电源域，实现"监控 5V、复位 3.3V 器件"的电平转换效果

## 与软件的关联

1. **复位源寄存器**：复位后软件第一件事读复位源——S32K1xx 读 RCM_SRS0/SRS1（区分上电/外部/看门狗/软件/LVD 复位），TC3xx 读 RSTSTAT 类寄存器（以 RM 为准），把复位原因记入 NvM/DTC。
2. **冷启动 vs 热复位**：上电复位要全量初始化，软件复位可跳过部分外设重配置——但前提是软件能区分二者（读复位源）。
3. **外部复位按钮的软件消抖**：nRST 低有效，长按 100ms 以上才动作；软件不要试图"屏蔽"外部复位。
4. **Bootloader 与应用互复位**：跳转/回滚时的软复位也走复位源寄存器留痕，便于产线追溯。
5. 启动细节（BMI/BMHD、复位后取指流程）见 [启动流程](../../../../02-芯片与体系结构/2-L2进阶/启动流程/README.md)。

## 易错点与陷阱

- RC 复位的电压缓降盲区：电压缓慢跌落时 RC 不会触发复位，MCU 在欠压区跑飞——必须靠 BOR/电压监控芯片
- 忘装放电二极管：快速掉电再上电，电容残压导致复位时间不足，表现为"立即重启后异常"
- nRST 上的电容选太大：上电正常，但调试器 connect under reset 连不上
- 把 nRST 直接接到别的芯片推挽输出：两个驱动打架，平时看似正常，偶发复位风暴
- 复位芯片阈值选错档位：阈值高于 MCU 实际最低工作电压 → 过早复位；反之 → MCU 已乱跑芯片才复位
- 多复位源直接线与（wired-AND）却漏了其中一路的上拉

## 面试高频题

**Q1：上电复位 RC 电路的时间常数怎么算？为什么要"够长"？**
A：τ=R×C，nRST 充电到 VIH 的时间 t=-τ·ln(1-VIH/VCC)，如 10kΩ×10μF 且 VIH=0.7VCC 时约 120ms。要够长是因为复位必须保持到电源稳定、晶振起振、外部器件就绪之后，否则 MCU 在未就绪状态下开始取指，行为不可预期。

**Q2：电压监控复位芯片为什么比 RC 复位可靠？**
A：RC 只按时间复位，不看电压；电压缓慢跌落（brown-out）时 RC 不触发，MCU 在欠压区乱跑。监控芯片以精确阈值检测电压，低于阈值立即复位，且复位脉宽精确，不受温漂影响。

**Q3：复位按钮旁的二极管是干什么的？**
A：放电二极管。按钮按下或快速掉电时快速泄放复位电容上的电荷；没有它，电容残留电荷会让"立即重新上电"的复位保持时间不足，芯片不复位、启动异常。

**Q4：NRST 引脚有什么特性？**
A：低有效、内部常有弱上拉、多数允许外接小电容滤毛刺；有些芯片该脚 5V 容忍。外部复位源推荐开漏+上拉线与，避免多驱动冲突。

**Q5：什么是 brown-out？RC 复位为什么防不住？**
A：brown-out 指电源电压缓慢跌落到欠压区又缓慢恢复的过程。RC 复位只在上电时按时间常数动作一次，电压缓降时电容跟着掉电、引脚电压始终高于阈值，永远不会触发复位；而 MCU 内部逻辑在欠压区已不可靠，会跑飞。这就是必须有 BOR/电压监控芯片的原因。

**Q6：软件怎么知道上次复位的原因？**
A：读复位源寄存器——S32K1xx 的 RCM_SRS0/SRS1 区分上电/外部/看门狗/软件/LVD 等复位源，TC3xx 读 RSTSTAT 类寄存器；复位后第一时间读取并记录，用于 DTC 与产线追溯。
