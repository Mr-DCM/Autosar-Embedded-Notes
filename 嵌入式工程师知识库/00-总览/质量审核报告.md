## 3. P1 问题清单（明显技术含糊/深度不足，摘录高频项）

- **01**：MISRA 分区引用错（函数宏是 Dir 4.9/Rule 20.x，非 8.x）；TriCore `__isync()` 被当 MMIO 写序屏障（应为 sync/dsync）；模板篇残留"修正：原实现…"编辑痕迹。
- **02**：MPU 篇 `ARM_MPU_RASR` 按 2 参数手拼（CMSIS 实为 8 参数宏）；链接脚本示例 RAM 基址 0x1FFF0000 与 S32K 实际映射（SRAM_L 起 0x1FFF8000）混淆且未标"示意"。
- **03**：KL30 冷启 6V 算例忽略防反接/TVS 压降与 buck 最小关断时间约束，"OK"结论偏乐观；复位释放阈值按 0.7×VCC 假设未提示查 NRST 专用 POR 规格。
- **04**：Port 示例把 Dio 通道 ID 当 Port_PinType 用（两套命名空间）；"同为上拉会分压出中间态"解释不成立（中间态出现在方向相反时）；隐式/显式同步写描述与自家代码示例矛盾；`EcuM_ErrorHook(ECUM_E_CLOCK)` API 存疑。
- **05**：`LIN_HDR_ERROR` 非 Lin SWS 标准枚举值（疑厂商扩展，应标注）。
- **06**：F186 标准语义=ActiveDiagnosticSession，当"供应商码"示例与 14229 Annex F 冲突；"UDS 请求多数超 8 字节"与事实相反（多帧压力在响应与写侧）；S3Server 刷新"仅物理寻址"限定过窄。
- **07**：`EcuM_RequestRUN/POSTRUN` 是 Fixed EcuM 接口，被写成 Flexible 与 BswM 的主流交接手段（API 归属错位）。
- **08**："OSEK 标准资源嵌套即 E_OS_ACCESS"疑把特定实现限制写成规范事实；`vTaskList(&s)` 签名错（应为 char* / uxTaskGetSystemState）；`PROTECTION_STACKOVERFLOW` 系自造标识符（标准为 E_OS_PROTECTION_STACKFAULT）；中断栈与 configMINIMAL_STACK_SIZE 挂钩误导。
- **09**：TriCore ME 缩写与故障类型错配（ME 是 ECC 类，非"非法取指"）；`__asm(syscfg)` 复位指令查无出处；EXC_RETURN 栈选择是位 2 非"位 3"。
- **11**：E2E P05 计数器宽度存疑（常见描述为 8bit，原文 16bit）；TC377 HSM "覆盖 EVITA Full" 与非对称硬件加速口径有张力。
- **12**：TC377 CAN 模块应为 **MCAN**（MultiCAN 是 TC2xx 时代名）；S32K 模板"RTD 提供基础驱动"未区分 K1(SDK)/K3(RTD)；复盘模板零示例。
- **13**：TC377 UM 篇 trap 助记符 FCN/MRA 与 TriCore 公开体系（VAF/VAP/MPP/MPD/FCD/SYS…）对不上；"N_RC" 术语混用（15765-2 无此命名）。
- **14**：S32K 复位寄存器应为 **RCM_SRS**（原文 RC_SRS）；"ISR 不保存 FPU 上下文"对 Cortex-M4F lazy stacking 过绝对。
- **15**：英飞凌 AppNote "AP32xxx" 编号体系存疑；com-assistant 未标维护状态，与自家"看最近 commit"纪律不对齐。

## 4. P2/共性问题（不扣大分，影响一致性）

1. **Q/答格式 4 种变体**：`**Q：**+答：`（08~12 区标准）／`**Q1：**+A：`（01/02/03/06 区）／列表式 `- **Q：**+缩进 A：`（07 区）／题库成对式（14 区）。实质答案全在，仅排版不一。
2. **头部措辞变体**：02 区 GTM×3+iLLD×3 共 6 篇用 `> 一句话：` 而非全库标准 `> 一句话定位：`。
3. **小节名变体**：12/15 区"核心概念/易错点"被题材化改写（如"资源清单/踩坑清单"）。
4. **机器"表格列不齐"9 处**：抽查证实多为 inline code 内 `|`（如 `flags |= bit`）的计数误报，真实排版风险低。
5. **元层账目**：00-总览 README "425 篇域笔记 + 15 篇入门导读"口径不对——按分区表自加为 **407 域笔记 + 18 篇导读（02 区 4 篇）= 425**，即 425 已含导读；知识地图"+4 篇总览文档"实为 5 个文件；学习路线图底部残留维护者视角的"建议抽读验收"过程文字。
6. **口径不一**：04 区"四层"vs 07 区"五层"分层口径；13 区文档"五类 vs 六类"两种说法未互释；15 区"Part 1/2"vs 13 区"Volume 1/2"称谓。
7. **时效性**：07 区版本演进篇止于 R24-11（2026-08 时点 R25-11 应已发布，宜标"截至"日期）。
8. **体量**：01 区 12 篇 >250 行（多为代码示例类，可接受）；全库无 <80 行残篇。
